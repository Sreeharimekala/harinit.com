Reading Errors

Errors aren't failures — they're Python telling you exactly what's wrong. Read the last line first: it names the error type and the reason.

Cell — deliberate errorPython
print("Total sales: " + 500)
TypeError: can only concatenate str (not "int") to str

Translation: you can't join text (str) and a number (int) with +. Fix: print("Total sales:", 500) or f"Total sales: {500}". You'll learn about types in the next lesson.

Python is a high-level, interpreted, dynamically typed language known for readable syntax and a vast data and AI ecosystem (NumPy, Pandas, scikit-learn, PyTorch). Code runs interactively in the REPL, as scripts, or in notebooks. Blocks are defined by indentation after a colon, names are case-sensitive, and comments start with #. Error messages are read from the last line, which gives the exception type and cause.

Variables are labels, not boxes. Two names can label the same mutable object. This explains many "why did my data change?" bugs — especially with lists of records and Pandas DataFrames.

Naming Rules and Conventions

  • Letters, digits and underscores; can't start with a digit; no spaces; not a keyword (class, for…)
  • Use snake_case for variables and functions: total_sales, customer_count
  • UPPER_CASE for constants: TAX_RATE = 0.18; PascalCase for classes
  • Choose meaningful names: monthly_revenue, not x or data2
Variables in Python are names bound to objects; the object, not the name, has a type, determined dynamically. Core types are int, float, complex, bool, str and None, plus collections — list, tuple, range, set and dict. Values are converted explicitly with int(), float(), str() and bool(); floats are approximate, so money needs Decimal or integer units. Immutable objects (numbers, strings, tuples) can't change, while mutable ones (lists, dicts, sets) can, and assigning one name to another shares the same object, so copies must be explicit.

Precedence

From highest to lowest: ** → * / // % → + - → comparisons → not → and → or. When in doubt, add parentheses — they cost nothing and make intent clear: (price - discount) * qty.

Python operators cover arithmetic (including // floor division, % remainder and ** power), comparison (chainable, as in 18 <= age < 60), logical and/or/not, augmented assignment, membership (in) and identity (is). == compares values while is compares object identity and should be used only for singletons such as None. and/or short-circuit and return an operand, enabling default patterns such as value or "Unknown". Floats should be compared with math.isclose, and parentheses clarify precedence.

def validate(order):
    problems = []
    if not order.get("customer_id"):
        problems.append("missing customer_id")
    if order.get("quantity", 0) <= 0:
        problems.append("quantity must be positive")

Loops and Performance

Plain Python loops are fine for thousands of items. For millions of numbers, use vectorised tools — NumPy and Pandas (Lessons 1.20–1.21) process whole columns in compiled code, often 10–100× faster than a loop.

for loops iterate over any iterable — lists, strings, dictionaries, files, range — and enumerate and zip provide positions and parallel iteration without manual indexing. while loops repeat until a condition becomes false and need a guaranteed exit or attempt limit. break leaves a loop, continue skips to the next iteration, and a loop's else runs only when no break occurred, which suits search and retry patterns. For large numeric data, vectorised NumPy and Pandas operations replace Python loops.

    after_discount = price * (1 - discount)
    return round(after_discount * (1 + tax), 2)

print(net_price(1000, tax=0.05))             # keyword: skip discount

  • One job per function, named with a verb: clean_email, load_orders, calculate_margin

Lambda, Recursion & Functional Tools

Where recursion really helps: nested data

def flatten(record, prefix=""):
    """Turn nested JSON into flat column names — e.g. for loading into a table."""
    flat = {}
    for key, value in record.items():
        name = f"{prefix}{key}"
        if isinstance(value, dict):
            flat.update(flatten(value, prefix=name + "_"))   # recurse into the sub-dict
        else:
            flat[name] = value
    return flat

A lambda is an anonymous single-expression function, most useful as a key for sorted, min and max or as an argument to map and filter; named logic should use def. sorted with a key, including tuple keys for multi-level ordering, is the idiomatic way to order records. map transforms, filter selects, any/all test, and reduce folds, though comprehensions and sum are usually clearer. A recursive function solves a problem by calling itself on a smaller part until a base case, which suits tree-shaped data such as nested JSON, but Python's recursion limit makes loops better for simple repetition.

Comprehensions

A comprehension builds a new list, set or dictionary from an existing collection in a single readable line — "give me X for each item, if condition". It's one of the most used Python features in data work, replacing many three- or four-line loops.

From Loop to Comprehension

Loop

clean = []
for name in names:
    if name:
        clean.append(name.strip().title())

Comprehension

clean = [name.strip().title()
         for name in names
         if name]

Read it as: [expression for item in collection if condition].

Use a generator expression when you only need to loop over the results once (sum, max, writing to a file). More in Lesson 1.15.

When Not to Use One

  • More than one condition plus nesting → write a normal loop or a helper function
  • You need side effects (printing, writing) rather than a new collection → normal loop
  • Millions of numbers → NumPy/Pandas vectorised operations
Comprehensions build lists, sets and dictionaries in one expression: [expr for item in iterable if condition]. A trailing if filters items, while expr_a if cond else expr_b before for chooses a value per item; nested for clauses follow the order of nested loops. Generator expressions use parentheses and produce values lazily, saving memory for single-pass use such as sum. Comprehensions should stay simple; complex logic, side effects or large numeric workloads call for loops, helper functions or vectorised libraries.

Rules for Good Error Handling

✗ Swallowing everything

    load_data()

class BankAccount:
    interest_rate = 0.04                    # class attribute: shared by all accounts

    def __init__(self, owner, balance=0):   # runs when an object is created
        self.owner = owner                  # instance attributes: per object
        self.balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("deposit must be positive")
        self.balance += amount
        return self.balance

    def withdraw(self, amount):
        if amount > self.balance:
            raise ValueError(f"insufficient funds: balance {self.balance}")
        self.balance -= amount
        return self.balance

    def __repr__(self):                     # how the object prints
        return f"BankAccount({self.owner!r}, balance={self.balance})"

def timed(func):
    @functools.wraps(func)                 # keep the original name and docstring

A Decorator with Arguments: Retry

CellPython
def retry(times=3, delay=0.01, exceptions=(Exception,)):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    print(f"  attempt {attempt} failed: {e}")
                    if attempt == times:
                        raise                     # out of attempts: let it fail
                    time.sleep(delay * 2 ** (attempt - 1))   # exponential back-off
        return wrapper
    return decorator

calls = {"n": 0}

@retry(times=4, exceptions=(ConnectionError,))
def fetch_rates():
    calls["n"] += 1
    if calls["n"] < 3:
        raise ConnectionError("server busy")
    return {"USD": 0.012}

print(fetch_rates())
attempt 1 failed: server busy attempt 2 failed: server busy {'USD': 0.012}

Production-Ready: Retries, Rate Limits, Pagination

Real APIs time out, throttle you (HTTP 429), and return results a page at a time. Here is a reusable client — tested below against a simulated API so you can see exactly how it behaves:

Cell — reusable API helpersPython
import time

def get_json(session, url, params=None, attempts=5):
    """GET with timeout, retry on 429/5xx with back-off; fail fast on other errors."""
    for attempt in range(1, attempts + 1):
        resp = session.get(url, params=params, timeout=30)
        if resp.status_code == 429 or resp.status_code >= 500:
            wait = float(resp.headers.get("Retry-After", 2 ** attempt))
            print(f"  {resp.status_code} on attempt {attempt}, waiting {wait}s")
            time.sleep(wait)
            continue
        resp.raise_for_status()               # 400/401/404: our mistake -> stop now
        return resp.json()
    raise RuntimeError(f"{url} still failing after {attempts} attempts")

def get_all_pages(session, url, params=None):
    """Follow page numbers until the API says there are no more."""
    page, params = 1, dict(params or {})
    while True:
        body = get_json(session, url, {**params, "page": page})
        yield from body["results"]
        if not body.get("next_page"):
            break
        page = body["next_page"]

    """Read every CSV in the folder as text, remembering the source file."""

def validate(df: pd.DataFrame, products: dict) -> tuple[pd.DataFrame, pd.DataFrame]:
    """Split rows into valid and rejected (with the reason)."""
    reasons = pd.Series("", index=df.index)
    qty = pd.to_numeric(df["qty"], errors="coerce")             # "two" -> NaN
    reasons[qty.isna() | (qty <= 0)] += "invalid qty; "
    reasons[df["customer"].str.strip() == ""] += "missing customer; "
    reasons[~df["product"].isin(products)] += "unknown product; "
    reasons[pd.to_datetime(df["order_date"], errors="coerce").isna()] += "invalid date; "

    bad_mask = reasons != ""
    rejected = df[bad_mask].assign(reason=reasons[bad_mask].str.rstrip("; "))
    valid = df[~bad_mask].assign(qty=qty[~bad_mask].astype(int))
    log.info("Validation: %d valid, %d rejected", len(valid), len(rejected))
    if len(rejected):
        log.warning("Rejected reasons: %s", rejected["reason"].value_counts().to_dict())
    return valid, rejected

def run_pipeline(config: dict) -> dict:
    start = time.perf_counter()
    log.info("=== Sales ETL started ===")

The mini project is a small ETL pipeline: extract reads every CSV in a folder as text with its source file; validate uses vectorised checks to separate valid rows from rejected ones with explicit reasons (invalid quantity, missing customer, unknown product, invalid date); transform removes duplicates, standardises text, parses dates, enriches from a product reference table with a validated merge and computes revenue, margin and USD values; and the load step writes a multi-sheet Excel report, a JSON summary and a chart. A single entry point logs each stage and re-raises failures, configuration is kept separate from code, and unit tests protect the business rules.
