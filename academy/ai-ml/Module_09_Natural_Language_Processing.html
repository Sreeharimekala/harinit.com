9.1

Text Processing & the NLP Pipeline

Text is the messiest data there is: typos, emojis, mixed languages (Hinglish!), HTML, phone numbers, inconsistent case. Natural Language Processing (NLP) is the set of methods that let computers work with human language. Every NLP system starts by turning raw text into clean, consistent units — and the right amount of cleaning depends on the model you'll use.

Cleaning in Practice

Cell — normalise customer messages with regular expressionsPython
import re, html, unicodedata
messages = [
    "<p>Order #A12345 NOT delivered!!! 😡 Call me on +91 98480 12345</p>",
    "Refund   kab milega?? Paid ₹1,299 via UPI on 12/11/2026",
    "Visit https://shop.example.in/help — café latte machine stopped working",
]
def clean(text, lower=True):
    text = html.unescape(text)
    text = re.sub(r"<[^>]+>", " ", text)                                   # strip HTML tags
    text = unicodedata.normalize("NFKC", text)                             # unify unicode forms
    text = re.sub(r"https?://\S+", " <URL> ", text)                         # mask URLs
    text = re.sub(r"(\+91[\s-]?)?[6-9]\d{4}\s?\d{5}", " <PHONE> ", text)    # mask Indian mobile numbers (privacy!)
    text = re.sub(r"#?[A-Z]\d{5}", " <ORDER_ID> ", text)                     # mask order ids
    text = re.sub(r"₹\s?[\d,]+", " <AMOUNT> ", text)
    text = re.sub(r"([!?.])\1+", r"\1", text)                                # "!!!" → "!"
    text = re.sub(r"\s+", " ", text).strip()
    return text.lower() if lower else text
for m in messages:
    print(clean(m))
order <order_id> not delivered! 😡 call me on <phone> refund kab milega? paid <amount> via upi on 12/11/2026 visit <url> — café latte machine stopped working

Masking replaces specific values with placeholders: the model learns "a phone number was here" without memorising personal data — important for privacy (and India's DPDP Act).

9.2

Tokenization

Tokenization splits text into units — tokens — that become the model's vocabulary. Splitting on spaces sounds easy, until you meet "don't", "₹1,299.50", "U.S.", hashtags, or languages without spaces. Modern models use subword tokenizers that break rare words into common pieces, so they never meet an unknown word. Tokens are also how LLM usage is counted and billed.

Word-Level Tokenization

Each tokenizer makes different choices about contractions, currency and punctuation. What matters is applying the same tokenizer at training and prediction time.

The Vocabulary Problem

Word tokens

Huge vocabularies (every inflection, typo, name). Unseen words become [UNK] and their meaning is lost.

Character tokens

Tiny vocabulary, never unknown — but sequences get very long and each token means little.

Subword tokenizers sit in between: frequent words stay whole, rare words split into meaningful pieces ("unbelievably" → "un", "believ", "ably").

Train a Byte-Pair Encoding (BPE) Tokenizer

Cell — learn merges from a small corpus with the Hugging Face tokenizers libraryPython
from tokenizers import Tokenizer, models, trainers, pre_tokenizers
corpus = ["delivery delayed again", "delivered late but packaging good", "refund requested for damaged item",
          "refunded within two days", "replacement delivered quickly", "the delivery partner was polite",
          "requesting refund for late delivery", "item damaged during delivery", "quick refund and replacement",
          "delay in refund processing", "packaging damaged", "polite and quick delivery partner"] * 20
tok = Tokenizer(models.BPE(unk_token="[UNK]"))
tok.pre_tokenizer = pre_tokenizers.Whitespace()
tok.train_from_iterator(corpus, trainers.BpeTrainer(vocab_size=120, special_tokens=["[UNK]", "[PAD]"]))
for s in ["delivered", "redelivery", "refunds", "unpackaged", "delayed"]:
    print(f"{s:<12} → {tok.encode(s).tokens}")
print("vocabulary size:", tok.get_vocab_size())
delivered → ['delivered'] redelivery → ['re', 'delivery'] refunds → ['refund', 's'] unpackaged → ['u', 'n', 'pa', 'ck', 'ag', 'ed'] delayed → ['delayed'] vocabulary size: 120

BPE starts from characters and repeatedly merges the most frequent adjacent pair. Words it never saw ("redelivery", "unpackaged") are still represented — by meaningful pieces when it has learned them ("re" + "delivery"), and by smaller fragments otherwise. Real tokenizers learn 30,000–200,000 pieces from billions of words, so most words split sensibly. GPT models use byte-level BPE; BERT uses the similar WordPiece; many multilingual models use SentencePiece.

Tokenization splits text into tokens that form a model's vocabulary; word tokenizers must handle contractions, punctuation, numbers and currency and suffer from huge vocabularies and unknown words, while character tokenization avoids unknowns but makes long, less meaningful sequences. Subword methods — byte-pair encoding (GPT), WordPiece (BERT) and SentencePiece — keep frequent words whole and split rare ones into learned pieces, so no word is unknown. The same tokenizer must be used in training and inference, and token counts determine LLM context limits and cost, often higher for non-English scripts.
9.3

Stemming & Lemmatization

"Deliver", "delivered", "delivering" and "delivery" are forms of one idea. For classic models that count words, treating them as different features splits the evidence. Stemming chops word endings with fast rules; lemmatization maps each word to its dictionary form using vocabulary and grammar. Both shrink the vocabulary.
Cell — Porter, Snowball and Lancaster stemmers vs a lemmatizerPython
import pandas as pd, spacy

Stemming applies suffix-stripping rules (Porter, Snowball, the aggressive Lancaster) to reduce words to stems that may not be real words and can over-merge unrelated words, while lemmatization uses vocabulary and part of speech to return dictionary forms and handles irregular forms like children → child and was → be. Both reduce vocabulary size and sparsity for count-based models and search; stemming is faster, lemmatization more accurate. Transformer pipelines generally skip them because subword tokenization and context handle morphology.
9.4

Bag of Words & TF-IDF

Models need numbers. The simplest representation, bag of words, counts how often each word appears, ignoring order. TF-IDF improves it by down-weighting words that appear everywhere ("delivery" in a delivery app's reviews) and up-weighting words that distinguish documents. Combined with logistic regression, TF-IDF remains a fast, strong and explainable baseline — and the backbone of keyword search.
\[ \text{tf-idf}(t, d) = \text{tf}(t, d) \times \text{idf}(t), \qquad \text{idf}(t) = \ln\frac{1 + N}{1 + \text{df}(t)} + 1 \]tf = count of term t in document d · df = number of documents containing t · N = number of documents (scikit-learn's smoothed form; rows are then L2-normalised)

Similarity Search

Cell — find the most similar FAQ to a customer question (cosine similarity)Python
from sklearn.metrics.pairwise import cosine_similarity
faqs = ["How do I track my order?", "How can I get a refund for a damaged item?",
        "Can I change my delivery address?", "What payment methods do you accept?",
        "How do I cancel my order before it ships?"]
vec = TfidfVectorizer(stop_words="english", sublinear_tf=True).fit(faqs)
for q in ["how can I track where my order is", "I need a refund, the item was damaged", "parcel arrived broken, want my money back"]:
    sims = cosine_similarity(vec.transform([q]), vec.transform(faqs))[0]
    print(f"{q:<46} → {faqs[sims.argmax()]}  (score {sims.max():.2f})")
how can I track where my order is → How do I track my order? (score 1.00) I need a refund, the item was damaged → How can I get a refund for a damaged item? (score 1.00) parcel arrived broken, want my money back → How do I track my order? (score 0.00)

The first two match because they share key words with an FAQ. The third means the same as the refund FAQ but shares no words with it ("broken" vs "damaged", "money back" vs "refund"), so TF-IDF scores it zero against everything. Meaning without shared words is exactly what embeddings (next lesson) and transformers add.

StrengthsLimits

Bag of words represents a document as word counts ignoring order; TF-IDF multiplies term frequency by inverse document frequency so words common to all documents get low weight and distinctive words high weight, with rows usually L2-normalised. N-grams capture short phrases such as "not good". The result is a sparse, high-dimensional matrix used with linear models or cosine similarity for search and matching; it is fast and explainable but cannot match synonyms or understand context, which embeddings and transformers address. BM25 is the standard TF-IDF-style ranking function for keyword search.
9.5

Word Embeddings: Word2Vec, GloVe & FastText

TF-IDF treats "broken" and "damaged" as unrelated columns. A word embedding represents each word as a dense vector of, say, 100 numbers, learned so that words used in similar contexts get similar vectors. "You shall know a word by the company it keeps": if "broken" and "damaged" both appear near "item", "arrived" and "replace", their vectors end up close. Three classic methods learn these vectors in different ways.

GloVe: Co-occurrence Counts Factorised

Cell — the GloVe idea in miniature: log co-occurrences → low-rank vectorsPython
from collections import Counter
vocab = sorted({w for s in sentences for w in s}); idx = {w: i for i, w in enumerate(vocab)}
C = np.zeros((len(vocab), len(vocab)))
for s in sentences:
    for i, w in enumerate(s):
        for j in range(max(0, i - 4), min(len(s), i + 5)):
            if i != j: C[idx[w], idx[s[j]]] += 1.0 / abs(i - j)          # nearer words count more
U, S_, _ = np.linalg.svd(np.log1p(C))
vectors = U[:, :20] * S_[:20]                                             # 20-dimensional embeddings
vectors /= np.linalg.norm(vectors, axis=1, keepdims=True)
def neighbours(word, k=3):
    sims = vectors @ vectors[idx[word]]
    return [vocab[i] for i in np.argsort(-sims)[1:k + 1]]
for w in ["damaged", "idli", "pune"]:
    print(f"{w:<8} → {neighbours(w)}")
damaged → ['cracked', 'defective', 'broken'] idli → ['pulao', 'paneer', 'biryani'] pune → ['chennai', 'bengaluru', 'kolkata']

Real GloVe fits vectors so that their dot products match log co-occurrence counts with a weighted least-squares loss; factorising the matrix with SVD captures the same idea.

Using Embeddings, and Their Limit

  • Average a document's word vectors for a quick document vector (or weight by TF-IDF)
  • Use pretrained vectors (Google News Word2Vec, GloVe 6B, FastText's 157 languages incl. Hindi, Telugu, Tamil) as features or to initialise a model's embedding layer
  • Limit: one vector per word. "Bank" gets the same vector in "river bank" and "bank loan". Contextual embeddings from transformers (next lessons) give a different vector per usage
  • Embeddings absorb biases in their training text (gender, region) — test before relying on them
Word embeddings represent words as dense vectors learned from context so that similar words are close, unlike sparse one-hot or TF-IDF features. Word2Vec trains a shallow network with CBOW or skip-gram objectives, GloVe factorises global co-occurrence statistics, and FastText learns from character n-grams so it can embed misspelt and unseen words and suits morphologically rich languages. Embeddings support similarity, analogies and averaged document features and can initialise neural models, but they are static (one vector per word regardless of context) and inherit biases, which contextual transformer embeddings address.
9.6

Attention & Transformers

In "The parcel didn't fit in the locker because it was too big", what does "it" refer to? You decide by looking at other words. Attention lets a model do the same: every token builds its representation by looking at all other tokens and weighting the relevant ones. The transformer (2017, "Attention Is All You Need") is built from attention layers alone — no recurrence — so it trains in parallel on huge datasets and captures long-range context. Every modern language model, from BERT to GPT, is a transformer.

Scaled Dot-Product Attention

\[ \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V \]each token emits a query (what am I looking for?), a key (what do I contain?) and a value (what do I pass on?) — learned linear projections of its embedding · √d_k keeps scores in a range where softmax still has useful gradients
Cell — attention from scratch on a tiny sentencePython
import numpy as np, matplotlib.pyplot as plt
rng = np.random.default_rng(6)
tokens = ["the", "parcel", "was", "too", "big", "so", "it", "didn't", "fit"]
d_model, d_k = 16, 8
E = rng.normal(size=(len(tokens), d_model))                    # token embeddings (normally learned)
E[tokens.index("it")] = E[tokens.index("parcel")] * 0.8 + rng.normal(0, 0.3, d_model)   # pretend "it" has learned to resemble "parcel"
Wq, Wk, Wv = (rng.normal(0, 0.4, (d_model, d_k)) for _ in range(3))
Wk = Wq.copy()                                                 # tie Q and K here so similar tokens attend to each other

def attention(Q, K, V, mask=None):
    scores = Q @ K.T / np.sqrt(K.shape[-1])
    if mask is not None: scores = np.where(mask, scores, -1e9)
    w = np.exp(scores - scores.max(axis=-1, keepdims=True)); w /= w.sum(axis=-1, keepdims=True)
    return w @ V, w

out, weights = attention(E @ Wq, E @ Wk, E @ Wv)
print("output shape:", out.shape, "— one context-aware vector per token")
i = tokens.index("it")
print("'it' attends most to:", [(tokens[j], round(float(weights[i, j]), 2)) for j in np.argsort(-weights[i])[:3]])

causal = np.tril(np.ones((len(tokens), len(tokens)), dtype=bool))    # GPT-style: no peeking at future tokens
_, w_causal = attention(E @ Wq, E @ Wk, E @ Wv, mask=causal)
fig, axes = plt.subplots(1, 2, figsize=(10, 3.6))
for ax, w, title in [(axes[0], weights, "bidirectional (BERT-style)"), (axes[1], w_causal, "causal mask (GPT-style)")]:
    ax.imshow(w, cmap="viridis"); ax.set_xticks(range(len(tokens)), tokens, rotation=60, fontsize=7)
    ax.set_yticks(range(len(tokens)), tokens, fontsize=7); ax.set_title(title, fontsize=9)
plt.tight_layout()

Each row shows where one token "looks". With a causal mask a token can only see itself and earlier tokens — that's what lets GPT generate text left to right.

The Transformer Block

1
Token embeddings + positional encodings
Attention ignores order by itself, so position information is added (sinusoids, learned vectors, or rotary embeddings in modern LLMs)
2
Multi-head self-attention
Several attention "heads" in parallel, each free to track a different relation (syntax, coreference, nearby words)
3
Add & layer norm (residual)
x + attention(x), normalised — keeps very deep stacks trainable
4
Feed-forward network
The same small MLP applied to each position (most of the parameters live here)
×N
Repeat the block
BERT-base: 12 blocks; large LLMs: 80+ blocks

Word Order Matters: A Transformer vs Bag of Words

Cell — reviews where meaning depends on order and negationPython
import torch, torch.nn as nn, numpy as np, random
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.linear_model import LogisticRegression
torch.set_num_threads(2); random.seed(6); torch.manual_seed(6)
pos_w, neg_w = ["good", "fresh", "fast", "great"], ["bad", "stale", "slow", "awful"]
items = ["food", "delivery", "packaging", "service"]
def make(n):
    X, y = [], []
    for _ in range(n):
        a, b = random.choice(items), random.choice(items)
        p, q = random.choice(pos_w), random.choice(neg_w)
        if random.random() < 0.5:                      # same words, different order → opposite overall verdict
            X.append(f"{a} was {q} but overall the {b} was {p}"); y.append(1)
        else:
            X.append(f"{a} was {p} but overall the {b} was {q}"); y.append(0)
    return X, np.array(y)
Xtr, ytr = make(3000); Xte, yte = make(600)
bow = CountVectorizer().fit(Xtr)
lr = LogisticRegression(max_iter=1000).fit(bow.transform(Xtr), ytr)
print(f"bag of words + logistic regression: test accuracy {lr.score(bow.transform(Xte), yte):.3f}")

vocab = {w: i + 1 for i, w in enumerate(sorted({w for s in Xtr for w in s.split()}))}
enc = lambda xs: torch.tensor([[vocab[w] for w in s.split()] for s in xs])
class TinyTransformer(nn.Module):
    def __init__(self, V, d=32, L=9):
        super().__init__()
        self.tok, self.pos = nn.Embedding(V, d), nn.Embedding(L, d)
        layer = nn.TransformerEncoderLayer(d, nhead=4, dim_feedforward=64, batch_first=True, dropout=0.0)
        self.encoder = nn.TransformerEncoder(layer, num_layers=2)
        self.head = nn.Linear(d, 2)
    def forward(self, ids):
        h = self.tok(ids) + self.pos(torch.arange(ids.shape[1]))
        return self.head(self.encoder(h).mean(1))
model = TinyTransformer(len(vocab) + 1)
opt = torch.optim.Adam(model.parameters(), 2e-3); Ttr, Tte = enc(Xtr), enc(Xte)
for step in range(400):
    b = torch.randint(0, len(Ttr), (64,))
    opt.zero_grad(); nn.functional.cross_entropy(model(Ttr[b]), torch.tensor(ytr)[b]).backward(); opt.step()
with torch.no_grad(): acc = (model(Tte).argmax(1).numpy() == yte).mean()
print(f"2-layer transformer:                 test accuracy {acc:.3f}")

Both sentences in each pair use exactly the same words, so a bag-of-words model is stuck at chance. The transformer uses positions and attention ("what comes after overall?") to get it right.

Why Transformers Won

RNN / LSTMTransformer
ProcessingSequential, step by stepAll positions in parallel → fast on GPUs
Long-range linksInformation passes through many stepsAny two tokens connect in one attention step
ScalingHard to scaleScales to billions of parameters and trillions of tokens
CostLinear in sequence lengthAttention is quadratic in length (hence context limits and efficient-attention research)
Attention computes, for every token, a weighted average of value vectors from all tokens, with weights given by softmax of query–key dot products scaled by √d_k; self-attention lets each token's representation depend on its context, and a causal mask restricts tokens to earlier positions for generation. A transformer block combines multi-head self-attention, residual connections with layer normalisation and a position-wise feed-forward network, stacked N times, with positional encodings because attention is order-agnostic. Transformers process sequences in parallel, connect distant tokens directly and scale to huge models, at the cost of attention that is quadratic in sequence length.

BERT & GPT

Two families of transformer dominate NLP. BERT uses the encoder with bidirectional attention and is pretrained to fill in masked words — it's built to understand text (classification, search, entity extraction). GPT uses the decoder with causal attention and is pretrained to predict the next word — it's built to generate text, and at scale becomes the LLMs behind ChatGPT and Claude. Both follow the same recipe: pretrain on huge unlabelled text, then adapt to tasks.

A Tiny GPT, Trained From Scratch

GPT's objective is simple enough to train here: a small character-level transformer reads text and learns to predict the next character. With a few hundred training steps on a small corpus of delivery-update messages, it learns to spell words and produce plausible phrases. The same objective, scaled up by roughly ten orders of magnitude in data and compute, produces modern LLMs.

Cell — corpus, model (causal self-attention), trainingPython

torch.set_num_threads(2); torch.manual_seed(7); random.seed(7)
names = ["ravi", "anita", "meera", "arjun", "kavya", "john"]
places = ["hyderabad", "pune", "chennai", "the warehouse", "the hub"]
lines = []
for _ in range(1500):
    lines.append(random.choice([
        f"your order has been shipped from {random.choice(places)}.",
        f"{random.choice(names)} is out for delivery and will reach you today.",
        f"your parcel has been delivered to {random.choice(names)} at the gate.",
        f"delivery delayed due to heavy rain in {random.choice(places)}.",
        f"refund of rs {random.randint(1, 9)}{random.randint(0, 9)}{random.randint(0, 9)} has been processed.",
        f"your order is packed and ready at {random.choice(places)}."]))
text = "\n".join(lines)
chars = sorted(set(text)); stoi = {c: i for i, c in enumerate(chars)}
data = torch.tensor([stoi[c] for c in text])
block, V = 48, len(chars)

class GPT(nn.Module):
    def __init__(self, d=96, heads=4, layers=3):
        super().__init__()
        self.tok, self.pos = nn.Embedding(V, d), nn.Embedding(block, d)
        layer = nn.TransformerEncoderLayer(d, heads, 4 * d, dropout=0.1, batch_first=True, norm_first=True)
        self.blocks = nn.TransformerEncoder(layer, layers, enable_nested_tensor=False)
        self.ln, self.out = nn.LayerNorm(d), nn.Linear(d, V)
    def forward(self, idx):
        T = idx.shape[1]
        mask = nn.Transformer.generate_square_subsequent_mask(T)       # causal: no peeking ahead
        h = self.blocks(self.tok(idx) + self.pos(torch.arange(T)), mask=mask, is_causal=True)
        return self.out(self.ln(h))

model = GPT(); opt = torch.optim.AdamW(model.parameters(), 2e-3)
print(f"{len(text):,} characters, vocabulary {V}, model {sum(p.numel() for p in model.parameters()):,} parameters")
t0 = time.perf_counter()
for step in range(1, 601):
    ix = torch.randint(0, len(data) - block - 1, (32,))
    x = torch.stack([data[i:i + block] for i in ix]); y = torch.stack([data[i + 1:i + block + 1] for i in ix])
    loss = F.cross_entropy(model(x).reshape(-1, V), y.reshape(-1))
    opt.zero_grad(); loss.backward(); opt.step()
    if step in (1, 200, 600): print(f"step {step:>4}  loss {loss.item():.3f}")
print(f"trained in {time.perf_counter() - t0:.0f}s")

Cell — generate text one character at a time (temperature sampling)Python
@torch.no_grad()
def generate(prompt, n=70, temperature=0.8):
    model.eval(); idx = torch.tensor([[stoi[c] for c in prompt]])
    for _ in range(n):
        logits = model(idx[:, -block:])[:, -1] / temperature           # scores for the next character
        nxt = torch.multinomial(F.softmax(logits, -1), 1)               # sample, don't always take the max
        idx = torch.cat([idx, nxt], 1)
        if chars[nxt.item()] == "\n": break
    return "".join(chars[i] for i in idx[0].tolist()).strip()
torch.manual_seed(1)
for p in ["your order", "meera is", "delivery del", "refund of"]:
    print("→", generate(p))
→ your order is packed and ready at pune. → meera is out for delivery and will reach you today. → delivery delayed due to heavy rain in hyderabad. → refund of rs 285 has been processed.

The model has only ever predicted the next character, yet it completes messages coherently, with names and places in the right slots. Temperature controls randomness: low = predictable, high = creative (and more errors).

BERT is an encoder-only transformer with bidirectional attention, pretrained by masked language modelling (about 15% of tokens masked with an 80/10/10 replacement rule), and is best for understanding tasks such as classification, NER, embeddings and extractive QA, using the [CLS] vector for sentence-level tasks. Named Entity Recognition

Named Entity Recognition (NER) finds and labels the "things" in text — people, organisations, places, products, dates, amounts, IDs. It turns unstructured messages into structured fields: from "Ravi ordered a Prestige cooker from Pune on 12 Nov for ₹2,499" you get name, product, city, date and amount. NER feeds search, analytics, compliance (finding personal data) and chatbots (filling slots).

How NER Is Framed: BIO Tags

TokenRaviKumarorderedaPrestigecookerfromPune
TagB-PERSONI-PERSONOOB-PRODUCTI-PRODUCTOB-CITY

B = beginning of an entity, I = inside, O = outside. NER is token classification: predict one tag per token, then join B/I runs into entity spans.

from spacy.training import Example
random.seed(11)
train_people = ["Ravi Kumar", "Anita Rao", "Meera Shah", "Arjun Reddy", "Kavya Nair", "Rahul Verma", "Sneha Iyer", "Vikram Singh"]
test_people = ["Pooja Desai", "Imran Khan", "Lakshmi Menon", "Harpreet Kaur"]           # never seen in training
train_cities, test_cities = ["Pune", "Chennai", "Hyderabad", "Kolkata", "Jaipur", "Lucknow"], ["Indore", "Mysuru", "Nagpur"]
train_products, test_products = ["Prestige cooker", "boAt earbuds", "Lenovo laptop", "Bata shoes", "Philips trimmer"], ["Havells fan", "Samsung phone"]
templates = ["{P} ordered a {D} from {C}", "the {D} for {P} was shipped from {C}", "{P} wants to return the {D}",
             "deliver the {D} to {P} in {C}", "{P} from {C} complained that the {D} was damaged", "is the {D} available in {C}"]

def make(people, cities, products, n):
    out = []
    for _ in range(n):
        t = random.choice(templates); vals = {"P": random.choice(people), "C": random.choice(cities), "D": random.choice(products)}
        text, ents, pos = "", [], 0
        for part in re.split(r"(\{[PCD]\})", t):
            if part in ("{P}", "{C}", "{D}"):
                key = part[1]; val = vals[key]
                ents.append((len(text), len(text) + len(val), {"P": "PERSON", "C": "CITY", "D": "PRODUCT"}[key])); text += val
            else:
                text += part
        out.append((text, {"entities": ents}))
    return out
train_data = make(train_people, train_cities, train_products, 600)
test_data = make(test_people, test_cities, test_products, 150)

nlp = spacy.blank("en"); ner = nlp.add_pipe("ner")
for _, ann in train_data:
    for *_, label in ann["entities"]: ner.add_label(label)
opt = nlp.initialize()
for epoch in range(8):
    random.shuffle(train_data); losses = {}
    for i in range(0, len(train_data), 32):
        nlp.update([Example.from_dict(nlp.make_doc(t), a) for t, a in train_data[i:i + 32]], sgd=opt, drop=0.2, losses=losses)
print("final training loss:", round(losses["ner"], 2))

scores = nlp.evaluate([Example.from_dict(nlp.make_doc(t), a) for t, a in test_data])
print(f"on UNSEEN names, cities and products: precision {scores['ents_p']:.3f}  recall {scores['ents_r']:.3f}  F1 {scores['ents_f']:.3f}")
for label, s in scores["ents_per_type"].items(): print(f"  {label:<8} F1 {s['f']:.3f}")

Evaluation and Uses

  • Score at the entity level: a prediction counts only if both the span and the label are exactly right (precision, recall, F1 per type)
  • Test on unseen entities, as above — otherwise you're measuring memorisation
  • Pretrained options: spaCy pipelines (en_core_web_trf), Hugging Face token-classification models, and multilingual / Indic NER models
  • Uses: PII detection and redaction, invoice and KYC extraction, linking mentions to a catalogue (entity linking), slot filling in chatbots (9.13)
Named entity recognition locates and labels spans such as people, organisations, places, products, dates and amounts, usually framed as token classification with BIO tags. Regular expressions and gazetteer rules (spaCy EntityRuler) work well for structured entities like IDs, amounts and dates, while statistical models — spaCy's NER, CRFs, BiLSTM-CRF or fine-tuned transformers — use context to recognise open-ended entities, including unseen names. Hybrid pipelines combine both. Evaluation uses entity-level precision, recall and F1 per type on held-out data with unseen entities, and NER powers PII redaction, document extraction, entity linking and chatbot slot filling.

Question Answering

Question answering (QA) systems return an answer, not a list of documents. Ask "How many days do I have to return a phone?" and get "7 days" with the source. There are three styles: extractive QA copies the answer span from a passage, generative QA writes an answer in its own words, and open-domain QA first retrieves relevant passages from a large collection. Retrieval + generation is exactly the RAG pattern behind most enterprise assistants (Module 11).

Reader: Extract the Answer

A fine-tuned reader model (below, with internet) predicts the exact start and end of the answer. To keep this runnable offline, a simple reader scores each sentence of the top passage by word overlap with the question, then pulls a rupee amount (for cost questions) or a duration.

Cell — sentence selection + span extraction, with the source citedPython
def answer(q):
    doc_id = retrieve(q, 1)[0][0]
    sents = re.split(r"(?<=\.)\s+", kb[doc_id])
    qwords = set(tokenize(q))
    best = max(sents, key=lambda s: len(qwords & set(tokenize(s))))

    span = re.search(pattern, best)
    return (span.group(0) if span else best), best, doc_id

Evaluating QA

Cell — exact match and token-overlap F1 (the SQuAD metrics)Python
from collections import Counter
def norm(t): return re.sub(r"\b(a|an|the)\b|[^\w\s₹]", " ", t.lower()).split()
def f1(pred, gold):
    common = sum((Counter(norm(pred)) & Counter(norm(gold))).values())
    if common == 0: return 0.0
    p, r = common / len(norm(pred)), common / len(norm(gold)); return 2 * p * r / (p + r)
tests = [("how many days to return a laptop?", "7 days"), ("how long for a card refund?", "5 to 7 business days"),
         ("what is the fee for cash on delivery?", "₹49"), ("how long does delivery take in metro cities?", "2 to 3 days"),
         ("until when can I cancel for free?", "until they are shipped")]
em, f = [], []
for q, gold in tests:
    pred = answer(q)[0]; em.append(norm(pred) == norm(gold)); f.append(f1(pred, gold))
    print(f"{q:<46} pred {pred[:40]!r:<44} EM {int(em[-1])}  F1 {f[-1]:.2f}")
print(f"\nexact match {np.mean(em):.2f} · F1 {np.mean(f):.2f}")

Question answering returns answers rather than documents: extractive QA predicts start and end positions of an answer span in a passage (BERT-family models fine-tuned on SQuAD, with SQuAD 2.0 adding unanswerable questions), generative QA writes answers and risks hallucination when closed-book, and open-domain QA combines a retriever (BM25 or dense embeddings) with a reader or LLM over retrieved passages — the RAG pattern — and cites sources. Systems are evaluated with exact match and token-overlap F1 for answers and recall@k for retrieval.

Fine-Tuning Language Models

A pretrained language model knows language; fine-tuning teaches it your task, style or domain by continuing training on your labelled examples. Full fine-tuning updates every weight — expensive for big models. Parameter-efficient fine-tuning (PEFT), especially LoRA, freezes the original weights and trains tiny add-on matrices instead, cutting trainable parameters by 100× or more with similar results. Before fine-tuning at all, check whether prompting or retrieval would do.

LoRA: Low-Rank Adaptation

\[ W' = W + \Delta W = W + \frac{\alpha}{r} B A, \qquad W \in \mathbb{R}^{d \times k} \text{ frozen},\; B \in \mathbb{R}^{d \times r},\; A \in \mathbb{R}^{r \times k},\; r \ll d, k \]only A and B are trained · B starts at zero so training begins exactly at the pretrained model · rank r is typically 4–64
Cell — LoRA from scratch: wrap a frozen linear layerPython
import torch, torch.nn as nn
torch.set_num_threads(2)
class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r=4, alpha=8):
        super().__init__()
        self.base = base
        for p in self.base.parameters(): p.requires_grad = False          # freeze pretrained weights
        self.A = nn.Parameter(torch.randn(r, base.in_features) * 0.01)
        self.B = nn.Parameter(torch.zeros(base.out_features, r))          # zero → no change at start
        self.scale = alpha / r
    def forward(self, x):
        return self.base(x) + (x @ self.A.T @ self.B.T) * self.scale

layer = nn.Linear(768, 768)                                              # one attention projection in BERT-base
lora = LoRALinear(layer, r=8)
full, train = sum(p.numel() for p in layer.parameters()), sum(p.numel() for p in lora.parameters() if p.requires_grad)
print(f"full fine-tuning: {full:,} trainable · LoRA r=8: {train:,} trainable ({train / full:.1%})")
x = torch.randn(2, 768)
print("output unchanged at initialisation:", torch.allclose(layer(x), lora(x)))
print("7-billion-parameter model, LoRA on attention projections: typically ~0.1–1% of weights trained")

Fine-Tune a Pretrained Model Three Ways

We pretrain a small transformer on a large "general" task (sentiment of 4,000 short reviews), then adapt it to a new task — "would this customer recommend us?" — phrased differently, with only 60 labelled examples that use just 4 of the 12 opinion words. The test set uses all 12. A model trained from scratch can only learn the 4 words it saw; a pretrained model already knows the rest. We compare a frozen encoder + new head, full fine-tuning, and LoRA.

Cell — pretrain, then adapt; compare accuracy and trainable parametersPython
import random, copy, numpy as np
random.seed(14); torch.manual_seed(14)
good, bad = ["great", "quick", "fresh", "helpful", "neat", "fine"], ["late", "broken", "rude", "cold", "missing", "wrong"]
things = ["order", "delivery", "food", "parcel", "agent", "refund", "item", "payment"]
def sentiment_example():
    lab = random.random() < 0.5
    return f"the {random.choice(things)} was {random.choice(good if lab else bad)} and the {random.choice(things)} was {random.choice(good if lab else bad)}", int(lab)
def review_example(adjs_good, adjs_bad):                       # task B: different phrasing, a new question
    lab = random.random() < 0.5
    return f"honestly i felt the {random.choice(things)} was {random.choice(adjs_good if lab else adjs_bad)} so i would recommend", int(lab)
A = [sentiment_example() for _ in range(4000)]
B_train = [review_example(good[:2], bad[:2]) for _ in range(60)]        # only 4 adjectives appear in the small task-B set
B_test = [review_example(good, bad) for _ in range(600)]                # test uses all 12
vocab = {w: i + 1 for i, w in enumerate(sorted({w for t, _ in A + B_train + B_test for w in t.split()}))}
def enc(data, L=14):
    ids = [[vocab[w] for w in t.split()][:L] + [0] * (L - len(t.split())) for t, _ in data]
    return torch.tensor(ids), torch.tensor([y for _, y in data])

class Encoder(nn.Module):
    def __init__(self, V, d=64):
        super().__init__()
        self.emb, self.pos = nn.Embedding(V, d, padding_idx=0), nn.Embedding(14, d)
        self.attn = nn.MultiheadAttention(d, 4, batch_first=True)
        self.ff = nn.Sequential(nn.Linear(d, 128), nn.ReLU(), nn.Linear(128, d))
        self.n1, self.n2 = nn.LayerNorm(d), nn.LayerNorm(d)
    def forward(self, ids):
        h = self.emb(ids) + self.pos(torch.arange(ids.shape[1]))
        h = self.n1(h + self.attn(h, h, h, key_padding_mask=ids == 0)[0])
        h = self.n2(h + self.ff(h))
        return h.masked_fill((ids == 0)[..., None], 0).sum(1) / (ids != 0).sum(1, keepdim=True)

def train(model, X, y, steps, lr):
    opt = torch.optim.AdamW([p for p in model.parameters() if p.requires_grad], lr=lr)
    for _ in range(steps):
        b = torch.randint(0, len(X), (32,))
        opt.zero_grad(); nn.functional.cross_entropy(model(X[b]), y[b]).backward(); opt.step()
def acc(model, X, y):
    model.eval()
    with torch.no_grad(): return (model(X).argmax(1) == y).float().mean().item()

XA, yA = enc(A); XB, yB = enc(B_train); XT, yT = enc(B_test)

train(pretrained, XA, yA, 600, 2e-3)
print(f"pretrained on task A (sentiment): accuracy {acc(pretrained, XA, yA):.3f}\n")

Good Practice

  • Data quality beats quantity: a few hundred to a few thousand clean, consistent, representative examples
  • Hold out a test set and compare against the prompted base model — fine-tuning must beat it
  • Low learning rates (1e-5 – 5e-5 full; 1e-4 – 3e-4 LoRA), few epochs; watch validation loss to avoid overfitting
  • Check for catastrophic forgetting of general abilities and for leaked personal data in training sets
  • LoRA adapters are small files — keep one per task and swap them over a shared base model
Fine-tuning adapts a pretrained language model to a task, style or domain by further training on labelled examples; prompting suits tasks the model already handles, RAG suits changing knowledge, and fine-tuning suits consistent behaviour, narrow high-volume tasks and smaller models. Options range from training only a new head on a frozen model, through full fine-tuning with low learning rates, to parameter-efficient methods: LoRA freezes weights W and learns a low-rank update (α/r)·BA with B initialised to zero, training well under 1% of parameters, and QLoRA does this over a 4-bit base model. Instruction tuning uses chat-formatted pairs (SFT) and preference tuning uses DPO or RLHF; good practice emphasises data quality, held-out comparison with the base model and checks for forgetting.

3 · Hybrid retrieval

Cell — combine both rankings with reciprocal rank fusion (RRF)Python
def search(q, k=3):
    bm = bm25.get_scores(toks(q))
    sem = doc_vecs @ normalize(svd.transform(tfidf.transform([q])))[0]
    rank_bm, rank_sem = np.argsort(np.argsort(-bm)), np.argsort(np.argsort(-sem))
    rrf = 1 / (60 + rank_bm) + 1 / (60 + rank_sem)                         # robust to different score scales
    top = np.argsort(-rrf)[:k]
    return [(chunks.id[i], round(float(bm[i]), 2), round(float(sem[i]), 2)) for i in top]

Cell — choose the best sentence from the top chunks; refuse when evidence is weakPython
def answer(q, min_overlap=2):
    qset = set(toks(q))
    best = (0, None, None)
    for cid, *_ in search(q, k=3):
        for sent in re.split(r"(?<=\.)\s+", chunks.set_index("id").text[cid]):
            score = len(qset & set(toks(sent))) + 0.5 * len(qset & set(toks(cid)))
            if score > best[0]: best = (score, sent, cid)
    score, sent, cid = best
    if score < min_overlap:
        return {"answer": "I couldn't find this in the policies. Please contact hr@company.example.", "source": None, "score": score}
    return {"answer": sent, "source": cid, "score": score}

Production Checklist

  • Keep the index in sync with policy updates; show the policy version and date with each answer
  • Respect access control — only retrieve documents the employee is allowed to see
  • Log questions (with PII masked) and unanswered queries; they show which policies are unclear or missing

Interview Questions

Frequently asked NLP interview questions with concise answers and the lesson to revisit. Say your answer out loud first, then compare.

Text Representation

QuestionStrong answer
Walk through a typical NLP pipeline.Clean/normalise → tokenise → represent (TF-IDF, embeddings or a transformer's own tokenizer) → model → post-process and evaluate. Preprocessing depth depends on the model. (9.1)
Stemming vs lemmatisation?Stemming chops suffixes by rule (fast, may produce non-words); lemmatisation maps to dictionary forms using vocabulary and POS (accurate, slower). Transformers usually need neither. (9.3)
What does TF-IDF capture and miss?Captures word importance within a document relative to the corpus; misses synonyms, word order (beyond n-grams) and context. (9.4)
What is subword tokenisation and why use it?BPE/WordPiece/SentencePiece split rare words into frequent pieces: small vocabulary, no unknown words, handles new words and morphology. (9.2)
Word2Vec vs GloVe vs FastText?Word2Vec: predictive (CBOW/skip-gram). GloVe: factorises global co-occurrence. FastText: character n-grams, so embeds unseen/misspelt words. All static — one vector per word. (9.5)
Static vs contextual embeddings?Static gives "bank" one vector; contextual (BERT etc.) gives a different vector in "river bank" and "bank loan" based on surrounding words. (9.5, 9.7)

Transformers

QuestionStrong answer
Explain self-attention.Each token creates query, key and value vectors; attention weights = softmax(QKᵀ/√d), output = weighted sum of values. Every token can draw on every other token in one step. (9.6)
Why divide by √dk?Dot products grow with dimension; large scores saturate softmax and shrink gradients. Scaling keeps them in a trainable range. (9.6)
Why positional encodings?Attention is permutation-invariant; position information (sinusoidal, learned or rotary) tells the model word order. (9.6)
BERT vs GPT?BERT: encoder, bidirectional, masked-LM pretraining — understanding tasks. GPT: decoder, causal mask, next-token pretraining — generation. (9.7)
Why did transformers replace RNNs?Parallel training, direct long-range connections, better scaling with data and compute. Cost: attention is quadratic in sequence length. (9.6)
What does temperature do in generation?Divides logits before softmax: low = more deterministic, high = more diverse; top-k/top-p sampling further limit choices. (9.7)

Applications

QuestionStrong answer
How would you build a sentiment model for product reviews?Baseline TF-IDF + logistic regression (keep negations, use n-grams), compare with a fine-tuned transformer; evaluate by phenomena (negation, contrast, sarcasm); consider aspect-based sentiment for actionability. (9.9)
Which metric for imbalanced text classification?Macro-F1 (and per-class recall/precision), not accuracy; use stratified CV and class weights. (9.10)
How is NER framed and evaluated?Token classification with BIO tags; entity-level precision/recall/F1 requiring exact span and type match, tested on unseen entities. (9.11)
Extractive vs generative QA?Extractive copies a span (start/end prediction) — faithful but limited; generative writes answers — flexible but can hallucinate unless grounded with retrieval. (9.12)
What is RAG and why use it?Retrieve relevant documents, then generate an answer from them with citations. Keeps knowledge current without retraining and reduces hallucination. (9.15, Module 11)
When fine-tune vs prompt vs RAG?Prompt for tasks the model can already do; RAG for changing knowledge; fine-tune for consistent format/behaviour, narrow high-volume tasks or smaller models. (9.14)
What is LoRA?Freeze the weights, learn a low-rank update BA added to chosen layers; trains <1% of parameters with near full fine-tuning quality; adapters are small and swappable. (9.14)
How do you handle Indian languages and code-mixing?Multilingual or Indic models (MuRIL, IndicBERT, IndicTrans2), transliteration normalisation, character n-grams for spelling variants, and evaluation data in the target languages. (9.2, 9.13)

import numpy as np, math
docs = [["late", "delivery"], ["quick", "delivery"], ["late", "refund"]]
def tfidf(term, doc):
    tf = doc.count(term) / len(doc)
    idf = math.log(len(docs) / sum(term in d for d in docs))
    return round(tf * idf, 3)
print("tf-idf('delivery', doc0) =", tfidf("delivery", docs[0]), "| tf-idf('refund', doc2) =", tfidf("refund", docs[2]))

def attention(Q, K, V):
    s = Q @ K.T / np.sqrt(K.shape[1]); w = np.exp(s - s.max(1, keepdims=True)); w /= w.sum(1, keepdims=True)
    return w @ V, w
Q = K = V = np.eye(3)
out, w = attention(Q, K, V)
print("attention rows sum to 1:", np.allclose(w.sum(1), 1), "| output shape:", out.shape)
