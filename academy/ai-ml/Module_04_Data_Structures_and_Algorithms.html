Complexity & Big-O

How do you compare two solutions without running them on every possible input? Big-O notation describes how running time (or memory) grows as the input size n grows. It ignores constants and machine speed and focuses on what matters at scale: does doubling the data double the time, quadruple it, or barely change it?

Measure It: Duplicate Detection Three Ways

CellPython
import time, random

def has_dup_pairs(xs):          # O(n²): compare every pair
    for i in range(len(xs)):
        for j in range(i + 1, len(xs)):
            if xs[i] == xs[j]:
                return True
    return False

def has_dup_sort(xs):           # O(n log n): sort, then neighbours
    s = sorted(xs)
    return any(s[i] == s[i + 1] for i in range(len(s) - 1))

def has_dup_set(xs):            # O(n): remember what we've seen
    seen = set()
    for x in xs:
        if x in seen:
            return True
        seen.add(x)
    return False

random.seed(0)
for n in (1_000, 2_000, 4_000):
    data = random.sample(range(10 * n), n)       # no duplicates: worst case for all three
    times = []
    for f in (has_dup_pairs, has_dup_sort, has_dup_set):
        t = time.perf_counter(); f(data); times.append((time.perf_counter() - t) * 1000)
    print(f"n = {n:5d}:  pairs {times[0]:8.1f} ms   sort {times[1]:5.2f} ms   set {times[2]:5.2f} ms")
n = 1000: pairs 13.7 ms sort 0.16 ms set 0.06 ms n = 2000: pairs 54.7 ms sort 0.34 ms set 0.13 ms n = 4000: pairs 218.2 ms sort 0.72 ms set 0.23 ms

Doubling n roughly quadruples the pairwise version's time — the signature of \(O(n^2)\) — while the others barely move. At a million rows, the pairwise version would take hours.

Rules for Working Out Big-O

  • Drop constants: \(O(3n + 10) = O(n)\)
  • Keep the dominant term: \(O(n^2 + n) = O(n^2)\)
  • Sequential steps add, nested loops multiply: a loop inside a loop over n is \(O(n^2)\)
  • Halving each step gives \(O(\log n)\)
  • Different inputs get different letters: looping over orders (n) then products (m) is \(O(n + m)\)

Space Complexity and Trade-Offs

The set version above uses \(O(n)\) extra memory to save time. Trading memory for speed (caching, indexes, hash tables) is one of the most common design decisions in data engineering.

Big-O describes how an algorithm's time or memory grows with input size, ignoring constants and lower-order terms: O(1) constant, O(log n) halving, O(n) single pass, O(n log n) efficient sorting, O(n²) nested pairwise loops and O(2ⁿ) subsets. Sequential steps add and nested loops multiply. Space complexity counts extra memory, and many optimisations trade memory for time, such as a hash set reducing duplicate detection from O(n²) to O(n). Python's hidden costs matter: membership in a list is O(n) while sets and dicts are O(1) on average, append is amortised O(1) and pop(0) is O(n).

Arrays & Strings

An array stores items side by side in memory, so any position can be reached instantly by index. Python's list is a dynamic array; strings are arrays of characters. Most interview problems start here, and a few techniques — prefix sums, in-place updates, frequency counts — solve a surprising number of them.

Classic: Maximum Subarray (Kadane's Algorithm)

Find the best run of consecutive days in a profit series. Brute force checks every start and end — \(O(n^2)\). Kadane keeps "best sum ending here" in one pass:

CellPython
def max_subarray(nums):
    best = current = nums[0]
    start = best_start = best_end = 0
    for i in range(1, len(nums)):
        if current < 0:                       # a negative run only hurts: start fresh here
            current, start = nums[i], i
        else:
            current += nums[i]
        if current > best:
            best, best_start, best_end = current, start, i
    return best, (best_start, best_end)

profit = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
print(max_subarray(profit))                   # sum 6, from index 3 to 6: [4, -1, 2, 1]
assert max_subarray([-3, -1, -2]) == (-1, (1, 1))
(6, (3, 6))

In-Place Techniques

Cell — move zeros to the end, keeping order, O(1) extra spacePython
def move_zeros(a):
    write = 0
    for x in a:
        if x != 0:
            a[write] = x
            write += 1
    for i in range(write, len(a)):
        a[i] = 0
    return a

print(move_zeros([0, 3, 0, 5, 7, 0, 2]))

Strings

Strings are immutable arrays of characters. Counting characters and comparing counts solves anagram, palindrome and "first unique" problems:

CellPython
from collections import Counter

def is_anagram(a, b):
    return Counter(a.replace(" ", "").lower()) == Counter(b.replace(" ", "").lower())

def is_palindrome(s):
    cleaned = [c.lower() for c in s if c.isalnum()]
    return cleaned == cleaned[::-1]

def first_unique(s):
    counts = Counter(s)
    return next((i for i, c in enumerate(s) if counts[c] == 1), -1)

print(is_anagram("Listen", "Silent"), is_anagram("Data", "Date"))
print(is_palindrome("A man, a plan, a canal: Panama"))
print(first_unique("swiss"))                 # 'w' at index 1

Hash Tables

A hash table finds a value by its key in constant time on average. Python's dict and set are hash tables, and they are the single most useful structure for turning slow solutions into fast ones: counting, grouping, de-duplicating, caching, and joining datasets.

  • Two keys landing in the same bucket is a collision; Python resolves it by probing for another slot
  • When the table gets ~2/3 full it resizes — so inserts are amortised \(O(1)\)
  • Keys must be hashable (immutable): str, int, tuple — not list or dict
  • Worst case is \(O(n)\) if many keys collide, but that's rare in practice

Pattern 1: Two Sum — Have I Seen the Complement?

CellPython
def two_sum(nums, target):
    seen = {}                                  # value -> index
    for i, x in enumerate(nums):
        if target - x in seen:
            return seen[target - x], i
        seen[x] = i
    return None

prices = [2499, 799, 1350, 1200, 650]
print(two_sum(prices, 2000))                   # two items that exactly use a ₹2,000 voucher
assert two_sum([3, 3], 6) == (0, 1) and two_sum([1, 2], 10) is None

Pattern 2: Group By a Key

Cell — group anagramsPython
from collections import defaultdict

def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups["".join(sorted(w))].append(w)      # sorted letters = the group key
    return list(groups.values())

print(group_anagrams(["listen", "silent", "enlist", "google", "gogole", "cat", "act"]))

Pattern 3: Prefix Sums + Hash Map

Cell — count subarrays that sum to kPython
def subarray_sum_count(nums, k):
    count, running = 0, 0
    seen = {0: 1}                                  # prefix sum -> how many times seen
    for x in nums:
        running += x
        count += seen.get(running - k, 0)          # earlier prefix that leaves exactly k
        seen[running] = seen.get(running, 0) + 1
    return count

Linked Lists

A linked list stores items as nodes, each pointing to the next. You lose instant indexing, but gain constant-time insertion and removal anywhere you already have a pointer. Python rarely needs them directly, but they appear in interviews constantly and underpin queues, LRU caches and many other structures — and they're the best practice for thinking about pointers.

Build One

CellPython
class Node:
    def __init__(self, val, next=None):
        self.val, self.next = val, next

def from_list(values):
    head = None
    for v in reversed(values):
        head = Node(v, head)                  # O(1) insert at the front
    return head

def to_list(head):
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out

head = from_list([10, 20, 30, 40])
print(to_list(head))

The Classic Problems

Cell — reverse, middle, cycle, mergePython
def reverse(head):
    prev = None
    while head:
        head.next, prev, head = prev, head, head.next     # re-point one arrow at a time
    return prev

def middle(head):                                         # slow/fast pointers
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
    return slow.val

def has_cycle(head):                                      # Floyd's tortoise and hare
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            return True
    return False

def merge_sorted(a, b):
    dummy = tail = Node(0)                                # dummy head avoids special cases
    while a and b:
        if a.val <= b.val:
            tail.next, a = a, a.next
        else:
            tail.next, b = b, b.next
        tail = tail.next
    tail.next = a or b
    return dummy.next

print("reversed:", to_list(reverse(from_list([1, 2, 3, 4, 5]))))
print("middle:", middle(from_list([1, 2, 3, 4, 5])))
loop = from_list([1, 2, 3]); loop.next.next.next = loop.next          # 3 -> 2 makes a cycle
print("cycle:", has_cycle(loop), has_cycle(from_list([1, 2, 3])))
print("merged:", to_list(merge_sorted(from_list([1, 4, 9]), from_list([2, 3, 10]))))

Two techniques solve most linked-list problems: slow and fast pointers (middle, cycle detection, k-th from end) and a dummy head node (merging, deleting, inserting without edge cases for the first node). Draw the arrows on paper before coding.

Where Linked Structures Live in Practice

  • collections.deque — a doubly linked list of blocks: \(O(1)\) at both ends
  • LRU caches — hash map + doubly linked list (OrderedDict)
  • Blockchain, undo histories, file systems' free-block lists
A linked list is a chain of nodes each holding a value and a pointer to the next node (doubly linked lists also point back). It offers O(1) insertion and deletion at the head or after a known node, but O(n) access by position and extra memory per node. Key techniques are iterative pointer reversal, slow and fast pointers for finding the middle and detecting cycles (Floyd's algorithm), and a dummy head to simplify merges and deletions. In Python, deque and OrderedDict use linked structures internally, as do LRU caches.

Stacks & Queues

A stack is last-in-first-out (LIFO) — like a pile of plates. A queue is first-in-first-out (FIFO) — like a ticket line. Stacks power undo, parsing, function calls and depth-first search; queues power task scheduling, message brokers and breadth-first search.

Stack: Balanced Brackets

CellPython
def balanced(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack

for expr in ["f(a[0], {b: (1, 2)})", "(]", "((x)", "SELECT (a + (b * c))"]:

Stack: Evaluate an Expression (Reverse Polish Notation)

CellPython
import operator
def eval_rpn(tokens):
    ops = {"+": operator.add, "-": operator.sub, "*": operator.mul, "/": operator.truediv}
    stack = []
    for t in tokens:
        if t in ops:
            b, a = stack.pop(), stack.pop()
            stack.append(ops[t](a, b))
        else:
            stack.append(float(t))
    return stack.pop()

print(eval_rpn("3 4 + 2 *".split()))          # (3 + 4) * 2

Monotonic Stack: Next Greater Element

"For each day, how many days until a warmer one?" Brute force is \(O(n^2)\). A stack of indices kept in decreasing temperature order answers it in \(O(n)\):

CellPython
def days_until_warmer(temps):
    answer = [0] * len(temps)
    stack = []                                 # indices with no warmer day found yet
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            j = stack.pop()
            answer[j] = i - j
        stack.append(i)
    return answer

print(days_until_warmer([73, 74, 75, 71, 69, 72, 76, 73]))
[1, 1, 4, 2, 1, 1, 0, 0]

Sliding-Window Maximum with a Deque

Cell — max of every 3-day window in O(n)Python
def window_max(nums, k):
    dq, out = deque(), []                      # indices; their values decrease front to back
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:
            dq.pop()                           # smaller values can never be a future max
        dq.append(i)
        if dq[0] <= i - k:
            dq.popleft()                       # front slid out of the window
        if i >= k - 1:
            out.append(nums[dq[0]])
    return out

print(window_max([1, 3, -1, -3, 5, 3, 6, 7], 3))
[3, 3, 5, 5, 6, 7]
A stack is LIFO, implemented with a Python list's append and pop, and is used for undo, parsing and matching brackets, expression evaluation, call stacks and depth-first search; a monotonic stack solves next-greater-element problems in O(n). A queue is FIFO, implemented with collections.deque's append and popleft (list.pop(0) is O(n)), and is used for scheduling, buffering, message queues and breadth-first search. A monotonic deque computes sliding-window maxima in linear time.

Recursion & Backtracking

Module 1 introduced recursion. Here we use it as an algorithm design tool: define the answer for a big input in terms of smaller inputs. Backtracking extends recursion to search — build a candidate step by step, and undo the last step ("backtrack") as soon as it can't lead to a valid answer. It solves permutations, subsets, puzzles and constraint problems.

Thinking Recursively

  1. Base case: the smallest input you can answer directly.
  2. Recursive case: assume the function already works on smaller inputs; combine their answers.
  3. Progress: every call must move towards the base case.
Cell — power in O(log n) by halvingPython
def power(x, n):
    if n == 0:
        return 1
    half = power(x, n // 2)              # solve a problem half the size, once
    return half * half * (x if n % 2 else 1)

print(power(2, 10), power(3, 13), 3 ** 13)
1024 1594323 1594323
Recursion that solves overlapping subproblems repeatedly can explode: naive Fibonacci calls itself about \(2^n\) times. The fix — remembering answers — is dynamic programming (Lesson 4.16). Python's default recursion limit is about 1,000 frames.

Subsets and Permutations

CellPython
def subsets(items):
    out = []
    def go(i, path):
        if i == len(items):
            out.append(path[:])
            return
        go(i + 1, path)                    # exclude items[i]
        path.append(items[i])
        go(i + 1, path)                    # include items[i]
        path.pop()
    go(0, [])
    return out

def permutations(items):
    out, used = [], [False] * len(items)
    def go(path):
        if len(path) == len(items):
            out.append(path[:]); return
        for i, x in enumerate(items):
            if not used[i]:
                used[i] = True; path.append(x)
                go(path)
                path.pop(); used[i] = False
    go([])
    return out

Pruning: Combination Sum

"Which combinations of these pack sizes make exactly 10 units?" Stop exploring as soon as the total overshoots:

CellPython
def combination_sum(sizes, target):
    sizes = sorted(sizes)
    out = []
    def go(start, remaining, path):
        if remaining == 0:
            out.append(path[:]); return
        for i in range(start, len(sizes)):
            if sizes[i] > remaining:
                break                              # prune: sorted, so the rest are bigger too
            path.append(sizes[i])
            go(i, remaining - sizes[i], path)      # i (not i+1): a size can repeat
            path.pop()
    go(0, target, [])
    return out

print(combination_sum([2, 3, 5], 10))
[[2, 2, 2, 2, 2], [2, 2, 3, 3], [2, 3, 5], [5, 5]]

N-Queens: Constraints at Every Step

CellPython
def n_queens(n):
    solutions, cols, diag1, diag2 = [], set(), set(), set()
    placement = []
    def go(row):
        if row == n:
            solutions.append(placement[:]); return
        for c in range(n):
            if c in cols or row - c in diag1 or row + c in diag2:
                continue                           # attacked: skip this square
            cols.add(c); diag1.add(row - c); diag2.add(row + c); placement.append(c)
            go(row + 1)
            cols.remove(c); diag1.remove(row - c); diag2.remove(row + c); placement.pop()
    go(0)
    return solutions

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])     # divide + conquer
    merged, i, j = [], 0, 0                                     # combine: O(n)
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
    return merged + left[i:] + right[j:]

def quick_sort(a):
    import random
    if len(a) <= 1:
        return a
    pivot = random.choice(a)
    return (quick_sort([x for x in a if x < pivot]) + [x for x in a if x == pivot]
            + quick_sort([x for x in a if x > pivot]))

        return a, 0

Two Pointers & Sliding Window

Two simple techniques turn many \(O(n^2)\) "check every pair / every range" problems into single \(O(n)\) passes. Two pointers move through a sequence from both ends (or at different speeds). A sliding window keeps a range that grows on the right and shrinks on the left, updating a running total instead of recomputing it.

Two Pointers on Sorted Data

Cell — pair with a target sum, and three-sumPython
def pair_sum_sorted(a, target):
    i, j = 0, len(a) - 1
    while i < j:
        s = a[i] + a[j]
        if s == target: return a[i], a[j]
        if s < target: i += 1             # need bigger: move left pointer right
        else: j -= 1                      # need smaller: move right pointer left
    return None

def three_sum_zero(nums):
    nums, out = sorted(nums), []
    for k in range(len(nums) - 2):
        if k and nums[k] == nums[k - 1]:
            continue                      # skip duplicate anchors
        i, j = k + 1, len(nums) - 1
        while i < j:
            s = nums[k] + nums[i] + nums[j]
            if s == 0:
                out.append((nums[k], nums[i], nums[j]))
                i += 1
                while i < j and nums[i] == nums[i - 1]: i += 1
            elif s < 0: i += 1
            else: j -= 1
    return out

def longest_unique(s):
    last, start, best = {}, 0, (0, 0)
    for end, ch in enumerate(s):
        if ch in last and last[ch] >= start:
            start = last[ch] + 1              # shrink: jump past the previous copy
        last[ch] = end
        if end - start + 1 > best[1] - best[0]:
            best = (start, end + 1)
    return s[best[0]:best[1]]

def min_window_sum(nums, target):
    left, total, best = 0, 0, float("inf")
    for right, x in enumerate(nums):
        total += x                            # grow
        while total >= target:
            best = min(best, right - left + 1)
            total -= nums[left]; left += 1    # shrink while still valid
    return 0 if best == float("inf") else best

    return levels

class RunningMedian:
    def __init__(self):
        self.low, self.high = [], []            # max-heap (negated) of lower half, min-heap of upper half
    def add(self, x):
        heapq.heappush(self.low, -x)
        heapq.heappush(self.high, -heapq.heappop(self.low))      # keep every low ≤ every high
        if len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))  # rebalance sizes
    def median(self):
        if len(self.low) > len(self.high):
            return -self.low[0]
        return (-self.low[0] + self.high[0]) / 2

        for ch in prefix:
            node = node.children.get(ch)
            if node is None:
                return None
        return node

    def contains(self, word):
        node = self._find(word)
        return bool(node and node.count)

    def suggest(self, prefix, k=3):
        node, found = self._find(prefix), []
        def walk(n, path):
            if n.count:
                found.append((n.count, prefix + path))
            for ch, child in n.children.items():
                walk(child, path + ch)
        if node:
            walk(node, "")
        return [w for _, w in sorted(found, key=lambda t: (-t[0], t[1]))[:k]]

def find_words(board, words):
    trie = Trie()
    for w in words:
        trie.insert(w)
    rows, cols, found = len(board), len(board[0]), set()
    def dfs(r, c, node, path):
        ch = board[r][c]
        node = node.children.get(ch)
        if node is None:
            return                                   # prune: no word continues this way
        path += ch
        if node.count:
            found.add(path)
        board[r][c] = "#"                            # mark visited
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] != "#":
                dfs(nr, nc, node, path)
        board[r][c] = ch                             # backtrack
    for r in range(rows):
        for c in range(cols):
            dfs(r, c, trie, "")
    return sorted(found)

def bfs_path(start, goal):

    while q:
        node = q.popleft()
        if node == goal:
            path = []
            while node is not None:
                path.append(node); node = parent[node]
            return path[::-1]

                parent[nxt] = node
                q.append(nxt)
    return None

DFS: Explore Deeply — Connected Components

def components(graph):
    seen, groups = set(), []
    for start in graph:
        if start in seen:
            continue
        stack, group = [start], []
        seen.add(start)
        while stack:                                  # iterative DFS with a stack
            node = stack.pop()
            group.append(node)
            for nxt in graph[node]:
                if nxt not in seen:
                    seen.add(nxt); stack.append(nxt)
        groups.append(sorted(group))
    return groups

def has_cycle(dag):
    WHITE, GREY, BLACK = 0, 1, 2                      # unvisited, on current path, finished
    color = {n: WHITE for n in dag}
    def visit(n):
        color[n] = GREY
        for m in dag.get(n, []):
            if color.get(m, WHITE) == GREY:           # back edge to the current path
                return True
            if color.get(m, WHITE) == WHITE and visit(m):
                return True
        color[n] = BLACK
        return False
    return any(color[n] == WHITE and visit(n) for n in dag)

Shortest Paths, Topological Sort & Union-Find

Three graph algorithms cover most practical problems: Dijkstra finds the cheapest route when edges have costs; topological sort orders tasks so every dependency runs first (how Airflow, dbt and Spark schedule work); and union-find tracks which items are connected as links are added — the engine behind Kruskal's minimum spanning tree and entity resolution.

Dijkstra's Algorithm

Like BFS, but always expand the closest unfinished node next — a priority queue (4.11) makes that efficient. Works with non-negative weights; \(O((V + E)\log V)\).

Cell — delivery distances (km)Python
import heapq
roads = {
    "Warehouse": {"A": 4, "B": 1},
    "A": {"Warehouse": 4, "B": 2, "C": 5},
    "B": {"Warehouse": 1, "A": 2, "C": 8, "D": 10},
    "C": {"A": 5, "B": 8, "D": 2},
    "D": {"B": 10, "C": 2},
}

def dijkstra(graph, source):
    dist, prev = {source: 0}, {}
    pq = [(0, source)]
    while pq:
        d, node = heapq.heappop(pq)
        if d > dist[node]:
            continue                                   # stale entry: already found shorter
        for nxt, w in graph[node].items():
            nd = d + w
            if nd < dist.get(nxt, float("inf")):
                dist[nxt], prev[nxt] = nd, node
                heapq.heappush(pq, (nd, nxt))
    return dist, prev

def route(prev, target):
    path = [target]
    while path[-1] in prev:
        path.append(prev[path[-1]])
    return path[::-1]

dist, prev = dijkstra(roads, "Warehouse")
for place in ("A", "C", "D"):
    print(f"{place}: {dist[place]} km via {' → '.join(route(prev, place))}")

The direct road Warehouse → A (4 km) loses to Warehouse → B → A (3 km): Dijkstra never commits to a route until it's provably the shortest. For negative edge weights use Bellman-Ford; for map-like graphs with a good distance estimate, A* is faster.

Topological Sort: Dependency Order

Cell — Kahn's algorithm on a data pipelinePython
from collections import deque
depends_on = {                                    # task: tasks it needs first
    "load_orders": [], "load_customers": [], "load_fx": [],
    "clean_orders": ["load_orders"],
    "dim_customer": ["load_customers"],
    "fact_sales": ["clean_orders", "dim_customer", "load_fx"],
    "dashboard": ["fact_sales"],
}

def topo_order(deps):
    indegree = {t: len(d) for t, d in deps.items()}
    children = {t: [] for t in deps}
    for t, d in deps.items():
        for parent in d:
            children[parent].append(t)
    ready = deque(sorted(t for t, n in indegree.items() if n == 0))
    order = []
    while ready:
        t = ready.popleft()
        order.append(t)
        for child in children[t]:
            indegree[child] -= 1
            if indegree[child] == 0:
                ready.append(child)
    if len(order) != len(deps):
        raise ValueError("cycle detected — no valid order")
    return order

print(" → ".join(topo_order(depends_on)))

Union-Find (Disjoint Set Union)

Cell — merge duplicate customer records sharing an email or phonePython
class UnionFind:
    def __init__(self, items):
        self.parent = {x: x for x in items}
        self.size = {x: 1 for x in items}
    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]     # path compression (halving)
            x = self.parent[x]
        return x
    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra                                  # union by size
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

    for k in keys:
        if k in first_seen:
            uf.union(rid, first_seen[k])
        else:
            first_seen[k] = rid
clusters = {}

Greedy Algorithms

A greedy algorithm makes the choice that looks best right now and never reconsiders. When the problem has the right structure, that's both simple and optimal (Dijkstra and Kruskal are greedy). When it doesn't, greedy gives a fast approximate answer — and knowing which case you're in is the skill.

When Greedy Works: Interval Scheduling

Book as many meetings as possible in one room. The greedy rule that works: always pick the meeting that ends earliest.

def max_meetings(ms):
    chosen, free_at = [], 0
    for name, start, end in sorted(ms, key=lambda m: m[2]):    # earliest end first
        if start >= free_at:
            chosen.append(name)
            free_at = end
    return chosen

['standup', '1:1', 'review', 'planning']

Why it's safe: finishing earliest leaves the most room for everything else — any optimal schedule can be swapped to start with that meeting without getting worse (the "exchange argument").

import heapq, itertools
from collections import Counter

def huffman(text):
    tie = itertools.count()
    heap = [(f, next(tie), {ch: ""}) for ch, f in Counter(text).items()]
    heapq.heapify(heap)
    while len(heap) > 1:                               # greedily merge the two rarest
        f1, _, a = heapq.heappop(heap)
        f2, _, b = heapq.heappop(heap)
        merged = {ch: "0" + code for ch, code in a.items()} | {ch: "1" + code for ch, code in b.items()}
        heapq.heappush(heap, (f1 + f2, next(tie), merged))
    return heap[0][2]

Dynamic Programming

Dynamic programming (DP) solves problems that break into overlapping subproblems: solve each small subproblem once, store the answer, and build the big answer from stored ones. It turns exponential recursion into polynomial time, and it's behind edit distance (spell checking, record matching), sequence alignment, the Viterbi algorithm and reinforcement learning.

From Exponential to Linear: Fibonacci

CellPython
import time
from functools import lru_cache

calls = 0
def fib_naive(n):
    global calls; calls += 1
    return n if n < 2 else fib_naive(n - 1) + fib_naive(n - 2)

@lru_cache(maxsize=None)                      # top-down DP: memoisation
def fib_memo(n):
    return n if n < 2 else fib_memo(n - 1) + fib_memo(n - 2)

def fib_table(n):                             # bottom-up DP: tabulation, O(1) memory
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

The DP Recipe

  1. Define the state: what does dp[i] (or dp[i][j]) mean, in words?
  2. Write the recurrence: how does a state follow from smaller states?
  3. Base cases: the smallest states you know directly.
  4. Order: fill states so each one's dependencies are already computed (or memoise).
  5. Answer: which state holds the final result?

def knapsack(items, cap):
    dp = [0] * (cap + 1)                          # dp[b] = best value with budget b
    choice = [[False] * (cap + 1) for _ in items]
    for i, (_, cost, value) in enumerate(items):
        for b in range(cap, cost - 1, -1):        # go downwards so each item is used once
            if dp[b - cost] + value > dp[b]:
                dp[b] = dp[b - cost] + value
                choice[i][b] = True
    picked, b = [], cap                           # walk back to recover the choice
    for i in range(len(items) - 1, -1, -1):
        if choice[i][b]:
            picked.append(items[i][0]); b -= items[i][1]
    return dp[cap], picked[::-1]

def edit_distance(a, b):
    dp = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(len(a) + 1): dp[i][0] = i
    for j in range(len(b) + 1): dp[0][j] = j
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]
            else:
                dp[i][j] = 1 + min(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1])
    return dp[-1][-1]

Recognising DP

  • "Minimum / maximum / number of ways" to reach a goal
  • Choices at each step affect later options (take or skip, which coin, which edit)
  • A recursive solution that recomputes the same arguments
  • Common shapes: 1-D (stairs, coins), 2-D over two sequences (edit distance, LCS), knapsack over items × capacity, grids
Dynamic programming solves problems with overlapping subproblems and optimal substructure by storing each subproblem's answer — top-down with memoisation (lru_cache) or bottom-up with tabulation — turning exponential recursion such as naive Fibonacci into linear time. The recipe is to define the state, write the recurrence, set base cases, choose a fill order and identify the answer. Classic examples are coin change, 0/1 knapsack (iterating capacity downwards and backtracking to recover choices), edit distance for fuzzy matching, longest increasing subsequence and grid path sums; DP also underlies sequence alignment, Viterbi decoding and reinforcement learning.

How a Segment Tree Is Built

Each node stores the answer for a range; its two children split that range in half. The root covers everything; leaves are single elements. Any range is covered by at most about \(2\log_2 n\) nodes.

Cell — range sum and range max with updatesPython
class SegmentTree:
    def __init__(self, data, combine=lambda a, b: a + b, identity=0):
        self.n, self.f, self.id = len(data), combine, identity
        self.tree = [identity] * (2 * self.n)
        self.tree[self.n:] = data                       # leaves
        for i in range(self.n - 1, 0, -1):              # parents
            self.tree[i] = self.f(self.tree[2 * i], self.tree[2 * i + 1])

    def update(self, i, value):                         # O(log n)
        i += self.n
        self.tree[i] = value
        while i > 1:
            i //= 2
            self.tree[i] = self.f(self.tree[2 * i], self.tree[2 * i + 1])

    def query(self, lo, hi):                            # inclusive lo..hi, O(log n)
        res_l = res_r = self.id
        lo += self.n; hi += self.n + 1
        while lo < hi:
            if lo & 1: res_l = self.f(res_l, self.tree[lo]); lo += 1
            if hi & 1: hi -= 1; res_r = self.f(self.tree[hi], res_r)
            lo //= 2; hi //= 2
        return self.f(res_l, res_r)

Fenwick Tree (Binary Indexed Tree)

CellPython
class Fenwick:
    def __init__(self, n):
        self.t = [0] * (n + 1)
    def add(self, i, delta):            # 0-based index
        i += 1
        while i < len(self.t):
            self.t[i] += delta
            i += i & -i                 # jump to the next responsible node
    def prefix(self, i):                # sum of 0..i
        i += 1; s = 0
        while i:
            s += self.t[i]
            i -= i & -i
        return s
    def range(self, a, b):
        return self.prefix(b) - (self.prefix(a - 1) if a else 0)

fw = Fenwick(8)
for i, v in enumerate([40, 12, 7, 33, 25, 0, 18, 9]):
    fw.add(i, v)
print(fw.range(2, 5))
fw.add(3, -30)
print(fw.range(2, 5))
65 35

Where these appear: competitive programming, real-time leaderboards and order books, counting inversions, time-series databases and rolling analytics over mutable data.

Segment trees store aggregates (sum, min, max or any associative function) over halving ranges in a binary tree — compactly in an array of size 2n — so both point updates and range queries take O(log n), versus O(1)/O(n) for plain arrays and O(n)/O(1) for prefix sums. Fenwick (binary indexed) trees offer the same complexity for prefix sums with less code using lowest-set-bit jumps. They suit frequently updated data that needs range answers, such as live inventory, leaderboards and rolling metrics, and should be validated against brute force with randomised tests.

3 · Shortest distances (Dijkstra)

CellPython
def dijkstra(src):
    dist, pq = {src: 0}, [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in graph[u].items():
            if d + w < dist.get(v, float("inf")):
                dist[v] = d + w
                heapq.heappush(pq, (d + w, v))
    return dist

5 · Best visiting order: exact DP vs greedy

Visiting n stops in the best order is the Travelling Salesman Problem. Trying every order is \(O(n!)\). The Held-Karp DP is \(O(n^2 2^n)\) — exact for up to ~20 stops. A greedy "nearest next stop" heuristic is fast but not always optimal:

CellPython
stops = ["Warehouse", "Charminar", "Erragadda", "Falaknuma", "Dilsukhnagar", "Ameerpet"]
D = {a: dijkstra(a) for a in stops}                     # shortest road distance between every pair

def held_karp(stops):
    n = len(stops)
    dp = {(1, 0): (0, None)}                            # (visited mask, last stop) -> (cost, previous)
    for mask in range(1, 1 << n):
        if not mask & 1:
            continue                                    # every route starts at the warehouse (index 0)
        for last in range(n):
            if (mask, last) not in dp:
                continue
            cost = dp[(mask, last)][0]
            for nxt in range(n):
                if mask & (1 << nxt):
                    continue
                key = (mask | (1 << nxt), nxt)
                new = cost + D[stops[last]][stops[nxt]]
                if new < dp.get(key, (float("inf"),))[0]:
                    dp[key] = (new, last)
    full = (1 << n) - 1
    best_cost, last = min((dp[(full, j)][0] + D[stops[j]]["Warehouse"], j) for j in range(1, n))
    order, mask = [], full
    while last is not None:                             # walk back through the stored choices
        order.append(stops[last])
        mask, last = mask ^ (1 << last), dp[(mask, last)][1]
    return best_cost, order[::-1] + ["Warehouse"]

def nearest_neighbour(stops):
    route, left, total = ["Warehouse"], set(stops[1:]), 0
    while left:
        nxt = min(left, key=lambda s: D[route[-1]][s])
        total += D[route[-1]][nxt]; route.append(nxt); left.remove(nxt)
    total += D[route[-1]]["Warehouse"]
    return total, route + ["Warehouse"]

class Trie:
    def __init__(self): self.kids, self.word = {}, None
    def add(self, w):
        n = self
        for ch in w.lower(): n = n.kids.setdefault(ch, Trie())
        n.word = w
    def complete(self, prefix):
        n = self
        for ch in prefix.lower():
            n = n.kids.get(ch)
            if not n: return []
        out, stack = [], [n]
        while stack:
            n = stack.pop()
            if n.word: out.append(n.word)
            stack.extend(n.kids.values())
        return sorted(out)
