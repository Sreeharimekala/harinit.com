n8n Architecture

How n8n works internally, how workflows are executed, how data moves between nodes, how credentials are managed, and how n8n is deployed in an enterprise environment.

2.1

Understanding n8n Architecture

n8n architecture describes how different components of n8n work together to create, execute, manage and monitor automated workflows.

1.1 What is n8n Architecture?

When you create a workflow in n8n, several components work behind the scenes:

  1. User interface.
  2. Workflow management.
  3. Workflow execution engine.
  4. Nodes.
  5. Trigger mechanisms.
  6. Database.
  7. Credential management.
  8. External applications and APIs.

What happens internally?

  1. The schedule trigger starts the workflow.
  2. The execution engine initializes execution.
  3. The HTTP Request node calls an external API.

  6. The Email node sends the result.
  7. Execution information is recorded.
Key takeaway: n8n architecture consists of multiple components working together to execute workflows and integrate external systems.
2.2

How n8n Works Internally

Let's understand what happens internally when you execute a workflow.

2.1 Workflow Definition

When you create a workflow, n8n maintains information about:

  • Workflow ID
  • Workflow name
  • Nodes
  • Node configurations
  • Connections
  • Credentials references
  • Workflow settings

A simplified workflow definition looks like this:

{
  "name": "Employee Notification",
  "nodes": [
    { "name": "Schedule Trigger", "type": "scheduleTrigger" },
    { "name": "Send Email", "type": "emailSend" }
  ],
  "connections": {
    "Schedule Trigger": {
      "main": [
        [ { "node": "Send Email" } ]
      ]
    }
  }
}
This is an illustrative representation, not a complete exportable n8n workflow. The workflow definition tells n8n what operations to perform and how the nodes are connected.

2.2 Internal Execution Process

Consider this workflow:

Manual Trigger
→
HTTP Request
→
Code Node
→
Database Insert
1
Workflow initialization
n8n identifies the workflow that needs to execute.
2
Trigger evaluation
The configured trigger determines when execution should begin.
3
Execution context creation
n8n creates an execution context to manage the current workflow run.
4
Node execution
The execution engine executes nodes according to workflow connections and execution rules.
5
Data processing
Each node receives input data, performs an operation and produces output data.
6
Execution completion
The workflow finishes successfully or encounters an error.
7
Execution recording
Depending on execution settings, execution information is saved for monitoring and troubleshooting.

2.3 Important Internal Concepts

ConceptMeaning
WorkflowCollection of connected nodes
ExecutionOne complete workflow run
NodeIndividual processing component
Input dataData received by a node
Output dataData generated by a node
Execution contextInformation associated with a workflow run
Workflow stateInformation about the workflow configuration and status
Remember: a workflow is the definition of what should happen. An execution is one actual run of that workflow. One workflow can have thousands of executions.

3.5 Manual vs Automatic Execution

🖱️ Manual execution

  • You execute the workflow manually from the editor
  • Development
  • Testing
  • Debugging
  • Validating node configurations

⚡ Automatic execution

  • The workflow executes based on configured triggers
  • Production automation
  • Scheduled reporting
  • Event-driven processing
  • Real-time notifications
The execution lifecycle runs from creating and saving a workflow, through activating (publishing) it, a trigger event, execution start, node-by-node processing, to a finish that is either success or failure, after which execution data is recorded according to settings. Manual executions are for development and debugging; automatic executions run from triggers in production.
2.4

Nodes and Connections

A node is an individual component that performs a specific operation within an n8n workflow. Think of nodes as individual functions in a programming application.

4.1 What is a Node?

Examples: Schedule Trigger, HTTP Request, IF, Code, MySQL, Microsoft Outlook, Gmail.

4.2 Types of Nodes

CategoryPurposeExamples
1. Trigger nodesStart workflow executionSchedule Trigger, Webhook, Email Trigger, Manual Trigger
2. Action nodesPerform specific operationsSend Email, Insert Database Record, Create File, Send Teams Message
3. Logic nodesControl workflow executionIF, Switch, Merge, Loop Over Items
4. Data transformation nodesModify incoming informationEdit Fields, Code, Aggregate, Sort
5. AI nodesPerform AI-related operationsAI Agent, OpenAI Chat Model, Embeddings, Vector Store integrations

4.3 What are Connections?

Connections define the execution path between nodes.

          Trigger
             │
        HTTP Request
             │
          IF Node
          ┌──┴──┐
        True   False
          │      │
          ▼      ▼
        Email  Database

Here, the IF node has two possible output paths. If the condition is true, the workflow follows the True output. Otherwise, it follows the False output.

4.4 How Connections Work

A connection defines:

  1. Source node.
  2. Destination node.
  3. Output type.
  4. Input type.

In n8n, connections can represent different output channels, such as normal main outputs or AI-specific connections (for example, a chat model or memory plugged into an AI Agent).

Important: A connection does not necessarily mean that data is immediately transferred. It defines how execution proceeds and how node output is made available to the next node.
2.5

Triggers and Actions

A trigger is a component that starts workflow execution when a particular event occurs — the starting point of an automated process. An action is an operation performed after the workflow starts.

5.1 Types of Triggers

TriggerDescriptionExample
Manual TriggerStarts manuallyTesting a workflow
Schedule TriggerStarts at scheduled timeDaily report
WebhookStarts when an HTTP request arrivesApplication event
Email TriggerStarts when an email arrivesCustomer complaint
Application TriggerStarts based on application eventsNew CRM record

5.2 What is an Action?

  • Send an email.
  • Insert database records.
  • Update a SharePoint document.
  • Create a ticket.
  • Call an API.
  • Generate a report.

5.3 Trigger vs Action

FeatureTriggerAction
PurposeStarts executionPerforms an operation
PositionUsually starts workflowUsually follows trigger
ResponsibilityDetects an eventProcesses or changes information
ExampleNew email receivedSend notification
ExecutionInitiates workflowExecutes within workflow

Requirement: Whenever a new customer registers, automatically send a welcome email.

  • Webhook is the trigger.
  • Validation and database insertion are processing actions.
  • Email sending is another action.
2.6

Workflow Execution Engine

The execution engine is the core component responsible for running workflows. It coordinates the execution of nodes, manages workflow progression and handles execution results.

6.1 What is the Execution Engine?

Think of it as the engine of a car: the nodes represent the individual operations, while the execution engine coordinates when and how they run.

6.2 Responsibilities

  1. Initializing workflow execution.
  2. Managing execution context.
  3. Determining which node should execute.
  4. Passing data between nodes.
  5. Handling node execution results.
  6. Managing errors.
  7. Completing workflow execution.
  8. Recording execution information.

6.3 Execution Architecture

Trigger
→
Execution Engine
→
Node Selection
→
Execute Node 1
→
Receive Output
→
Execute Node 2
→
Receive Output
→
Execute Node 3
→
Final Execution

6.4 What Happens When a Node Fails?

Suppose your workflow contains:

Trigger
→
HTTP Request ✖
→
SQL Insert
→
Send Email

The HTTP Request node returns an error. Depending on the node and workflow error configuration:

  • The execution may stop.
  • The error can be routed or handled using configured error-handling mechanisms.
  • A separate error workflow may be invoked if configured.
  • Execution details can be inspected for troubleshooting.

6.5 Main Execution Modes

Regular execution

  • A workflow runs within the normal n8n execution process
  • Simple to run
  • Good for most small and medium setups

Queue mode

  • Execution work is distributed through a queue to worker processes
  • Scales horizontally
  • Important for scalable production deployments
We will explore queue mode in detail in the deployment section (Lesson 2.10 and Chapter 25).
The execution engine is the core that runs workflows: it initializes an execution and its context, decides which node runs next based on connections, passes data between nodes, handles results and errors, and records execution information. It runs either in regular mode inside the main process, or in queue mode where executions are distributed to worker processes.
2.7

Data Flow Architecture

Data flow describes how information moves from one node to another during workflow execution. This is particularly important for developers and data engineers. n8n primarily uses JSON-based data structures to pass information between nodes.

7.2 Understanding JSON Data

Suppose an API returns the following response:

{
  "employee_id": 101,
  "employee_name": "Sreehari",
  "department": "Data Engineering",
  "salary": 50000
}

The HTTP Request node receives this response, and the next node can access the returned information.

7.3 How Data Moves Between Nodes

HTTP Request
→
JSON Response
→
Edit Fields
→
IF Condition
→
Database Insert

Each node receives input and produces output.

7.4 Understanding Items

An important n8n concept is the item: a unit of data processed by nodes.

[
  { "employee_id": 101, "employee_name": "Sreehari" },
  { "employee_id": 102, "employee_name": "Ramesh" },
  { "employee_id": 103, "employee_name": "Kiran" }
]

This represents three records/items. The next node can process these items.

7.5 Understanding Data Transformation

Suppose the source provides:

{ "first_name": "Sreehari", "last_name": "Mekala" }

You want the following output:

{ "full_name": "Sreehari Mekala" }

You can achieve this using the Edit Fields node or a Code node. Example JavaScript:

return $input.all().map(item => {
  return {
    json: {
      full_name:
        item.json.first_name + " " +
        item.json.last_name
    }
  };
});

7.6 Important Data Flow Concepts

ConceptExplanation
JSONData interchange format
ItemIndividual unit of data
InputInformation received by a node
OutputInformation generated by a node
TransformationModifying input data
ExpressionDynamic access to workflow data
MergeCombining data from multiple inputs
BranchingSending data through different paths
Important: n8n's item linking and data references allow you to access information from previous nodes. Learn these carefully in the practical chapters.
Data in n8n flows between nodes as JSON items: each node receives a list of items, processes them — usually once per item — and outputs a new list. Nodes can transform data with Edit Fields or Code, branch it along different paths, merge inputs, and reference earlier nodes through expressions and item linking.
2.8

Credentials Management

Credentials are authentication details required to connect n8n with external applications and services such as Microsoft Outlook, SQL Server, Gmail, OpenAI and Azure services. n8n provides a credential management mechanism to store and reuse them.

8.2 Types of Authentication

AuthenticationDescriptionExample
API KeySecret key used to authenticate requestsOpenAI API
Basic AuthenticationUsername and passwordSome REST APIs
OAuth 2.0Token-based authorizationMicrosoft 365
Bearer TokenToken included in HTTP headersREST APIs
Database CredentialsDatabase username and passwordSQL Server

8.3 How Credential Management Works

n8n Workflow
→
HTTP Request Node
→
Select Credentials
→
Authentication
→
External API

When the node executes, n8n uses the configured credentials to authenticate with the external service.

8.4 Where are Credentials Stored?

  • Credential information is stored in the configured database.
  • Sensitive credential data is encrypted.
  • The encryption key is essential for decrypting credentials.
  • Self-hosted installations must protect the encryption key.

For self-hosted environments, the N8N_ENCRYPTION_KEY environment variable can be used to configure the encryption key.

Important Security Practices

  • Never hardcode passwords in Code nodes
  • Never expose API keys in workflow outputs
  • Use dedicated service accounts
  • Restrict access to credentials
  • Protect environment variables
  • Secure database connections
  • Back up encryption keys securely
  • Rotate credentials periodically
If the encryption key is lost or changed, saved credentials can no longer be decrypted. Store it securely and back it up.

Execution History

Execution history provides information about previously executed workflows: which workflows executed, when, whether they succeeded or failed, which nodes ran, what errors occurred and how long execution took.

9.3 Execution Lifecycle Statuses

Common execution statuses include Running, Success, Error, Waiting and Canceled. The exact status and display can depend on the execution stage and n8n version.

9.5 Execution Data Retention

n8n supports execution data retention and pruning. You can configure execution saving and cleanup according to your operational requirements, for example:

  • Save successful executions only when needed.
  • Save failed executions for troubleshooting.
  • Configure automatic pruning.
  • Avoid retaining unnecessary sensitive data.
Enterprise recommendation: Define an execution retention policy before moving n8n into production.

10.6 Architecture 4: Queue Mode Deployment

Queue mode is important when you need to scale workflow execution. In queue mode, n8n uses Redis to manage queued execution work, and separate worker processes execute workflows.

                       USERS
                         │
                   Load Balancer
                         │
                  n8n Main Process
                  ┌──────┴──────┐
                  ▼             ▼
              PostgreSQL      Redis
                  │             │
                  │      Execution Queue
                  │      ┌──────┼──────┐
                  │      ▼      ▼      ▼
                  │   Worker  Worker  Worker
                  │     1       2       3
                  │      │      │      │
                  └──────┴──────┴──────┘
                         │
                 External Applications

10.7 Components of Queue Mode

ComponentResponsibility
Main processManages workflows and triggers
PostgreSQLStores persistent application data
RedisManages execution queues
WorkersExecute workflow jobs
Load balancerDistributes incoming application requests
External servicesAPIs, databases and applications

10.8 Why Do We Need Queue Mode?

Consider an organization running 10,000 workflow executions every day. If everything runs in a single process, the system may experience resource limitations. Queue mode allows you to distribute execution workloads across multiple workers.

  • Better workload distribution
  • Horizontal scaling
  • Independent worker processes
  • Improved execution capacity
  • Better resource management
Queue mode does not automatically guarantee high availability. You must also design database availability, Redis availability, backups, networking and monitoring.
n8n can run on n8n Cloud, locally, in Docker, on a VM or on Kubernetes. Local installs with SQLite suit learning; production typically uses PostgreSQL for persistence behind a load balancer. For scale, queue mode splits roles: the main process handles workflows and triggers, Redis holds the execution queue, and multiple workers execute jobs, all sharing PostgreSQL. High availability still requires redundant databases, Redis, backups and monitoring.

Interview questions and answers

What is the difference between a trigger and an action?

A trigger starts a workflow; an action performs an operation after the workflow has started.

What is an n8n item?

A unit of workflow data, commonly containing a JSON object and optionally binary data.

Why should credentials not be hard-coded?

Hard-coded secrets can leak through workflow exports, logs, source control, or shared access.

Cloud or self-hosted: which should a beginner choose?

Cloud is usually fastest to start; self-hosting is useful when you need deployment control and can manage operations.
