19.1

What is an AI agent?

An AI agent is a model-driven system that can decide which steps or tools to use to pursue a goal within defined instructions and permissions. Unlike a simple prompt-response call, an agent may select tools, inspect results and continue for multiple steps.

Agent autonomy should be bounded. Define allowed tools, maximum iterations, timeout, budget and actions that require approval.

19.2

AI agent architecture

The model proposes tool calls; the orchestration layer executes them and returns results. The model should not be treated as a trusted execution environment. Validate tool inputs and outputs outside the model.

19.3

AI Agent Node

n8n's AI Agent node coordinates a model with connected tools. Depending on n8n version, agent type and available sub-nodes, configuration can include a chat model, tools, memory and optional output parsing.

  1. Define a narrow task and agent instructions.
  2. Connect a supported chat model.
  3. Attach only the tools required.
  4. Set iteration/time limits where available.
  5. Inspect intermediate steps and final output.
  6. Test with ambiguous, malicious and failure inputs.
19.4

AI tools

Tools let an agent interact with systems—for example, search a knowledge base, query a database, retrieve a ticket or create a draft. Each tool should have a clear name, description, input schema and permission boundary.

A tool description is not a security boundary. Enforce authorization and input validation in the actual workflow/tool implementation.
19.5

Agent memory

Memory provides context across steps or conversations. It may hold recent messages, summaries or retrieved facts. Memory is not automatically accurate or appropriate to retain forever.

  • Define what is stored and why.
  • Set retention and deletion policies.
  • Separate users/sessions to prevent data leakage.
  • Do not store credentials or unnecessary sensitive data.
  • Allow users to correct or clear retained context through approved controls.
19.6

Short-term memory

Short-term memory preserves context within a conversation or agent session. It can help resolve follow-up references but consumes context tokens and may include stale or irrelevant details.

Use session identifiers consistently, bound history length and summarize older turns when needed. Confirm how the chosen n8n memory component scopes sessions.

19.7

Long-term memory

Long-term memory persists selected information beyond a single session, often using a database or vector store. It requires governance: consent/notice, purpose limitation, access control, retention, deletion and correction.

Prefer explicit user-approved facts or curated knowledge over silently storing every conversation. Retrieval should filter by tenant/user and permissions.

19.8

Tool calling

Tool calling is the model's structured request for an external operation. A workflow/tool implementation receives arguments, validates them, performs the operation and returns a result.

  1. Define a narrow tool contract.
  2. Validate types, allowed values and required identifiers.
  3. Check user authorization independently of the model.
  4. Apply timeouts and rate limits.
  5. Return minimal, sanitized results.
19.9

Multi-step reasoning

An agent may plan a sequence such as search a record, inspect status, prepare a draft and request approval. Each step can fail or return misleading information. Keep steps observable and constrain the loop.

For predictable business processes, explicit n8n branches and sub-workflows may be safer than giving an agent broad autonomy.

19.10

Human approval workflows

Require approval before high-impact or irreversible actions such as sending external communications, changing production records, issuing refunds, deleting files or modifying access.

  1. Agent prepares a proposed action.
  2. Workflow displays the proposed payload and evidence.
  3. Approver accepts, rejects or edits.
  4. Workflow checks approval identity and expiry.
  5. Only then does a restricted action node execute.
19.11

AI agent error handling

Common failures include tool timeouts, invalid arguments, missing permissions, empty retrieval, model refusal, iteration exhaustion and malformed output.

  • Set maximum iterations and execution time.
  • Validate tool schemas and outputs.
  • Retry transient errors only when safe.
  • Use idempotency keys for writes.
  • Provide a graceful fallback to a person or deterministic workflow.
  • Log tool name, sanitized arguments, outcome and correlation ID.
19.12

Multi-agent architecture

A multi-agent design divides work among specialized agents, such as a researcher, analyst and reviewer. It can improve separation of concerns but increases orchestration complexity, latency, cost and failure modes.

Use it only when a single agent or deterministic workflow cannot meet the requirement. Define agent responsibilities, shared data contracts, termination conditions and conflict resolution.

Practical labs

Lab 1 – Read-only knowledge agent

  1. Create a small approved knowledge source.
  2. Configure an agent with a read-only search tool.
  3. Ask questions answerable from the source.
  4. Require citations or document references in the response.
  5. Test questions outside the knowledge base and ensure the agent admits uncertainty.

Lab 2 – Human approval before ticket update

  1. Provide the agent a read-only ticket lookup tool.
  2. Ask it to propose a ticket priority or description update.
  3. Send proposed changes to an approval step.
  4. Execute the update only after explicit approval.
  5. Record approver, decision and resulting ticket ID.

Lab 3 – Failure testing

  1. Simulate tool timeout, invalid arguments and permission denial.
  2. Set maximum iterations and a bounded timeout.
  3. Ensure failures route to a safe fallback.
  4. Verify no duplicate write occurs after retry.

Interview questions and answers

  1. What is an AI agent?
    A model-driven system that selects and uses tools to pursue a goal within instructions and constraints.
  2. How does an agent differ from a simple LLM call?
    An agent can choose tools and perform iterative actions rather than only returning one response.
  3. What is the AI Agent node?
    An n8n node that orchestrates a model with connected tools and optional memory.
  4. What is a tool?
    A callable capability such as search, database lookup or ticket creation exposed to an agent.
  5. Why validate tool arguments?
    Model-generated arguments can be invalid, unsafe or unauthorized.
  6. What is short-term memory?
    Context retained during a conversation or agent session.
  7. What is long-term memory?
    Selected information persisted across sessions, often in a database or vector store.
  8. What is tool calling?
    A model's structured request to invoke an external function/tool.
  9. Why limit agent iterations?
    To prevent unbounded loops, excessive cost and long-running executions.
  10. When is human approval required?
    Before consequential, irreversible, external or privileged actions.
  11. How do you prevent duplicate tool writes?
    Use idempotency keys, stable request IDs and safe retry design.
  12. When use multi-agent architecture?
    When distinct specialized roles provide enough benefit to justify extra orchestration and cost.
