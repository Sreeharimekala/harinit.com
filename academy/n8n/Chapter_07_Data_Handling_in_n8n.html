Data Handling in n8n

Learn how n8n represents, passes, maps, transforms and validates data. This chapter covers JSON, objects, arrays, items, expressions, previous-node references, binary files and practical data-quality patterns.

Learning objectives

Chapter overview

Data handling is one of the most important n8n skills. A workflow can execute without errors and still produce incorrect business results if the data structure, mapping or data types are misunderstood.

Read dataUnderstand JSON, objects, arrays and n8n items.
Map dataPass values from previous nodes into later nodes.
Transform dataRename, calculate, filter, combine and reshape fields.
Protect data qualityValidate required fields, types, formats and files.
Key distinction: Data mapping references existing data in another node. Data transformation changes or reshapes data. n8n's documentation makes this distinction explicitly. See Referencing data in the UI.
7.1

Understanding JSON

1 · JSON

JSON (JavaScript Object Notation) is a text format used to represent structured data. n8n commonly uses JSON data to pass fields between nodes and to communicate with APIs.

1.1 Example JSON

{
  "employee_id": 101,
  "employee_name": "Alex Morgan",
  "department": "Data Engineering",
  "is_active": true,
  "monthly_salary": 60000
}

1.2 JSON value types

TypeExampleMeaning
String"Alex"Text in double quotes.
Number60000Numeric value; no quotes.
Booleantrue / falseTrue or false.
Object{"id":101}Collection of key-value pairs.
Array[1,2,3]Ordered list of values.
NullnullExplicit absence of a value.

1.3 JSON syntax rules

  • Property names and string values use double quotes.
  • Use commas between properties or array elements, but not after the final element.
  • Use a colon between a property name and its value.
  • JSON does not support comments.
  • JSON does not support undefined, functions or date objects as native JSON types.
Practical check: If an API expects a number, send 60000, not "60000", unless its API contract explicitly expects text.
7.2

Understanding Objects and Arrays

2 · Objects and arrays

An object stores named properties. An array stores an ordered list of values. JSON objects and arrays can be nested.

2.1 Object example

{
  "employee_id": 101,
  "employee_name": "Alex",
  "department": "IT"
}

Access a property in an n8n expression using {{ $json.employee_name }}.

2.2 Array example

{
  "skills": ["SQL", "Python", "Azure"]
}

Access the first skill using JavaScript-style indexing in an expression: {{ $json.skills[0] }}.

2.3 Array of objects

{
  "employees": [
    { "id": 101, "name": "Alex" },
    { "id": 102, "name": "Jordan" }
  ]
}

Use the appropriate node or expression to iterate over the array, or transform it into separate n8n items when downstream processing should handle each employee independently.

2.4 Common mistakes

  • Trying to access an object property as if it were an array index.
  • Assuming a field exists when it may be null or missing.
  • Confusing a string containing JSON with an actual parsed JSON object.
  • Assuming an array always contains at least one element.
7.3

Items and Data Structures

3 · n8n data structure

n8n processes workflow data as items. In common node outputs, an item has a json property containing structured data and may also have a binary property for file data. A node usually receives and returns a collection of items.

3.1 Example: two n8n items

[
  {
    "json": {
      "employee_id": 101,
      "employee_name": "Alex"
    }
  },
  {
    "json": {
      "employee_id": 102,
      "employee_name": "Jordan"
    }
  }
]

3.2 Item versus array field

ConceptExample
One itemOne employee record.
Multiple itemsA collection of employee records processed by a node.
Array inside one itemOne employee item containing a skills array.

These are not the same: two n8n items are different from one item whose JSON contains an array property. This difference affects iteration, mapping and downstream node behaviour.

3.3 Item linking

n8n tracks relationships between input and output items so later nodes can often identify which earlier item a result came from. This matters when a node changes the number of items or combines data. See the official guide to item linking.

Remember: When writing Code nodes that change item counts or construct new items, preserve item-linking information when needed so expressions can correctly refer back to linked input items.
7.4

Input and Output Data

4 · Input and output

Input is the data received by a node. Output is the data the node produces. The output of one node commonly becomes the input of the next connected node.

4.1 Inspecting input and output

  1. Execute the workflow or test the relevant node.
  2. Select the node on the canvas.
  3. Open its execution details.
  4. Inspect the INPUT panel to see incoming items.
  5. Inspect the OUTPUT panel to see produced items.
  6. Switch between available views such as Schema, Table or JSON when offered.

4.2 Output count can change

  • A node can return one output item for each input item.
  • A filter can return fewer items.
  • An aggregate operation can combine many inputs into fewer outputs.
  • A trigger or query can produce no items if no matching data exists.
  • A split operation can turn one array-containing item into multiple items.

4.3 Debugging example

If a downstream email node has an empty subject, inspect the upstream output first. Confirm that the expected field exists, has the correct spelling and contains a usable value.

7.5

Data Mapping

5 · Data mapping

Data mapping means taking a value from one node and placing it into a parameter or field in another node. Mapping does not, by itself, change the source data.

5.1 Example

Suppose an HTTP Request node returns:

{
  "customer_id": 5001,
  "customer_name": "Alex Morgan",
  "email": "alex@example.com"
}

In a later email node, map the recipient field to:

{{ $json.email }}

Map the message body to a value such as:

Hello {{ $json.customer_name }}, your customer ID is {{ $json.customer_id }}.

5.2 Ways to map data

  • Use the expression editor in a node parameter.
  • Drag a field from the INPUT pane into a parameter when the UI supports it.
  • Reference a node by name when the value is not from the immediate input.

5.3 Mapping best practices

  • Use the field picker to reduce spelling errors.
  • Check whether the field is nested, for example $json.customer.email.
  • Check data types before mapping into numeric, date or Boolean parameters.
  • Handle optional or missing fields with safe defaults or explicit validation.
Official distinction: n8n describes mapping as referencing data from previous nodes, not transforming it. For more detail, read Referencing data in the UI.
7.6

Data Transformation

6 · Data transformation

Data transformation changes the shape, values or structure of data so that it fits the next step in a workflow.

6.1 Common transformation tasks

TaskExampleTypical n8n approach
Rename fieldscust_name → customer_nameEdit Fields
Add calculated fieldMonthly salary × 12Edit Fields expression or Code
Filter recordsKeep only status = FailedFilter or IF
Combine dataJoin customer and order informationMerge
AggregateCount records by categoryAggregate or Code
Split arraysOne array into separate itemsSplit Out
Format dateConvert timestamp to a readable dateDate & Time or expressions

6.2 Example: add annual salary

Input:

{
  "employee_name": "Alex",
  "monthly_salary": 60000
}

Expected output:

{
  "employee_name": "Alex",
  "monthly_salary": 60000,
  "annual_salary": 720000
}

Using a Code node in JavaScript:

const items = $input.all();

return items.map(item => ({
  json: {
    ...item.json,
    annual_salary: Number(item.json.monthly_salary) * 12
  }
}));

For simple field mapping and calculations, prefer Edit Fields where it is sufficient. Use Code when the transformation is more complex or requires custom logic.

6.3 Data transformation checklist

  • Know the input schema.
  • Define the expected output schema.
  • Preserve fields needed by later nodes.
  • Convert data types intentionally.
  • Handle nulls and unexpected values.
  • Test with multiple items, not only one sample.
7.7

Expressions

7 · Expressions

Expressions are dynamic snippets used in node parameters to calculate or retrieve values at runtime. In the n8n editor, expressions commonly use the double-curly-brace syntax.

7.1 Basic expressions

ExpressionPurpose
{{ $json.name }}Read the name field from the current input item.
{{ $json.customer.email }}Read a nested email field.
{{ $json.amount * 1.18 }}Calculate a value using the amount.
{{ $now }}Use the current date/time value provided by n8n.
{{ $execution.id }}Reference the current execution ID.

7.2 Conditional expression example

{{ $json.status === "Failed" ? "Alert" : "No Alert" }}

7.3 Default value example

{{ $json.department || "Unassigned" }}

This uses JavaScript's logical OR behaviour, so an empty string, zero or false also falls back to the default. If those are valid values, use a more precise nullish check such as {{ $json.department ?? "Unassigned" }}.

7.4 Expressions versus Code node

ExpressionCode node
Used inside a parameter or field to produce a dynamic value.Runs a custom script to process input items.
Best for straightforward field references, formatting and calculations.Best for complex transformations, loops or custom algorithms.
Important: Expressions are evaluated in n8n's expression environment. Python is available in the Code node in supported configurations, but not in n8n expressions. See the official expression and built-in methods documentation.
7.8

Referencing Previous Nodes

8 · Previous node references

Use a node reference when you need data from a particular earlier node rather than only the current node's input.

8.1 Current input versus named node

ReferenceMeaning
{{ $json.customer_name }}Field from the current input item.
{{ $('Get Customer').item.json.email }}Linked item data from the node named Get Customer.
{{ $('Get Customer').first().json.email }}First output item's email from that node.
{{ $('Get Customer').all() }}All output items from that node.

Use the expression editor's node selector or drag-and-drop mapping where possible. The exact item accessor you need depends on whether you want the linked item, first item, all items or a specific item.

8.2 Example workflow

Get Customer → Get Orders → Build Email │ ↑ └──── reference customer ─┘

The email step may need the customer name from Get Customer and order details from its current input. A named-node reference can access the earlier customer data when item linking and execution context permit.

8.3 Item linking matters

When a workflow processes multiple items, n8n needs to know which output item corresponds to which input item. If a Code node creates or combines items without appropriate linking, a later expression that expects a paired item can fail or return unexpected data.

Best practice: Prefer the current input reference $json when possible. Use named-node references when there is a clear need to reach back to a specific node, and test with multiple items and branches.

Official guide: Referencing data in the UI and Item linking.

7.9

Working with Binary Data

9 · Binary data

Binary data represents file content such as PDFs, images, spreadsheets, audio files or other attachments. In n8n, an item can contain JSON metadata and a binary property that references the file data.

9.1 JSON versus binary

JSON dataBinary data
Structured values such as file name, customer ID or status.The actual content of the PDF, image or spreadsheet.
Human-readable fields in JSON view.Usually handled by nodes designed to read, write, upload or convert files.

9.2 Example use cases

  • Download a PDF using HTTP Request.
  • Read email attachments from an email trigger.
  • Extract text or rows from a PDF or spreadsheet.
  • Convert JSON data into a CSV or file.
  • Upload an image or document to cloud storage.

9.3 Common file nodes

Node / capabilityTypical purpose
Extract From FileExtract data from supported file formats.
Convert to FileConvert structured data into a file format.
Read/Write Files from DiskRead or write files on the host where permitted.
HTTP RequestDownload or upload files when the API supports it.
Email nodesReceive or send attachments, depending on node operation.

9.4 File-handling precautions

  • Validate file type and size.
  • Do not trust the filename extension alone; validate actual content where appropriate.
  • Be careful with untrusted documents and macros.
  • Consider execution-data retention and storage usage.
  • For large-volume deployments, understand the configured binary data storage mode and pruning.
Deployment note: n8n's binary data storage options depend on deployment and plan. External S3 binary storage is documented as an Enterprise feature for supported self-hosted deployments. See External storage documentation.
7.10

Data Validation

10 · Data validation

Data validation checks whether incoming data meets the rules required by the workflow and downstream systems. Validate data before sending emails, writing to databases, calling APIs or making business decisions.

10.1 Common validation rules

ValidationExample rule
Required fieldsemployee_id must be present.
Data typemonthly_salary must be numeric.
FormatEmail address must match an acceptable format.
RangeAmount must be greater than or equal to zero.
Allowed valuesStatus must be one of New, In Progress or Closed.
UniquenessOrder ID must not already have been processed.
Business consistencyEnd date must not be earlier than start date.

10.2 Example validation workflow

Trigger → Validate required fields → Validate data types ↓ IF valid? ↙ ↘ Valid Invalid ↓ ↓ Process data Log / reject / notify

10.3 Example Code node validation

const items = $input.all();

return items.map(item => {
  const data = item.json;
  const errors = [];

  if (!data.employee_id) {
    errors.push("employee_id is required");
  }

  if (typeof data.employee_name !== "string" ||
      data.employee_name.trim() === "") {
    errors.push("employee_name must be a non-empty string");
  }

  const salary = Number(data.monthly_salary);
  if (!Number.isFinite(salary) || salary < 0) {
    errors.push("monthly_salary must be a valid non-negative number");
  }

  return {
    json: {
      ...data,
      is_valid: errors.length === 0,
      validation_errors: errors
    }
  };
});

After this node, use an IF node on is_valid to route valid and invalid records. For production workflows, decide whether invalid records should be rejected, quarantined, logged or sent for correction.

10.4 Validation versus error handling

ValidationError handling
Checks whether data is acceptable before processing.Handles failures that occur during processing.
Example: required customer ID is missing.Example: database connection times out.
Security and privacy: Avoid logging passwords, access tokens, personal information or full sensitive documents in validation error messages. Store only the details needed to diagnose and correct the problem.

Practical Labs

Hands-on practice

Lab 1 — Explore JSON and items

  1. Create a Manual Trigger workflow.
  2. Add Edit Fields and create employee ID, name, department and salary.
  3. Add two sample records if your chosen node setup supports multiple items, or use a Code node to return two items.
  4. Inspect the JSON output and count the items.
  5. Compare two items with one item containing an array.

Lab 2 — Map fields into a message

  1. Create a sample customer record.
  2. Add an email or message node in a test environment.
  3. Map the recipient and customer name from input fields.
  4. Run with sample data and verify the resolved values.

Lab 3 — Transform employee data

  1. Input monthly salary and employee name.
  2. Use Edit Fields to add annual salary.
  3. Use a Filter or IF node to identify salaries above a chosen threshold.
  4. Inspect output data types and values.

Lab 4 — Reference a previous node

  1. Add one node named Get Customer that outputs customer details.
  2. Add another node that outputs order details.
  3. In a later node, reference customer name from the named earlier node.
  4. Test with multiple items and understand item linking.

Lab 5 — Validate incoming data

  1. Create fields for employee ID, name and monthly salary.
  2. Use the validation Code example above.
  3. Connect an IF node to route valid and invalid records.
  4. Test missing ID, blank name, negative salary and valid data.

Lab 6 — Process a file

  1. Use a test PDF or CSV file with non-sensitive sample data.
  2. Bring the file into n8n using a suitable file source.
  3. Inspect the binary property and metadata.
  4. Use a suitable extraction or conversion node.
  5. Validate extracted fields before downstream processing.
