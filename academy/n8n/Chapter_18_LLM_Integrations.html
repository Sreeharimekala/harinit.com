18.1

OpenAI integration

Connect n8n to OpenAI models using the supported OpenAI node or API integration. Configure an API credential in n8n; do not paste API keys into prompts, expressions or Code nodes.

Choose the model and operation, provide instructions and input, configure supported generation options, then inspect the response. API models and ChatGPT product features are related but distinct: a ChatGPT subscription does not automatically provide API usage credits.

18.2

ChatGPT integration

In automation discussions, “ChatGPT integration” usually means using an OpenAI model through the API or a supported n8n integration. ChatGPT is the end-user assistant product; the API is a developer platform with separate credentials, billing, limits and configuration.

For production workflows, use API credentials, an appropriate project and usage limits. Never assume a ChatGPT web session can be called directly from n8n.

18.3

Google Gemini integration

Gemini models can be accessed through Google's supported API and n8n integration options. Create and secure the required API credential, choose an available model, and verify supported input types, context size, safety settings and output capabilities.

Model names and availability change. Pin a model/version where supported and re-test before changing it in production.

18.4

Anthropic Claude integration

Claude models can be called through Anthropic's API or supported n8n integrations. Configure the API key securely and review model-specific limits, supported features and pricing. Use clear system instructions and validate outputs before downstream actions.

18.5

Ollama integration

Ollama runs supported models locally or on a server you control and exposes a local API. n8n must be able to reach the Ollama host from its runtime. If n8n runs in Docker, localhost inside the container refers to that container, not automatically the host machine.

Typical local endpoint:
http://localhost:11434

For container deployments, configure a reachable service hostname/network route. Do not expose Ollama publicly without appropriate network controls and authentication at the boundary.

18.6

Local LLM integration

A local LLM can improve data control and avoid per-request external API charges, but it still has infrastructure costs: CPU/GPU, RAM/VRAM, storage, maintenance, scaling and monitoring.

ConsiderationQuestions
HardwareCan the machine load the model and serve concurrent requests?
QualityDoes the model perform well on your actual task and language?
LatencyCan it meet workflow response-time needs?
SecurityWho can access the inference endpoint and logs?
OperationsHow are models updated, monitored and rolled back?
18.7

Model selection

Select models by testing representative tasks, not by brand alone.

  • Task quality and reliability on your domain data.
  • Context window and structured output support.
  • Latency and throughput.
  • Input/output token price or local infrastructure cost.
  • Data residency, retention and provider terms.
  • Tool-calling and multimodal capability where needed.

Maintain an evaluation set and compare candidate models before production changes.

18.8

System prompts

A system instruction defines the assistant's role, constraints and expected behaviour. Keep it stable and version-controlled. State allowed tasks, forbidden actions, uncertainty handling and output contract.

You are an operations assistant.
Classify the provided incident description.
Use only these priorities: P1, P2, P3, P4.
Do not invent facts or incident identifiers.
Return only the required JSON schema.
18.9

User prompts

The user prompt carries the specific request and data to process. Delimit source text and label it as untrusted content. Do not combine instructions and source text in a way that lets an email or document override the system task.

Classify this request using the system rules.
Source text (untrusted):
<message>{{ $json.body }}</message>
18.10

Structured output

Structured output asks the model to return data in a defined shape, often JSON. Use a schema with required properties, allowed enums and types. Then parse and validate it; a model saying it returned JSON does not guarantee the output is valid.

{
  "type": "object",
  "required": ["category", "priority", "summary"],
  "properties": {
    "category": {"type":"string", "enum":["Data","Access","Pipeline","Other"]},
    "priority": {"type":"string", "enum":["P1","P2","P3","P4"]},
    "summary": {"type":"string"}
  }
}
18.11

Token management

Tokens are the units used to measure model input and output. Prompt instructions, retrieved documents, conversation history and generated text all consume context and/or output budget.

  • Send only relevant context.
  • Limit retrieved chunks and conversation history.
  • Set reasonable output limits.
  • Summarize long histories when appropriate.
  • Handle context-window errors and truncation explicitly.
18.12

Model cost management

Cost depends on provider, model, input/output tokens, request volume and sometimes tools, image/audio processing or cached tokens. Local models shift cost to infrastructure and operations rather than making it zero.

  • Estimate cost using realistic sample volumes.
  • Use smaller/cheaper models for simple classification where quality permits.
  • Limit prompt size and output length.
  • Cache stable results where appropriate.
  • Set provider budgets/alerts and n8n execution monitoring.
  • Track cost by workflow, business process and model.

Practical labs

Lab 1 – Provider comparison

  1. Prepare a fixed set of ten representative prompts.
  2. Run them against two available providers/models.
  3. Capture correctness, output validity, latency and token usage.
  4. Compare quality and cost before choosing a production model.

Lab 2 – Ollama local model

  1. Install Ollama and pull a suitable model.
  2. Verify its local API responds.
  3. Ensure n8n can reach the Ollama host from its runtime/network.
  4. Configure the supported n8n model integration or HTTP Request.
  5. Run a test prompt and measure latency/resource use.

Lab 3 – JSON extraction

  1. Supply a sample incident description.
  2. Ask the model for a strict JSON object using an allowed schema.
  3. Parse the response and validate required fields/enums.
  4. Send invalid outputs to a retry or human-review branch.

Interview questions and answers

  1. Does a ChatGPT subscription automatically include API credits?
    No. ChatGPT product access and API platform usage/billing are separate.
  2. How do you connect OpenAI to n8n?
    Use the supported node/API integration and store the API credential securely in n8n.
  3. Why distinguish Gemini and Claude integrations?
    Each provider has its own API, models, credential setup, limits, features and pricing.
  4. What is Ollama?
    A tool/runtime for running supported LLMs locally or on a server you control.
  5. Why can localhost fail from Docker?
    Inside a container, localhost refers to that container, not necessarily the host machine.
  6. How choose a model?
    Evaluate task quality, context, structured output, latency, cost, security and throughput.
  7. What is a system prompt?
    High-level instructions defining role, constraints and response behaviour.
  8. What is a user prompt?
    The specific request and input data supplied for the current model call.
  9. Why validate structured output?
    The response may be malformed, incomplete or outside allowed values despite the requested format.
  10. What consumes tokens?
    Prompt text, context, conversation history, retrieved documents and generated output.
  11. How reduce token usage?
    Trim irrelevant context, retrieve selectively, limit output and summarize history.
  12. Are local LLMs free?
    Not necessarily; hardware, power, hosting, maintenance and operational costs remain.
