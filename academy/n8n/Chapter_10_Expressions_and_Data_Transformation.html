Expressions and Data Transformation

Learn how to create dynamic values, access data from the current and previous nodes, and transform dates, strings, numbers, arrays and objects using n8n expressions. This chapter builds the skills needed to map clean data between APIs, databases and business workflows.

10.1

Expression foundations

An n8n expression is a JavaScript-based expression evaluated at runtime using data available to the current workflow execution. Expressions let you insert values that change for each item or execution instead of typing fixed values into node fields.

Read data

Access current input with $json or reference data from another node.

Build values

Combine text, calculate numbers and construct dynamic URLs or messages.

Transform data

Format dates, normalize strings and reshape arrays or objects.

Apply logic

Use conditions to choose values based on the incoming data.

Conceptual diagram. Expressions are evaluated using the current execution context; this is not a screenshot of the n8n editor.
Important distinction: expressions are used in fields that support expression mode. They are not the same as writing code in the Code node. Use expressions for field-level dynamic values and the Code node for larger custom transformations.
10.2

Expression editor

Where expressions are created

The expression editor is the interface for entering and previewing dynamic values in supported node fields. In the editor, you can switch a field from fixed-value mode to expression mode, type an expression or use the input data panel to insert references.

Typical steps

  1. Open a node that has a field supporting expressions, such as an HTTP Request URL or an Edit Fields value.
  2. Switch the field to Expression mode (the control's appearance can vary by n8n version).
  3. Enter an expression or drag/select data from the input panel.
  4. Review the preview/result where available.
  5. Execute the node with representative input data to confirm the runtime value.

Fixed value vs expression

ModeExampleResult
Fixed valueorders@example.comSame recipient every time.
Expression{{ $json.email }}Recipient comes from each current item.
The expression preview depends on available input data. If the node has not received representative input, the preview may be empty or may not reflect the actual production execution.
10.3

Expression syntax

JavaScript inside {{ }}

In n8n's expression fields, dynamic expressions are generally wrapped in double curly braces: {{ ... }}. Inside the braces you can use JavaScript expressions and n8n-provided variables and helpers.

Core syntax examples

// Current input item's JSON
{{ $json.customer_name }}

// Nested field
{{ $json.customer.address.city }}

// Combine strings
{{ $json.first_name + " " + $json.last_name }}

// Numeric calculation
{{ Number($json.quantity) * Number($json.unit_price) }}

// Use a fallback when value is nullish
{{ $json.email ?? "unknown@example.com" }}

Common reference helpers

ExpressionMeaning
$jsonJSON data for the current input item.
$binaryBinary data for the current item, when present.
$input.first()First item from the current node's input.
$input.all()All items from the current node's input.
$('Node Name').first().jsonJSON data from the first output item of a named node.
$('Node Name').all()All output items from a named node.
$now / $todayCurrent date-time / start of today as n8n DateTime values.
$varsWorkflow variables available to the workflow.
$workflowInformation about the current workflow.

Accessing another node

// Linked item from a named node
{{ $('Get Customer').item.json.customer_id }}

// First output item from a named node
{{ $('Get Customer').first().json.customer_id }}

// All output items from a named node
{{ $('Get Customer').all() }}
Item linking matters: use .item when you need the item linked to the current item. Use .first() only when the first output item is deliberately the one you want. If a workflow aggregates or reshapes items, verify that the reference returns the intended record.

Expression vs Code node

  • Expression: a value or calculation for one supported field, evaluated in the current item context.
  • Code node: a script for custom transformations across one or many items.
  • Do not assume every n8n expression-only helper is available inside the Code node; check the reference for the specific method.
10.4

Dynamic values

Values change with data

Dynamic values are calculated when the workflow runs. They can come from the current item, previous nodes, workflow metadata, variables or date/time helpers.

Example: dynamic email

To:
{{ $json.email }}

Subject:
Order {{ $json.order_id }} has been received

Message:
Hello {{ $json.customer_name }},
Your order total is {{ $json.currency }} {{ $json.total }}.

Example: dynamic API URL

https://api.example.com/customers/{{ $json.customer_id }}/orders

Example: dynamic filename

customer_{{ $json.customer_id }}_{{ $now.toFormat('yyyyLLdd_HHmmss') }}.csv

Where dynamic values are useful

  • HTTP Request URLs, query parameters and request bodies.
  • Email recipients, subject lines and message bodies.
  • Database values and record keys.
  • File names and folder paths.
  • Conditional messages, labels and status fields.
10.5

Date and time transformations

Luxon DateTime

n8n recommends using Luxon-based DateTime helpers in expressions for date and time operations. The workflow time zone is important: $now uses the workflow's configured time zone, and date strings from other nodes should be parsed before date arithmetic.

Useful date expressions

// Current date and time
{{ $now }}

// Current date at the start of today
{{ $today }}

// Current timestamp as ISO string
{{ $now.toISO() }}

// Seven days ago
{{ $today.minus({ days: 7 }).toISODate() }}

// Add 2 hours
{{ $now.plus({ hours: 2 }).toISO() }}

// Format date as dd/MM/yyyy
{{ $now.toFormat('dd/LL/yyyy') }}

// Convert to a named time zone
{{ $now.setZone('Asia/Kolkata').toISO() }}

Parse incoming dates

// Input is ISO 8601
{{ DateTime.fromISO($json.created_at).toFormat('dd LLL yyyy') }}

// Input format is 21-11-2026
{{ DateTime.fromFormat($json.business_date, 'dd-MM-yyyy').toISODate() }}

Common format tokens

TokenMeaningExample
yyyyFour-digit year2026
LLTwo-digit month11
ddDay of month21
HH24-hour clock hour14
mmMinute05
ssSecond09
Timezone warning: do not assume that a timestamp without a timezone is UTC. Confirm the source system's timezone, the workflow timezone and whether conversion should preserve the same instant or the same wall-clock time.

Date helpers in expressions vs Code node

Some methods documented for n8n's expression editor are n8n-specific extensions and may not exist in the Code node. For example, expression formatting examples may use .format(), while native Luxon formatting in Code uses .toFormat(). Check the method documentation before copying an expression into Code.

10.6

String manipulation

Text cleanup and formatting

JavaScript string methods can normalize, search, extract and combine text. They are useful for cleaning data received from forms, spreadsheets, databases and APIs.

Common operations

// Remove leading/trailing spaces
{{ $json.customer_name.trim() }}

// Convert to uppercase
{{ $json.country.toUpperCase() }}

// Convert to lowercase
{{ $json.email.toLowerCase() }}

// Replace text
{{ $json.phone.replaceAll('-', '') }}

// Get first 5 characters
{{ $json.reference.substring(0, 5) }}

// Combine text
{{ $json.first_name + ' ' + $json.last_name }}

// Check if a value contains text
{{ $json.email.includes('@') }}

Safer handling of missing values

// Convert missing name to an empty string, then trim
{{ String($json.customer_name ?? '').trim() }}

// Normalize email safely
{{ String($json.email ?? '').trim().toLowerCase() }}
Normalize text before comparing it. For example, "Active", " active " and "ACTIVE" are different strings unless you standardize case and whitespace.
10.7

Number conversions

Numeric calculations

Values from APIs, CSV files and databases may arrive as strings. Convert them to numbers before doing arithmetic or numeric comparisons.

Common conversions

// Convert a numeric string
{{ Number($json.amount) }}

// Integer conversion
{{ parseInt($json.quantity, 10) }}

// Floating-point conversion
{{ parseFloat($json.unit_price) }}

// Default nullish value to zero
{{ Number($json.discount ?? 0) }}

// Calculate line total
{{ Number($json.quantity) * Number($json.unit_price) }}

// Round to 2 decimal places
{{ Number((Number($json.amount)).toFixed(2)) }}

Validate before calculating

// Check whether a value can be converted to a finite number
{{ Number.isFinite(Number($json.amount)) }}
InputConversionResult
"125"Number("125")125
"12.75"parseFloat("12.75")12.75
"abc"Number("abc")NaN
nullNumber(null)0
Be careful with empty strings, nulls, currency symbols and comma-formatted numbers. For example, Number("") returns 0, while Number("1,250") returns NaN. Clean and validate values before calculations.
10.8

Array manipulation

Working with lists

An array is an ordered list of values. In n8n, remember the difference between multiple n8n items and an array stored inside one item's JSON. Array methods operate on the array value itself.

Example input

{
  "products": [
    { "name": "Keyboard", "price": 1200 },
    { "name": "Mouse", "price": 500 },
    { "name": "Monitor", "price": 8500 }
  ]
}

Common array expressions

// Number of products
{{ $json.products.length }}

// First product name
{{ $json.products[0].name }}

// Get product names
{{ $json.products.map(p => p.name) }}

// Filter products costing over 1000
{{ $json.products.filter(p => p.price > 1000) }}

// Sum all product prices
{{ $json.products.reduce((total, p) => total + p.price, 0) }}

// Join product names into a string
{{ $json.products.map(p => p.name).join(', ') }}

Array method guide

MethodPurposeExample
map()Transform every element into a new value.items.map(x => x.id)
filter()Keep elements that satisfy a condition.items.filter(x => x.active)
find()Return the first matching element.items.find(x => x.id === 5)
some()Check whether at least one element matches.items.some(x => x.active)
every()Check whether all elements match.items.every(x => x.valid)
reduce()Accumulate elements into one result.items.reduce((s,x) => s+x.amount,0)
join()Join array elements into a string.names.join(', ')
If each nested array element must become its own n8n item for downstream processing, use the Split Out node. If you only need a calculated value or transformed array inside a field, an expression may be enough.
10.9

Object manipulation

Working with JSON objects

An object stores related data as key-value pairs. Expressions can read nested properties, create new objects, copy existing objects and select fields for an API payload.

Read nested properties

{{ $json.customer.address.city }}

Create a new object

{{ {
  customerId: $json.customer_id,
  name: $json.customer_name,
  contact: {
    email: $json.email,
    phone: $json.phone
  }
} }}

Copy an object and add a field

{{ {
  ...$json,
  processed: true,
  processedAt: $now.toISO()
} }}

Select only required fields

{{ {
  order_id: $json.order_id,
  order_status: $json.status,
  total_amount: Number($json.total_amount)
} }}

Useful object operations

  • Object.keys(obj) returns the object's property names.
  • Object.values(obj) returns the object's values.
  • Object.entries(obj) returns key/value pairs.
  • { ...obj, newField: value } creates a shallow copy with an added or overridden property.
Object spread is a shallow copy. Nested objects are not deeply cloned. Also, avoid referencing a nested property without checking that its parent object exists; otherwise the expression can fail.
10.10

Conditional expressions

Inline business rules

Conditional expressions return different values depending on whether a condition is true or false. They are useful when a field value must be calculated dynamically, without routing the workflow into separate branches.

Ternary operator

// Simple condition
{{ $json.total >= 1000 ? 'High Value' : 'Standard' }}

// Payment status
{{ $json.paid ? 'Paid' : 'Pending' }}

// Multiple outcomes
{{ $json.score >= 80 ? 'A' : $json.score >= 60 ? 'B' : 'C' }}

Nullish coalescing and logical OR

// Use fallback only for null or undefined
{{ $json.region ?? 'Unknown' }}

// Use fallback for any falsy value (including empty string, 0, false)
{{ $json.region || 'Unknown' }}

Conditional field value

{{ $json.is_active ? 'Enabled' : 'Disabled' }}

When to use a conditional expression vs IF node

NeedRecommended
Choose one value for a field.Ternary expression.
Send records down different workflow paths.IF node.
Route records to several categories.Switch node.
Keep only records matching a condition.Filter node.
10.11

Referencing workflow variables

Workflow context

Expressions can access more than item data. n8n exposes context variables for workflow metadata, workflow variables, execution information and current time. The exact availability of a variable can depend on the execution context and n8n configuration.

Common context variables

VariablePurposeExample
$varsAccess workflow variables configured for the workflow.{{ $vars.environment }}
$workflowAccess current workflow metadata.{{ $workflow.name }}
$executionAccess current execution metadata.{{ $execution.id }}
$nowCurrent date-time in workflow timezone.{{ $now.toISO() }}
$todayStart of the current day.{{ $today.toISODate() }}
$runIndexIndex of the current node run.{{ $runIndex }}

Example: environment-specific API base URL

// Example workflow variable: api_base_url
{{ $vars.api_base_url + '/customers/' + $json.customer_id }}

Example: execution audit field

{{ {
  workflow_name: $workflow.name,
  execution_id: $execution.id,
  processed_at: $now.toISO()
} }}
Variables are not secrets: do not store passwords, API keys or other credentials in ordinary workflow variables. Use n8n credentials or an appropriate secrets-management integration for sensitive values. Variable availability and permissions can depend on your n8n plan and deployment.
10.12

Practical transformation patterns

Pattern A — Normalize customer information

{{ {
  customer_id: String($json.customer_id ?? '').trim(),
  full_name: String($json.full_name ?? '').trim(),
  email: String($json.email ?? '').trim().toLowerCase(),
  country: String($json.country ?? '').trim().toUpperCase()
} }}

Pattern B — Calculate invoice amount

{{ {
  subtotal: Number($json.quantity) * Number($json.unit_price),
  tax: Number($json.tax_amount ?? 0),
  discount: Number($json.discount ?? 0),
  total: Number($json.quantity) * Number($json.unit_price)
          + Number($json.tax_amount ?? 0)
          - Number($json.discount ?? 0)
} }}

Pattern C — Prepare a date range for an API

{{ {
  from_date: $today.minus({ days: 7 }).toISODate(),
  to_date: $today.toISODate()
} }}

Pattern D — Build a compact notification

{{ `Order ${$json.order_id} for ${$json.customer_name} is ${$json.status}. Total: ${$json.currency} ${$json.total}.` }}

Pattern E — Extract a set of IDs from a nested list

{{ $json.orders.map(order => order.order_id) }}
When the same complex transformation is needed in several places, consider preparing it once in Edit Fields or a reusable sub-workflow. Keep field-level expressions understandable and avoid duplicating long business rules.

Hands-on practical labs

Lab 1 — Build dynamic customer email content

Goal: use current item values in a message.
  1. Prepare sample JSON with customer name, email, order ID and total.
  2. In an email node, set the recipient using {{ $json.email }}.
  3. Create a dynamic subject using the order ID.
  4. Build a message body with the customer's name and total.
  5. Execute with multiple customer items and inspect each rendered value.

Lab 2 — Date transformations

Goal: produce reporting dates.
  1. Create a sample workflow with a Manual Trigger.
  2. Use Edit Fields to add today's date and the date seven days ago.
  3. Format one field as dd/LL/yyyy.
  4. Convert the result to ISO date format for an API parameter.
  5. Check the workflow timezone and test the result.

Lab 3 — Clean and calculate sales data

Goal: normalize strings and numeric values.
  1. Prepare records with extra spaces, mixed-case emails and numeric strings.
  2. Use expressions to trim and lowercase text.
  3. Convert quantity and price to numbers.
  4. Calculate line totals and round to two decimal places.
  5. Test missing and invalid values.

Lab 4 — Transform an array

Goal: use map, filter and reduce.
  1. Prepare one item containing a products array.
  2. Use map() to extract product names.
  3. Use filter() to keep products above a price threshold.
  4. Use reduce() to calculate the total price.
  5. Inspect the resulting fields.

Lab 5 — Construct an API payload

Goal: build a clean nested JSON object.
  1. Prepare customer and address fields.
  2. Use an expression in Edit Fields to create a nested customer object.
  3. Use object spread to retain selected existing fields.
  4. Remove internal-only fields from the outbound payload.
  5. Validate the payload structure before sending it to a test endpoint.

Lab 6 — Use workflow variables and context

Goal: create environment-aware output.
  1. Configure a non-sensitive workflow variable such as environment or api_base_url, where supported.
  2. Reference it using $vars.
  3. Add workflow name and execution ID to an audit object.
  4. Execute the workflow and inspect the values.
  5. Confirm that credentials are stored separately from ordinary variables.
Use the expression preview and actual node execution together. A syntactically valid expression can still produce an unexpected result when the input data type, timezone or item-linking context differs from your assumption.

Troubleshooting and best practices

ProblemLikely reasonHow to fix
Expression is displayed as plain textField is in fixed-value mode or expression delimiters are missing.Switch to Expression mode and check the expression syntax.
Expression returns undefinedField path is incorrect or property is absent.Inspect input JSON and verify each nested property.
Cannot read property of undefinedA parent object is missing.Use optional chaining or nullish defaults, for example $json.customer?.address?.city.
Number calculation returns NaNInput contains non-numeric text, separators or symbols.Clean and validate values before converting.
Date output is shiftedTimezone or source timestamp interpretation is incorrect.Confirm source timezone, workflow timezone and conversion behaviour.
Date method is not a functionMethod is not supported in that expression/runtime context.Check the n8n expression reference; use native Luxon methods in Code where appropriate.
Wrong record is referenced from another nodeFirst-item reference used where linked-item reference was needed, or item linking changed.Choose .item, .first() or .all() intentionally and test with multiple items.
Array result is emptyWrong field path, value is not an array, or filter condition excludes all elements.Inspect the array and test the condition separately.
Workflow variable is unavailableVariable is not configured, not in scope or unsupported by the environment.Check workflow variables, permissions and deployment/plan availability.

Expression best practices

  • Use descriptive field names and keep expressions readable.
  • Use ?? when only null/undefined should trigger a fallback; use || only when all falsy values should trigger it.
  • Convert types before comparing or calculating.
  • Use Luxon for date arithmetic and be explicit about timezones.
  • Use named-node references when you need data from a particular upstream node; understand item linking.
  • Do not put secrets in expressions or ordinary workflow variables.
  • Use Edit Fields for reusable or multi-field data shaping; use Code for complex custom transformations.
  • Test nulls, empty strings, unexpected formats and multiple items.
10.15

Interview questions and answers

  1. What is an n8n expression?
    A JavaScript-based expression evaluated at runtime using the current workflow execution context.
  2. What syntax wraps an expression?
    Usually double curly braces: {{ ... }}.
  3. What is the Expression editor?
    The UI for entering, selecting and previewing dynamic expressions in supported node fields.
  4. What does $json represent?
    The JSON data for the current input item.
  5. How do you reference a previous node?
    For example, $('Node Name').item.json.field, with first/all variants when appropriate.
  6. What is the difference between .item and .first()?
    .item follows linked-item context; .first() explicitly selects the first output item.
  7. How do you create a dynamic value?
    Reference current or upstream data inside an expression in a supported field.
  8. Which date library is recommended in n8n expressions?
    Luxon DateTime helpers.
  9. What are $now and $today?
    They represent the current date-time and the start of the current day in the workflow's configured timezone.
  10. How do you add seven days to the current date?
    Use $today.plus({ days: 7 }).
  11. How do you format a date in an expression?
    For example, $now.toFormat('dd/LL/yyyy').
  12. Why are timezones important?
    The same instant can display as different local times; source and workflow timezone assumptions must be clear.
  13. How do you normalize an email?
    Use String($json.email ?? '').trim().toLowerCase().
  14. How do you convert a string to a number?
    Use Number(), parseInt() or parseFloat() as appropriate.
  15. What is NaN?
    A JavaScript value meaning “Not-a-Number”, often produced by invalid numeric conversion.
  16. What does map() do?
    Transforms each element of an array and returns a new array.
  17. What does filter() do?
    Returns a new array containing elements that satisfy a condition.
  18. What does reduce() do?
    Accumulates array elements into one result, such as a sum.
  19. How do you access a nested object property safely?
    Use optional chaining, for example $json.customer?.address?.city.
  20. How do you create a new object from existing data?
    Use an object literal and, where appropriate, the spread operator.
  21. What is a ternary expression?
    A compact conditional expression: condition ? valueIfTrue : valueIfFalse.
  22. What is the difference between ?? and ||?
    ?? falls back only for null/undefined; || falls back for any falsy value.
  23. How do you access workflow variables?
    Use $vars.variableName when the variable is configured and available.
  24. Should API keys be stored in workflow variables?
    No. Use n8n credentials or a suitable secrets manager.
