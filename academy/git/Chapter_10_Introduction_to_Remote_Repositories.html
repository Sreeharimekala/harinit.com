Chapter introduction

What it is. A remote repository is another copy of the project, usually hosted on a server (GitHub, Azure Repos, GitLab, Bitbucket), that the team uses to share commits.

In this course's project. Stage 4 begins: the team creates the GitHub repository retail-data/enterprise-retail-data-platform (private) and decides on SSH for developers and tokens/OIDC for automation.

10.1

What is a remote repository?

Source S11 · Chapter manual · 1. What is a remote repository?

A remote repository is another Git repository hosted outside your local working environment. It may be hosted by GitHub, GitLab, Bitbucket, Azure Repos, or your organization's own Git server.

Remotes let developers exchange commits, collaborate through reviews, and maintain shared project history. A remote is a named connection (such as origin) to another repository.

git remote -v
git remote add origin <repository-url>
git fetch origin

Local vs remote repository

Source S11 · Chapter manual · 2. Local vs remote repository

Stored on your computer.Hosted on a server or cloud platform.
Supports local commits and branches.Shared collaboration point for teams.
Can commit while offline.Requires network access to communicate.
Local branch names such as main.Remote-tracking references such as origin/main.

git fetch downloads remote objects and updates remote-tracking references. git pull fetches and then integrates changes into the current branch. git push sends local commits to a remote.

10.3

What is GitHub?

Source S11 · Chapter manual · 3. What is GitHub?

GitHub is a cloud platform for hosting Git repositories and collaborating on software. It adds pull requests, issues, code review, project management, automation through GitHub Actions, security features, and integrations around Git.

Git is the version-control system; GitHub is a hosting and collaboration platform built around Git. You can use Git without GitHub, and you can use GitHub through its web interface or Git clients.

10.4

Introduction to GitLab

Source S11 · Chapter manual · 4. Introduction to GitLab

GitLab provides Git repository hosting and an integrated DevSecOps platform. Common capabilities include merge requests, issue tracking, CI/CD pipelines, package and container registries, security scanning, and self-managed deployment options.

Organizations may choose GitLab SaaS or self-managed GitLab depending on governance, security, and operational requirements.

Introduction to Bitbucket

Source S11 · Chapter manual · 5. Introduction to Bitbucket

Bitbucket is Atlassian's Git repository hosting and collaboration service. It supports pull requests, access controls, and CI/CD integrations, including Bitbucket Pipelines. It is often used alongside Jira and other Atlassian products.

Creating a repository

Source S11 · Chapter manual · 8. Creating a repository

On GitHub, select New repository, provide a repository name, choose visibility, and optionally initialize it with a README, .gitignore, or license. The exact interface may evolve; follow the platform's current prompts.

Connect an existing local repository

git remote add origin https://github.com/ORG/CustomerETL.git
git branch -M main
git push -u origin main

Clone an existing repository

git clone https://github.com/ORG/CustomerETL.git
cd CustomerETL

Replace the example URL with the repository URL shown by your hosting service.

10.10

Understanding repository URLs

Source S11 · Chapter manual · 10. Understanding repository URLs

A repository URL identifies the remote location. A repository can commonly be accessed through HTTPS or SSH, depending on the host and organization policy.

# HTTPS example
https://github.com/ORG/CustomerETL.git

# SSH example
git@github.com:ORG/CustomerETL.git

Check configured remotes with git remote -v. The remote name origin is only a conventional label; it can be changed or additional remotes can be configured.

10.11

HTTPS vs SSH authentication

Source S11 · Chapter manual · 11. HTTPS vs SSH authentication
HTTPSSSH
Uses an HTTPS repository URL.Uses an SSH repository URL and key-based authentication.
Often authenticates through a credential manager, browser sign-in, or personal access token as required by the host.Uses an SSH key pair; the public key is registered with the hosting service and the private key remains secure on your device.
Can work well behind networks that permit HTTPS.Convenient for repeated Git operations after key setup; network policy may restrict SSH.

HTTPS remote example

git remote add origin https://github.com/ORG/CustomerETL.git
git push -u origin main

Use the host's approved authentication flow. Do not put passwords or tokens directly into repository URLs or scripts.

SSH key setup (high-level)

# Generate an Ed25519 key (if permitted by your organization)
ssh-keygen -t ed25519 -C "developer@example.com"

# Start agent and add key (commands vary by OS/shell)
ssh-add ~/.ssh/id_ed25519

# Test GitHub SSH authentication
ssh -T git@github.com

Register the public key (often id_ed25519.pub) with the hosting service. Never share the private key.

What is a Remote Repository?

Source S40 · 1. What is a Remote Repository?

1.1 Definition

A remote repository is a version of your project hosted on a server or cloud platform that multiple people can access to share and synchronise work. Your local repository keeps a named connection to it (usually origin).

1.2 Characteristics

  • Normally a bare repository (history only, no working files).
  • Acts as the team's agreed source of truth.
  • Provides access control, backup, and collaboration features (pull requests, CI/CD).
  • A local repository can have multiple remotes (e.g. origin and upstream).

1.3 Example

https://github.com/ravi/retail-data-platform.git

10.23

HTTPS vs SSH Authentication

Source S40 · 11. HTTPS vs SSH Authentication

11.1 HTTPS

  • Authenticate with a username + Personal Access Token, or browser/OAuth sign-in through Git Credential Manager.
  • Uses port 443 — works through most corporate firewalls and proxies.
  • Easiest to start with.

Note GitHub does not accept your account password for Git operations over HTTPS — use a token or Git Credential Manager.

11.2 SSH

  • Authenticate with an SSH key pair (private key on your machine, public key registered on GitHub).
  • Uses port 22 (GitHub also supports SSH over port 443 at ssh.github.com).
  • No tokens to enter once configured; keys can be protected with a passphrase.

11.3 Comparison

Aspect HTTPS SSH
Credential PAT / OAuth via credential manager Key pair
Setup effort Low One-time key generation
Firewall friendly Yes (443) Port 22 may be blocked
Credential expiry Tokens may expire Keys don't expire by default
Typical use Corporate networks, beginners Developers, automation on Linux

11.4 Switching protocol

git remote -v
git remote set-url origin git@github.com:ravi/retail-data-platform.git      # to SSH
git remote set-url origin https://github.com/ravi/retail-data-platform.git  # to HTTPS

(Detailed SSH key setup is in Chapter 23.)

Real-time scenarios

Source S12, S40 · Remote created with a README causes a failed first push

If the hosted repo was initialized with a README, the first git push is rejected because histories differ. Either recreate the remote empty, or git pull --rebase origin main (or merge with --allow-unrelated-histories) and push.

Course addition · Choosing a platform for a Microsoft-centric data team

Azure Repos integrates with Azure Boards and Azure Pipelines and supports ADF, Databricks and Fabric; GitHub offers Actions, Advanced Security and Copilot and is also supported by all three. Decide by existing tooling, identity (Entra ID), compliance and licensing — both work with this course.

Best practices

Course addition · best practices
  • Create one organization-owned repository per product; avoid personal-account ownership for team code.
  • Default to private/internal visibility for company data assets.
  • Prefer SSH keys or credential managers over embedding tokens in URLs.
  • Add a README, LICENSE (if public), CODEOWNERS and branch protection on day one.

Chapter 10 Interview Questions

Source S11 · Chapter manual · interview

Interview questions

  1. What is a remote? — A named connection to another Git repository.
  2. Difference between Git and GitHub? — Git is version control; GitHub hosts repositories and collaboration tools.
  3. Difference between fetch and pull? — Fetch downloads updates; pull fetches and integrates.
  4. What is origin? — A conventional default remote name, not a special Git keyword.
  5. Difference between HTTPS and SSH? — Different transport and authentication approaches.
  6. What is a private repository? — A repository with access restricted to authorized identities.
  7. Why should secrets never be committed? — History can retain them even after a later deletion.

Beginner
What is a remote repository?

A version of the project hosted elsewhere (server or another folder) that you fetch from and push to; origin is the default name after cloning.

Name four Git hosting platforms.

GitHub, Azure Repos (Azure DevOps), GitLab, Bitbucket.

Intermediate
When would you choose SSH over HTTPS?

For frequent developer access without credential prompts, when port 22 (or ssh.github.com:443) is allowed and keys are managed; HTTPS with a credential manager is simpler behind proxies.

What is the difference between private and internal visibility on GitHub?

Private: only explicitly granted users/teams. Internal (GitHub Enterprise): visible to all members of the enterprise, not the public.

Scenario
A contractor says "Repository not found" although the URL is correct. What do you check?

Their access (team membership/collaborator invite accepted), SSO authorization of their PAT/SSH key, that they use the organization repo URL, and cached credentials of another account.
