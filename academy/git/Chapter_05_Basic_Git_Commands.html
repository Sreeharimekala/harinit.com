5.2

git init — initialize a repository

Source S06 · Chapter manual · 1. git init — initialize a repository

git init creates the Git metadata needed to manage version history in a directory. It does not automatically add files or create a commit.

Syntax and examples

# Initialize the current folder
git init

# Create a new directory and initialize it
git init CustomerETL

# Initialize with a chosen initial branch name
git init -b main CustomerETL

After initialization, Git creates a .git directory (or Git directory reference in certain setups). Your project files remain in the working directory.

Verify the repository

git status
git rev-parse --show-toplevel
git rev-parse --git-dir
Use git init when starting version control for an existing local project. Use git clone when you need to create a local copy of an existing repository.
5.3

git status — inspect repository state

Source S06 · Chapter manual · 2. git status — inspect repository state

git status is one of the most frequently used Git commands. It reports the current branch and summarizes staged changes, unstaged changes, and untracked files.

git status
git status --short
git status --branch

Understanding common status output

Status categoryMeaningExample next step
Untracked filesFiles Git has not started tracking.git add new_file.sql
Changes not staged for commitTracked files have working-tree changes not yet staged.git add changed_file.sql
Changes to be committedChanges are in the index and ready to commit.git commit
Working tree cleanNo detected changes relative to the index and current commit.Continue working or switch tasks.

git status --short gives compact status codes. For example, ?? means untracked; M indicates modification. In the two-column format, the first column describes the index and the second the working tree.

5.4

git add — stage changes

Source S06 · Chapter manual · 3. git add — stage changes

git add copies the current content of selected paths into the staging area (index). It stages the content as it exists when the command runs; if you edit the file again afterward, the new edit is not automatically staged.

# Stage one file
git add README.md

# Stage selected files
git add sql/load_customers.sql python/validate_data.py

# Stage changes under the current directory
git add .

# Stage all additions, modifications, and deletions in the working tree
git add -A

# Stage modifications and deletions of tracked files
git add -u

Stage only part of a file

git add -p

Interactive patch mode lets you choose individual change sections (hunks) to stage. This is useful when one file contains multiple unrelated edits.

After staging, run git status and git diff --staged to verify exactly what will be included in the next commit.
5.5

git commit — save a snapshot in local history

Source S06 · Chapter manual · 4. git commit — save a snapshot in local history

A commit records the content in the staging area as a new snapshot in the current branch's history. It includes metadata such as the commit message, author/committer information, timestamps, and parent commit reference(s).

# Commit staged changes with a message
git commit -m "Add customer extraction query"

# Open the configured editor to write a longer message
git commit

# Include staged and tracked-file modifications in one step
git commit -am "Update customer validation logic"
Important about -a: git commit -am automatically stages modifications and deletions of files already tracked. It does not include brand-new untracked files. Use git add first for new files.

Commit-message recommendations

  • Describe the change, not just the file name.
  • Use a short, specific imperative message, such as Add null check to customer load.
  • Avoid vague messages such as changes, update, or final.
5.6

git log — view commit history

Source S06 · Chapter manual · 5. git log — view commit history

git log displays the commit history reachable from the current commit. It normally shows the commit ID, author, date, and message.

# Full commit history
git log

# Compact one-line history
git log --oneline

# Show branches and graph
git log --oneline --graph --decorate --all

# Show the latest five commits
git log -5

# Show commits affecting a particular file
git log -- sql/load_customers.sql

# Show commit history with file change summary
git log --stat

Use q to exit the pager when Git opens history in a terminal viewer.

5.7

git diff — compare changes

Source S06 · Chapter manual · 6. git diff — compare changes

git diff shows differences between versions of files. It is essential for reviewing changes before staging or committing.

CommandComparison
git diffWorking tree vs staging area (unstaged changes).
git diff --stagedStaging area vs current commit (staged changes).
git diff HEADWorking tree and index combined vs current commit.
git diff commitA commitBCompare two commits.
git diff -- file.sqlLimit the comparison to a particular path.

Reading a diff

diff --git a/sql/load_customers.sql b/sql/load_customers.sql
--- a/sql/load_customers.sql
+++ b/sql/load_customers.sql
@@
- WHERE IsActive = 0
+ WHERE IsActive = 1
  • Lines beginning with - are removed from the old version.
  • Lines beginning with + are added in the new version.
  • Context lines are shown to help locate the change.
5.8

git show — inspect a commit or Git object

Source S06 · Chapter manual · 7. git show — inspect a commit or Git object

git show displays details about a Git object. When used with no argument, it usually shows the latest commit and its patch.

# Show latest commit and its changes
git show

# Show a particular commit
git show a1b2c3d

# Show only the summary/statistics
git show --stat

# Show a file as it existed in a commit
git show a1b2c3d:sql/load_customers.sql

Commit IDs in examples are illustrative. Use an ID shown by git log --oneline.

git log vs git show

git loggit show
Primarily used to browse a sequence of commits.Primarily used to inspect one commit or object in detail.
Useful for understanding project history.Useful for reviewing what a particular commit changed.
5.9

git rm — remove tracked files

Source S06 · Chapter manual · 8. git rm — remove tracked files

git rm removes paths from the working tree and stages their removal from the index. The removal becomes part of history when you commit it.

# Remove a tracked file from working tree and stage deletion
git rm old_report.sql

# Remove a tracked directory recursively
git rm -r archive/

# Remove from Git tracking but keep the local file
git rm --cached local_config.json

Use git rm --cached when a file should no longer be tracked but you want to retain your local copy. Add an appropriate .gitignore rule if it should remain untracked in future.

If a file has unstaged modifications, Git may refuse to remove it to protect your work. Inspect the changes first. Do not force removal unless you deliberately intend to discard them.

Alternative: delete manually

You can delete a file using File Explorer or del/rm; Git will detect the deletion. Then stage it with git add -A or use git rm directly.

5.10

git mv — move or rename tracked files

Source S06 · Chapter manual · 9. git mv — move or rename tracked files

git mv moves or renames a tracked path in the working tree and updates the index to reflect the operation.

# Rename a file
git mv old_name.sql customer_load.sql

# Move a file into another directory
git mv customer_load.sql sql/customer_load.sql

# Review and commit the change
git status
git commit -m "Rename customer load script"

Git does not store a separate permanent “rename object”. Rename detection is inferred when Git compares snapshots, based on file content similarity.

You can also rename a file using your operating system, then stage the deletion and addition with git add -A.

5.11

git restore — restore working-tree or staged content

Source S06 · Chapter manual · 10. git restore — restore working-tree or staged content

git restore restores paths to a chosen source. The default source for a working-tree restore is the index; with --staged, the default source is HEAD.

CommandEffect
git restore file.sqlReplace working-tree content with the staged version. Unstaged edits to that file are discarded.
git restore --staged file.sqlUnstage the file, keeping its working-tree content.
git restore --source=HEAD file.sqlRestore the working-tree file from the current commit.
git restore --source=HEAD --staged --worktree file.sqlRestore both index and working tree from the current commit.

Example: unstage without losing edits

git add sql/load_customers.sql
git status

# Remove the staged version from the index
git restore --staged sql/load_customers.sql

# The edit remains in the working directory
git status
Potential data loss: git restore file.sql can overwrite unstaged changes in that file. If you need those edits, copy them elsewhere or stage/commit/stash them before restoring.
5.12

git clean — remove untracked files

Source S06 · Chapter manual · 11. git clean — remove untracked files

git clean removes untracked files from the working tree. It is useful for removing temporary outputs or generated files, but it can permanently delete work that Git has never recorded.

# Preview files that would be removed (dry run)
git clean -n

# Preview untracked files and directories
git clean -nd

# Remove untracked files
git clean -f

# Remove untracked files and directories
git clean -fd

# Include ignored files in the preview
git clean -ndx
High-risk command: Always run git clean -n or git clean -nd first. The -f flag confirms deletion; -d includes untracked directories; -x also includes ignored files. Avoid git clean -fdx unless you have carefully reviewed what will be deleted.

Git clean does not remove files that are tracked by Git. It targets untracked paths (and, with -x, ignored untracked paths).

5.13

git reset — move HEAD and optionally reset index/work tree

Source S06 · Chapter manual · 12. git reset — move HEAD and optionally reset index/work tree

git reset is used to move the current branch reference (and therefore HEAD when on a branch) to another commit. Depending on the mode, it can also update the staging area and working tree.

Three important modes

ModeBranch / HEADStaging areaWorking tree
--softMoves to target commitPreservedPreserved
--mixed (default)Moves to target commitReset to target commitPreserved
--hardMoves to target commitReset to target commitReset to target commit; tracked local changes can be discarded

Common examples

# Unstage a file while keeping working-tree edits
git reset HEAD -- sql/load_customers.sql

# Undo the latest commit but keep its changes staged
git reset --soft HEAD~1

# Undo the latest commit and unstage its changes (keep files edited)
git reset HEAD~1
# Equivalent explicit mode:
git reset --mixed HEAD~1

# Move branch and reset index and tracked working files
git reset --hard HEAD~1
Important: git reset --hard can discard tracked working-tree and staged changes. Resetting a branch that has already been shared can also rewrite the branch history from your perspective and cause collaboration problems. Coordinate with your team before changing shared history.

git reset vs git restore

git resetgit restore
Can move the current branch tip and reset the index; its effects depend on mode.Restores file content in the working tree and/or index; it does not move the branch tip.
Often used to undo commits locally or unstage changes.Often used to discard unstaged edits or unstage selected files.

For a beginner, prefer git restore --staged file for a straightforward unstage operation. Learn reset modes carefully before using them to alter commit history.

5.15

git init

Source S40 · 1. git init

Purpose

Creates a new, empty Git repository (the .git directory).

Syntax and options

git init [directory]
git init -b <branch-name>     # set initial branch
git init --bare               # bare repository (servers)
git init -q                   # quiet

Example

mkdir demo && cd demo
git init -b main

Notes

  • Running git init again in an existing repo is safe (it re-initialises without deleting history).
  • Use git clone instead when the repository already exists on a server.

git status

Source S40 · 2. git status

Purpose

Shows the state of the working directory and staging area: current branch, staged changes, unstaged changes, untracked files, and how your branch compares with its upstream.

Syntax and options

git add

Source S40 · 3. git add

Purpose

Adds changes from the working directory to the staging area.

Syntax and options

git add <file>          # single file
git add <file1> <file2> # several files
git add sql/            # whole folder

git add -A              # all changes in the whole repository (new, modified, deleted)

git add -n .            # dry run — show what would be added

git add -p responses

Key Action
y Stage this hunk
n Don't stage

e Edit hunk manually
q Quit

git status -s

5.18

git commit

Source S40 · 4. git commit

Purpose

Saves the staged snapshot permanently in the local repository with a message.

Syntax and options

git commit -m "Message"                 # single-line message
git commit -m "Subject" -m "Body text"  # subject + body
git commit                               # open editor for message
git commit -a -m "Message"              # stage all tracked modified files and commit
git commit --amend                       # modify the last commit
git commit --amend --no-edit             # add staged changes to last commit, keep message
git commit --allow-empty -m "Trigger CI" # commit with no changes
git commit -v                            # show diff in editor while writing message

Example

git commit -m "Add usp_load_customers procedure"

[main 3f2a7d1] Add usp_load_customers procedure
 1 file changed, 6 insertions(+)
 create mode 100644 sql/procedures/usp_load_customers.sql

Note -a does not include new (untracked) files — you must git add them first.

5.19

git log

Source S40 · 5. git log

Purpose

Shows the commit history.

Syntax and options

git log                                 # full history
git log --oneline                       # one line per commit
git log --oneline --graph --decorate --all   # visual graph of all branches
git log -n 5                            # last 5 commits
git log --stat                          # files changed per commit
git log -p                              # full diff per commit
git log --author="Ravi"                 # filter by author
git log --since="2026-11-01" --until="2026-11-26"

5.20

git diff

Source S40 · 6. git diff

Purpose

Shows differences between versions of files.

Syntax and options

git diff                         # working directory vs staging area (unstaged changes)
git diff --staged                # staging area vs last commit (same as --cached)
git diff HEAD                    # working directory vs last commit (all changes)
git diff <commit1> <commit2>     # between two commits
git diff main feature/orders     # between branch tips
git diff main...feature/orders   # changes on feature since it branched from main
git diff -- <path>               # limit to a file/folder
git diff --stat                  # summary only
git diff --name-only             # file names only
git diff --word-diff             # word-level changes
git diff --check                 # detect whitespace errors / conflict markers

Example

diff --git a/sql/procedures/usp_load_customers.sql b/sql/procedures/usp_load_customers.sql
index 1d4e2a0..7b8c9d1 100644
--- a/sql/procedures/usp_load_customers.sql
+++ b/sql/procedures/usp_load_customers.sql
@@ -2,5 +2,6 @@ CREATE PROCEDURE usp_load_customers
 AS
 BEGIN
-    SELECT * FROM customers;
+    SELECT * FROM customers
+    WHERE status = 'ACTIVE';
 END;

Lines starting with - were removed, + were added; @@ shows line positions.

5.22

git rm

Source S40 · 8. git rm

Purpose

Removes files from the working directory and stages the removal, or stops tracking files.

Syntax and options

git rm <file>             # delete file and stage deletion
git rm -r <folder>        # recursive
git rm --cached <file>    # stop tracking, keep file on disk
git rm -f <file>          # force (file has staged changes)
git rm -n <file>          # dry run

Examples

git rm sql/views/vw_old.sql
git commit -m "Remove obsolete vw_old"

# Accidentally committed a local settings file:
git rm --cached config/local.settings.json
echo "config/local.settings.json" >> .gitignore
git commit -m "Stop tracking local settings"

Note If you delete a file with the operating system (rm or Explorer), Git shows it as deleted; run git add <file> or git rm <file> to stage the deletion.

5.23

git mv

Source S40 · 9. git mv

Purpose

Moves or renames a tracked file and stages the change.

Syntax

git mv <old-path> <new-path>

Example

git mv sql/load.sql sql/procedures/usp_load_customers.sql
git status

Changes to be committed:
        renamed:    sql/load.sql -> sql/procedures/usp_load_customers.sql

Notes

  • git mv a b = mv a b + git rm a + git add b.
  • Git detects renames by content similarity (default 50%), so renaming with the OS and then git add -A also works.
  • Use git log --follow <file> to see history across renames.
5.24

git restore

Source S40 · 10. git restore

Purpose

Restores files in the working directory or staging area (introduced in Git 2.23 to replace the file-related uses of git checkout).

Syntax and options

git restore <file>                       # discard unstaged changes (working dir ← index)
git restore --staged <file>              # unstage (index ← HEAD), keep edits
git restore --staged --worktree <file>   # unstage and discard
git restore --source=<commit> <file>     # restore file content from a commit
git restore .                            # discard all unstaged changes
git restore -p <file>                    # interactively discard hunks

Examples

# Discard edits you don't want
git restore python/etl/transform.py

# Unstage a file added by mistake
git restore --staged sql/views/vw_test.sql

# Get the version from 3 commits ago
git restore --source=HEAD~3 sql/procedures/usp_load_customers.sql

Warning git restore <file> permanently discards uncommitted edits to that file.

5.25

git clean

Source S40 · 11. git clean

Purpose

Deletes untracked files from the working directory.

Syntax and options

git clean -n         # dry run — show what would be deleted (ALWAYS run first)
git clean -f         # delete untracked files
git clean -fd        # delete untracked files and directories
git clean -fx        # also delete ignored files
git clean -fdx       # everything untracked + ignored (e.g. reset build outputs)
git clean -i         # interactive mode

Example

git clean -n
# Would remove temp_output.csv
# Would remove scratch.sql
git clean -f

Warning Cleaned files are not in Git, so they cannot be recovered with Git.

5.26

git reset

Source S40 · 12. git reset

Purpose

Moves the current branch to a different commit and/or resets the staging area. (Full coverage in Chapter 18.)

Syntax and modes

git reset <file>              # unstage a file (same as git restore --staged)
git reset                     # unstage everything
git reset --soft  <commit>    # move branch; keep changes staged
git reset --mixed <commit>    # (default) move branch; keep changes unstaged
git reset --hard  <commit>    # move branch; discard all changes

Examples

git reset --soft HEAD~1       # undo last commit, keep it staged
git reset HEAD~1              # undo last commit, keep changes unstaged
git reset --hard HEAD~1       # undo last commit and delete its changes
git reset --hard origin/main  # make local branch identical to remote

Warning Avoid reset on commits already pushed to shared branches — use git revert instead.

Added topics, conflicts & verification

Source conflict — What does `git clean` remove?

S41 says git clean "removes ignored files". S06/S40 say it removes untracked files. Resolution (git-clean docs): by default it removes untracked, non-ignored files; ignored files are removed only with -x (both) or -X (only ignored). Always dry-run with -n.

Range syntax and rename detection from the cheat sheet (S39)

S39 lists git log --stat -M (show renames) and the ../... range notation. A..B = commits reachable from B but not A (used by log) — note that for git diff the meaning of .. and ... differs, as explained above.

⌨️

Command reference

git add
Syntax
git add <pathspec>…
git add -p
git add -A | git add .
Purpose
Copy the current content of files into the index.
Key parameters
  • -p / --patch — choose hunks interactively
  • -A / --all — stage new, modified and deleted files in the whole tree
  • . — stage changes under the current directory (includes deletions since Git 2.0)
  • -u — stage modified and deleted tracked files only
  • -n — dry run
Behaviour
Stages a snapshot of the file as it is now; later edits need another git add.
Example
git add sql/source/tables/dbo.Customer.sql

Common mistakes
git add . at the root picks up secrets or large data files — always review git status first and maintain .gitignore.
git commit
Syntax
git commit [-m <msg>] [-a] [--amend]
Purpose
Record the staged snapshot as a new commit.
Key parameters
  • -m — message (repeat -m for extra paragraphs)
  • -a — stage modified/deleted tracked files automatically (not new files)
  • --amend — replace the last commit (Chapter 6)
  • -v — show the diff in the editor
Expected output
[main 5c2e9ab] Add source table dbo.Customer (RDP-101)
 1 file changed, 14 insertions(+)
 create mode 100644 sql/source/tables/dbo.Customer.sql
Example

Common mistakes
Expecting -a to include new files; committing unrelated changes together.
git log
Syntax
git log [--oneline] [--graph] [--decorate] [--all] [-p] [--stat] [-n <N>] [--author=<p>] [--since=<date>] [-- <path>]
Purpose
Show commit history.
Expected output
* 5c2e9ab (HEAD -> main) Add source table dbo.Customer (RDP-101)
* 1f0d3c7 Initialize repository structure
Example
git log --oneline --graph --decorate --all

git log --follow -- python/ingestion/src/retail_ingest/extract_orders.py
Common mistakes
Forgetting -- before a path that looks like a branch name.
git diff
Syntax
git diff [--staged|--cached] [<commit> [<commit>]] [-- <path>]
Purpose
Show line-level differences between areas or commits.
Key parameters
  • --staged — index vs HEAD (what will be committed)
  • --stat — summary per file
  • --name-only — file names only
  • -w — ignore whitespace
  • --check — warn about whitespace errors and conflict markers
  • A..B / A...B — between two commits / since the merge base (S39)
Example
git diff
git diff --staged
git diff main...feature/RDP-102-orders-ingest --stat
Common mistakes
Running git diff after staging everything and concluding "no changes" — use --staged.
git rm / git mv
Syntax
git rm <file>
git rm --cached <file>
git mv <old> <new>
Purpose
Delete a tracked file, stop tracking a file but keep it on disk, or rename/move a file.
Expected output
rm 'config/local.settings.json'
Example
git rm --cached config/local.settings.json
echo "config/local.settings.json" >> .gitignore
git mv sql/warehouse/dim_cust.sql sql/warehouse/dim_customer.sql
Common mistakes
Thinking git rm --cached removes the file from history — it only stops tracking from the next commit; secrets need history rewriting (Chapter 23).
git restore / git clean
Syntax
git restore <file>
git restore --staged <file>
git restore --source=<commit> <file>
git clean -n | -f [-d] [-x]
Purpose
Discard working-tree changes, unstage files, restore an old version; remove untracked files.
Key parameters
  • -n — dry run (always first)
  • -f — actually delete
  • -d — include untracked directories
  • -x — also remove ignored files
  • -X — remove only ignored files
Expected output
Would remove tmp/orders_sample.csv
Would remove python/ingestion/.pytest_cache/
Example
git restore --staged sql/tests/test_customer.sql
git restore python/ingestion/src/retail_ingest/extract_orders.py
git clean -nd
git clean -fd
Common mistakes
git restore <file> and git clean -f permanently discard uncommitted work — there is no undo.

Best practices

Course addition · best practices
  • git status → git diff → git add → git diff --staged → git commit.
  • Stage deliberately; avoid blind git add . in large repos.
  • Use git clean -n before -f, always.
  • Use git log -- <path> and git log --follow to investigate a single file.
  • Prefer git switch/git restore over the overloaded git checkout (Git 2.23+).

Chapter 5 Interview Questions

Source S06 · Chapter manual · interview

1. What does git init do?

It initializes Git repository metadata in a directory. It does not automatically stage files or create a commit.

2. What information does git status provide?

It reports the current branch and summarizes untracked, modified, staged, and clean file states.

3. What is the purpose of git add?

It stages selected file content in the index for the next commit.

4. Does git add commit the file?

No. It stages the content. A separate git commit records the staged snapshot in history.

5. What is the difference between git commit and git push?

git commit records a commit locally. git push sends commits to a remote repository.

6. What is the difference between git diff and git diff --staged?

git diff compares working-tree changes with the index. git diff --staged compares staged content with the current commit.

7. What is the difference between git log and git show?

git log browses commit history; git show inspects a specific commit or object, usually including its patch.

8. What does git rm do?

It removes a tracked path from the working tree and stages the deletion. git rm --cached removes it from tracking but keeps the local file.

9. Does Git store a rename as a special object?

No. Rename detection is inferred when comparing snapshots, commonly based on content similarity.

10. How do you unstage a file but keep its edits?

Use git restore --staged filename.

11. What is the purpose of git clean?

It removes untracked files and, with -d, untracked directories. Use -n to preview first.

12. What is the difference between git reset --soft and --mixed?

Both move the current branch tip. Soft preserves the index and working tree; mixed resets the index but preserves working-tree files.

13. What does git reset --hard do?

It moves the current branch tip and resets the index and tracked working tree to the target commit, potentially discarding local changes.

14. What is the difference between git reset and git restore?

Reset can move the branch tip and reset the index; restore updates file content in the index and/or working tree without moving the branch tip.

15. How do you get help for a Git command?

Use git help command or git command -h.

Source S40 · 16. Chapter 5 – Interview Questions
No. Question Short answer
1 Difference between git add . and git add -A? . = current directory down; -A = entire repository (in Git 2.x both include deletions)
2 Difference between git diff and git diff --staged? Unstaged changes vs staged changes
3 How do you unstage a file? git restore --staged <file> (or git reset <file>)
4 How do you stop tracking a file but keep it? git rm --cached <file> + add to .gitignore
5 What does git commit -a do? Stages modified/deleted tracked files and commits (not new files)
6 How do you see the history of one file? git log --follow -- <file>
7 How do you remove untracked files safely? git clean -n first, then git clean -f
8 git restore vs git reset? restore works on files; reset moves the branch pointer (or unstages)
Beginner
What is the difference between git add . and git add -A?

Since Git 2.0 both stage new, modified and deleted files; git add . is limited to the current directory and below, -A covers the entire working tree.

How do you see what will be committed?

git diff --staged (or --cached).

Intermediate
How do you stop tracking a file without deleting it locally?

git rm --cached <file>, add it to .gitignore, commit.

What does git clean -fdx do?

Deletes untracked files and directories, including ignored ones. Run git clean -ndx first.

Advanced
Difference between git diff A..B and git diff A...B?

A..B compares the two tips directly; A...B compares B with the merge base of A and B — the changes introduced on B's side (what a pull request shows).

Scenario
You staged three files but want to commit only one. How?

git restore --staged <other files> (or git commit <file> -m ... which commits only that path's current content), then commit.
