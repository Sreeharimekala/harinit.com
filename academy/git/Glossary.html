Version control basics

TermMeaningLearn it in
Centralized VCSA model where one server holds the history (SVN, TFVC); commits need the server.Chapter 1
Distributed VCSA model where every clone holds the full history (Git, Mercurial); commits are local.Chapter 1
GitA free, open-source distributed version-control system created by Linus Torvalds in 2005.Chapter 2
GitHub / Azure Repos / GitLabHosting platforms for Git repositories that add pull requests, issues and CI/CD.Chapter 2
SCMSource code management, or the broader software configuration management discipline.Chapter 1
Version control (VCS)A system that records changes to files over time so you can review history, compare versions and restore earlier states.Chapter 1

Repository and commits

TermMeaningLearn it in
.gitattributesPer-path settings such as line endings, binary handling and LFS filters.Chapter 24
.gitignorePatterns for untracked files Git should ignore.Chapter 24
AmendReplace the last commit with a new one (git commit --amend); only for unpushed commits.Chapter 6
Bare repositoryA repository without a working tree, used as a shared server copy.Chapter 4
CommitA snapshot of the project with author, committer, message and parent(s), identified by a hash.Chapter 6
Commit ID / SHAThe hash that uniquely identifies an object (SHA-1 by default; SHA-256 optional).Chapter 6
Git LFSLarge File Storage — keeps big binaries outside the normal object store using pointer files.Chapter 24

Working treeThe files you see and edit on disk.Chapter 4

Branching and merging

TermMeaningLearn it in
BranchA movable pointer (ref) to a commit; new commits advance the current branch.Chapter 7
Branch protection / rulesetServer rules requiring PRs, reviews and checks on important branches.Chapter 9
Detached HEADHEAD points directly to a commit instead of a branch.Chapter 7
Fast-forward mergeThe target branch pointer simply moves forward; no merge commit.Chapter 8
Git FlowA branching model with long-lived main and develop plus feature, release and hotfix branches.Chapter 9
GitHub FlowA simple model: short-lived branches from main, merged via pull requests.Chapter 9
HEADA reference to the current position — usually the checked-out branch.Chapter 7
Merge baseThe most recent common ancestor of two branches.Chapter 8
Merge conflictOverlapping changes Git cannot combine automatically; resolved manually.Chapter 8
Squash mergeCombine all changes of a branch into one new commit.Chapter 8
Three-way mergeA merge using the merge base and both tips, usually creating a merge commit.Chapter 8
Trunk-based developmentSmall changes integrated into the trunk at least daily with strong CI.Chapter 9
