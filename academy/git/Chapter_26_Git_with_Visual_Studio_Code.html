Learning objectives

Chapter introduction

What it is. Using Git through Visual Studio Code: the Source Control view, staging, committing, branches, merging, conflict resolution in the merge editor, push/pull/sync, GitHub integration (sign-in, PRs and issues extension) and multi-repository workspaces.

Why it matters. Most data engineers write SQL, Python and YAML in VS Code; doing Git in the same window shortens the loop — as long as you know which Git command each button runs.

Where it is used. Daily development on Windows, macOS and Linux; remote development in containers/WSL/Codespaces.

In this course's project. The same Stage 2–4 tasks are repeated in VS Code: Asha stages hunks of a SQL file, resolves an ADF JSON conflict in the 3-way merge editor and opens a PR with the GitHub Pull Requests extension.

Source S40 · earlier complete course

This chapter shows how to perform every common Git task inside Visual Studio Code — the most popular editor for SQL, Python and Data Engineering work.

Learning objective By the end of this chapter, you should be able to use VS Code for staging, committing, branching, merging, resolving conflicts, syncing with GitHub and managing multiple repositories.

26.18

Staging Files

Source S40 · 5. Staging Files
  • Hover a file in Changes → click + (Stage Changes).
  • Stage all → + on the Changes header.
  • Partial staging: open the diff, select lines → right-click → Stage Selected Ranges (equivalent to git add -p).
  • Unstage with − in Staged Changes.
  • Discard with ↶ (careful — irreversible for uncommitted edits).
26.19

Committing Changes

Source S40 · 6. Committing Changes
  1. Type a message (first line = subject; use Shift+Enter for new lines in the body).
  2. Click Commit or press Ctrl+Enter.
  3. If nothing is staged, VS Code asks whether to stage all changes and commit (configure git.enableSmartCommit).
  4. Amend: Commit ▾ → Commit (Amend).
  5. Commit & Push / Commit & Sync for one-click publishing.
  6. Undo Last Commit: … → Commit → Undo Last Commit (soft reset).

(Copilot can generate a commit message suggestion — review it before committing.)

26.20

Branch Creation

Source S40 · 7. Branch Creation
  • Click the branch name in the status bar → + Create new branch… → enter feature/DE-1600-dim-store.
  • Or Ctrl+Shift+P → Git: Create Branch… / Git: Create Branch From… (choose base like origin/main).
  • New branch is checked out automatically.
  • Publish Branch (cloud icon in status bar or Source Control) pushes it with upstream.
26.21

Branch Switching

Source S40 · 8. Branch Switching
  • Click the branch name in the status bar → choose a local branch, or a remote branch (origin/...) to create a tracking branch.
  • Ctrl+Shift+P → Git: Checkout to….
  • If you have uncommitted changes that conflict, VS Code offers Stash & Checkout or Migrate Changes.
26.22

Merging Branches

Source S40 · 9. Merging Branches
  1. Check out the target branch (e.g. main).
  2. Ctrl+Shift+P → Git: Merge… (or … → Branch → Merge) → choose the source branch.
  3. Also available: Git: Rebase Branch…, Git: Delete Branch….
  4. View results in the Source Control Graph.

Note In team repositories, merge into main via pull requests (section 12), not locally.

26.23

Resolving Conflicts

Source S40 · 10. Resolving Conflicts

When a merge/pull/rebase conflicts:

  1. Conflicted files appear under Merge Changes with a !/C marker.
  2. Open the file — VS Code highlights conflicts with CodeLens actions:
Accept Current Change | Accept Incoming Change | Accept Both Changes | Compare Changes
<<<<<<< HEAD (Current Change)
    WHERE is_active = 1
=======
    WHERE status IN ('ACTIVE','VIP')
>>>>>>> feature/vip-customers (Incoming Change)
  1. Or click Resolve in Merge Editor — a 3-way view: Incoming (left), Current (right), Result (bottom). Tick checkboxes or edit the result directly.
  2. Save the file → + (stage) → Complete Merge / commit (or Continue for rebase).
  3. To abort: Ctrl+Shift+P → Git: Abort Merge (or terminal git merge --abort).

Configure VS Code as Git's merge tool for CLI use:

git config --global merge.tool vscode
git config --global mergetool.vscode.cmd 'code --wait --merge $REMOTE $LOCAL $BASE $MERGED'

26.25

GitHub Integration

Source S40 · 12. GitHub Integration
  • Accounts icon (bottom-left) → sign in with GitHub (used for clone, publish, PRs).
  • GitHub Pull Requests extension:
    • View PRs and issues in a sidebar.
    • Create Pull Request from the current branch (title, description, reviewers, labels, draft).
    • Check out PRs locally, review diffs, add comments and suggestions, approve, request changes, merge.
    • Start working on an issue → creates a linked branch.
  • Publish to GitHub from an unpublished repository.
  • Open on GitHub / Copy GitHub permalink from the editor context menu.
  • GitLens: inline blame, commit details on hover, file/line history, compare branches.
  • GitHub Codespaces / vscode.dev: press . on a GitHub repository to open it in the browser editor.
26.26

Working with Multiple Repositories

Source S40 · 13. Working with Multiple Repositories
  • Multi-root workspace: File → Add Folder to Workspace… for each repo (e.g. retail-data-platform, shared-sql-library) → File → Save Workspace As data-platform.code-workspace.
  • The Source Control view lists each repository separately with its own changes, branch and sync controls (toggle with Source Control Repositories view).
  • Repositories in sub-folders are detected automatically (git.autoRepositoryDetection, git.repositoryScanMaxDepth).
  • Each status bar branch indicator applies to the active editor's repository.
  • Use Git: Fetch From All Remotes to update all.
  • Git submodules and worktrees also appear as separate repositories.

Command reference

Useful VS Code settings and commands
Syntax
Ctrl+Shift+G (⌃⇧G on macOS) — Source Control view
Ctrl+Shift+P → "Git: Clone", "Git: Create Branch…", "Git: Merge Branch…", "Git: Stash"
Purpose
Reach Git features quickly and configure behaviour.
Example
// settings.json
{
  "git.autofetch": true,
  "git.confirmSync": true,
  "git.pruneOnFetch": true,
  "git.enableSmartCommit": false,
  "git.mergeEditor": true,
  "diffEditor.ignoreTrimWhitespace": false
}
Common mistakes
Enabling smart commit (commit all changes when nothing is staged) and committing unintended files.
VS Code as Git editor and diff/merge tool
Syntax
git config --global core.editor "code --wait"
git config --global merge.tool vscode
git config --global mergetool.vscode.cmd "code --wait --merge $REMOTE $LOCAL $BASE $MERGED"
git config --global diff.tool vscode
git config --global difftool.vscode.cmd "code --wait --diff $LOCAL $REMOTE"
Purpose
Use VS Code for commit messages, interactive rebase todo lists, diffs and merges from the CLI.
Example
git mergetool
git difftool HEAD~1 -- sql/warehouse/usp_load_dim_customer.sql
Common mistakes
Missing --wait — Git continues before you edit.

Continuous project — Stage 7: CI/CD

Continuous project · Stage 2–4 in VS Code
  1. Clone: Command Palette → Git: Clone → paste git@github.com:retail-data/enterprise-retail-data-platform.git → open.
  2. Branch: click branch name in status bar → Create new branch… → feature/RDP-121-dim-store.
  3. Edit & stage hunks: edit sql/warehouse/usp_load_dim_store.sql; in the diff view select lines → right-click → Stage Selected Ranges.
  4. Commit: message feat(sql): add dim_store load (RDP-121) → ✓ Commit.
  5. Publish: Publish Branch (runs git push -u origin feature/RDP-121-dim-store).
  6. Conflict: Git: Merge Branch… → main; adf/pipeline/pl_ingest_orders.json conflicts → open Merge Editor → accept both activity changes carefully → validate JSON → Complete Merge → Commit.
  7. PR: GitHub Pull Requests extension → Create Pull Request → reviewers retail-data/sql-team → link Closes #48.
  8. Verify in terminal: git log --oneline --graph -5 (the integrated terminal shows exactly what the UI did).

Real-time scenarios

Source S27, S40 · "Sync" pushed commits the developer didn't want to publish

Sync = pull then push. Enable git.confirmSync, check Outgoing commits in the Source Control graph before syncing, and use Pull alone when you only want updates.

Course addition · Multi-root workspace with the platform repo and a shared library repo

Add both folders to a workspace; the Source Control view lists each repository separately with its own branch and changes — commit and push them independently.

Best practices

Course addition · best practices
  • Learn the CLI equivalent of each button; check the Git output log (View → Output → Git) when unsure.
  • Keep smart commit off; stage deliberately.
  • Use the merge editor and validate JSON/YAML after resolving.
  • Use the GitHub PR extension to review with full IDE context.
  • Use code --wait as Git editor for rebase and commit messages.

Chapter 26 Interview Questions

Source S27 · Chapter manual · interview

1. Does VS Code replace Git?

No. It provides an IDE interface; Git performs the version-control operations.

2. What does staging mean?

Selecting changes for the next commit.

3. Does commit push changes?

No. Commit is local; push publishes to a remote.

4. Fetch vs pull?

Fetch downloads updates; pull integrates them.

5. Can a workspace contain multiple repositories?

Yes, through a multi-root workspace.

3 How do you resolve conflicts in VS Code? CodeLens accept options or the 3-way Merge Editor

Beginner
How do you stage only part of a file in VS Code?

Open the diff, select lines and choose "Stage Selected Ranges".

What does the Sync button do?

Pulls changes from the upstream branch and pushes local commits.

Intermediate
How do you resolve a merge conflict in VS Code?

Open the conflicted file in the merge editor, choose incoming/current/both or edit the result, then Complete Merge and commit.

Scenario
A colleague says "VS Code lost my changes after Discard". Can you recover them?

Discard runs git restore; uncommitted changes are not in Git. VS Code's local history (Timeline view) may still have earlier saved versions — check there.
