4.1

What is a Git repository?

Source S05 · Chapter manual · 1. What is a Git repository?

A Git repository (often called a repo) is a project directory that Git manages. It contains the project files and Git's metadata, including the history of commits, branches, tags, and configuration.

Git can record how tracked files change over time. You can inspect earlier versions, compare changes, create branches, and collaborate with others.

Important distinction: A normal folder becomes a Git repository after you initialize it with git init or obtain an existing repository by cloning it with git clone.

Example project

sales-data-pipeline/
├── sql/
│   └── load_customers.sql
├── python/
│   └── validate_data.py
├── README.md
└── requirements.txt

After Git initialization, Git creates a hidden .git directory inside the project. The visible project files remain your working files; Git metadata is stored separately.

4.2

What is a working directory?

Source S05 · Chapter manual · 2. What is a working directory?

The working directory (also called working tree) is the checked-out project content that you see and edit using an editor, IDE, or file explorer.

  • Create, edit, rename, and delete files here.
  • Changes made here are not automatically committed.
  • Git compares tracked working files with the index and the latest commit to identify changes.

Example

Suppose you open sql/load_customers.sql and add a filter to exclude inactive customers. That edit first exists in your working directory. Git can detect it, but it is not yet staged or committed.

Remember: Saving a file in VS Code or another editor does not save it to Git history. You must stage and commit it.
4.3

What is a staging area?

Source S05 · Chapter manual · 3. What is a staging area?

The staging area, technically called the index, is where you prepare the exact set of changes for your next commit. Use git add to place changes into this area.

Staging lets you choose which changes belong together in a commit. You do not have to commit every modification in your working directory at once.

# Stage one file
git add sql/load_customers.sql

# Stage several named files
git add README.md requirements.txt

# Stage all changes under the current directory
git add .

# Review what is staged and unstaged
git status

Why is staging useful?

  • Group related changes into a meaningful commit.
  • Keep incomplete or unrelated work out of a commit.
  • Review the exact content that will be committed using git diff --staged.
Good practice: Review staged changes before committing: git diff --staged.
4.4

What is a local repository?

Source S05 · Chapter manual · 4. What is a local repository?

The local repository is the Git database on your computer. It stores committed project snapshots and related history. The data is maintained under the repository's .git directory.

When you run git commit, Git records the staged snapshot as a new commit in your local repository. A commit normally includes a unique object ID, author and committer information, timestamp, message, and a reference to its parent commit or commits.

git add sql/load_customers.sql
git commit -m "Add active customer filter"

You can create commits while offline. A commit is local until you share it with a remote repository, for example by running git push.

4.5

What is a remote repository?

Source S05 · Chapter manual · 5. What is a remote repository?

A remote repository is another copy of a Git repository hosted elsewhere, commonly on a service such as GitHub, GitLab, Bitbucket, or Azure Repos. It may also be hosted on an organization's own server.

Remote repositories help teams share commits, review code, back up work, and coordinate development.

CommandPurpose
git remote -vList configured remote names and URLs.
git remote add origin <url>Add a remote named origin.
git fetch originDownload remote objects and update remote-tracking references without integrating them into the current branch.
git pullFetch and then integrate changes into the current branch (usually by merge or rebase, depending on configuration/options).
git pushSend local commits to a remote branch, subject to permissions and server rules.
Key point: Git itself is distributed. Your local repository has its own history; it is not merely a live window into GitHub or Azure Repos.
4.6

Understanding the .git directory

Source S05 · Chapter manual · 6. Understanding the .git directory

When you initialize a normal repository, Git creates a hidden directory named .git. This directory contains the repository's internal database and configuration. Do not manually edit or delete its contents unless you understand the consequences.

Common items inside .git

ItemPurpose
HEADIdentifies the current checkout, commonly by referring to the current branch.
configRepository-specific configuration, including remote definitions.
objects/Stores Git objects such as blobs, trees, commits, and annotated tags.
refs/Stores references such as local branches and tags (some references may be packed).
indexStores the staging area's index data.
logs/Stores reference logs (reflogs), which record local reference movements when enabled.
hooks/Contains sample or configured hook scripts that can run at specific Git events.
info/Contains additional repository information, such as the local exclude file.

Exact contents can vary by Git version, repository format, configuration, and whether the repository is bare or uses a worktree.

Inspect the repository metadata

# Show hidden files (PowerShell)
Get-ChildItem -Force

# Show hidden files (Git Bash / Linux / macOS)
ls -la

# Ask Git for the repository's Git directory
git rev-parse --git-dir

# Show the repository's top-level working directory
git rev-parse --show-toplevel
Do not remove .git: deleting it from a normal project folder removes that folder's Git metadata and local history. The visible files may remain, but the folder is no longer a normal Git working repository.
4.7

Initializing a repository

Source S05 · Chapter manual · 7. Initializing a repository

git init creates the Git metadata required to start tracking a project in the current directory. It does not automatically add files or create a commit.

Initialize in the current folder

cd C:\Projects\sales-data-pipeline
git init

Create and initialize a new folder

mkdir sales-data-pipeline
cd sales-data-pipeline
git init

Git typically names the initial branch master or main, depending on your Git configuration and version. You can set the default for future repositories:

git config --global init.defaultBranch main

To rename the current branch after initialization:

git branch -M main

Verify initialization

git status
git rev-parse --show-toplevel
git rev-parse --git-dir
4.8

Creating your first Git repository

Source S05 · Chapter manual · 8. Creating your first Git repository

Let's create a small Data Engineering project and make its first commit.

Step 1 — Create the project folder

mkdir CustomerETL
cd CustomerETL

Step 2 — Initialize Git

git init
git branch -M main

Step 3 — Create project files

Create the following files using VS Code, Notepad, or PowerShell:

README.md
sql/load_customers.sql
python/validate_customers.py

PowerShell example:

New-Item -ItemType Directory -Force sql, python
Set-Content README.md "# Customer ETL Project"
Set-Content sql/load_customers.sql "SELECT * FROM dbo.Customers;"
Set-Content python/validate_customers.py "print('Validate customer data')"

Step 4 — Check Git status

git status

The new files should appear under Untracked files. Git sees them in the working directory but is not tracking them yet.

Step 5 — Stage the files

git add README.md sql/load_customers.sql python/validate_customers.py
git status

The files should now appear under Changes to be committed.

Step 6 — Review the staged changes

git diff --staged

Step 7 — Create the first commit

git commit -m "Initial commit: create customer ETL project"

Step 8 — Verify the commit

git log --oneline
git status
Expected result: You have a local Git repository with one commit. Your working tree should report that it is clean, provided no additional changes were made.

4.10

Tracking files in Git

Source S05 · Chapter manual · 10. Tracking files in Git

Git does not automatically track every file in a folder. You explicitly add files to the index using git add. After a file has been included in a commit, Git can detect and report later modifications to it.

File states you should know

StateMeaningTypical next action
UntrackedFile exists in the working directory but is not yet tracked by Git.git add filename
UnmodifiedTracked file matches the version in the current commit.Edit it when needed.
ModifiedTracked file has working-directory changes not yet staged.git add filename
StagedChanges are recorded in the index and are ready for the next commit.git commit

Track a new file

git status
git add README.md
git status
git commit -m "Add project README"

Track all suitable changes

# Stage changes under the current directory
git add .

# Stage tracked modifications and deletions
git add -u

# Stage all changes (including untracked files)
git add -A

Be aware of your current directory when using git add .. From the repository root, it stages changes throughout the project. Review git status before committing.

Stop tracking a file but keep it on disk

git rm --cached filename

This stages removal of the file from Git's tracked snapshot while leaving your local copy in place. Commit the change to record it in history.

Ignore files using .gitignore

A .gitignore file tells Git which untracked files or paths to ignore. It is commonly used for temporary files, build outputs, local configuration, and secrets.

# Example .gitignore
*.log
__pycache__/
.venv/
.env
.vscode/
Security: Adding a file to .gitignore does not remove it from Git if it is already tracked. Never commit passwords, access tokens, connection strings, or private keys. If a secret was committed, removing it in a later commit does not erase it from earlier history; rotate the secret and follow your organization's history-cleanup process.

Useful commands for tracking and inspection

CommandWhat it tells you
git statusCurrent branch and staged, unstaged, and untracked changes.
git diffDifferences in the working tree that are not staged.
git diff --stagedDifferences staged for the next commit.
git ls-filesFiles currently in Git's index (tracked paths).
git check-ignore -v pathShows which ignore rule matches a path, if any.
git log --onelineCompact commit history.

End-to-end Git workflow: how the components work together

Source S05 · Chapter manual · End-to-end Git workflow: how the components work together
Working directory
Edit files
→ git add
Staging area
Select changes
→ git commit
Local repository
Save commit history
→ git push
Remote repository
Share commits

Typical daily sequence:

# 1. Inspect current state
git status

# 2. Edit files in your working directory

# 3. Review unstaged changes
git diff

# 4. Stage selected files
git add sql/load_customers.sql

# 5. Review staged changes
git diff --staged

# 6. Commit to local history
git commit -m "Improve customer load query"

# 7. Share commits (after configuring a remote and branch)
git push

The final push step requires a configured remote and suitable permissions. For a newly created remote repository, follow the hosting service's instructions for connecting it to your local repository.

How this applies to Data Engineering

  • SQL: Stage and commit stored procedures, views, table scripts, and data-quality queries.
  • Python/PySpark: Track ETL scripts, validation logic, reusable libraries, and tests.
  • ADF: Track exported pipeline and linked-service definitions where your team's deployment approach supports source control. Protect environment-specific settings and secrets.
  • Databricks/Fabric: Track notebooks, SQL scripts, configuration templates, and deployment assets using the supported source-control workflow for the workspace.

What is a Git Repository?

Source S40 · 1. What is a Git Repository?

1.1 Definition

A Git repository is a storage location that contains your project files plus the complete history of every change made to them. It consists of:

  1. The project files (your working directory), and
  2. A hidden .git directory that stores all commits, branches, tags and configuration.

1.2 Types of repositories

Type Description Example
Local repository On your computer C:\Projects\retail-data-platform
Remote repository Hosted on a server https://github.com/ravi/retail-data-platform
Bare repository Only history, no working files (used on servers) git init --bare project.git

1.3 Two ways to get a repository

git init                 # turn an existing folder into a new repository
git clone <url>          # copy an existing repository from a remote

Key point If you delete the .git folder, the project files remain but all history, branches and configuration are lost — it becomes a normal folder again.

4.13

What is a Working Directory?

Source S40 · 2. What is a Working Directory?

2.1 Definition

The working directory (also called the working tree) is the set of project files you see in your file explorer and edit in your IDE. It reflects one checked-out version of the project (usually the latest commit of the current branch) plus any edits you've made.

2.2 Characteristics

  • Files here can be untracked, unmodified, or modified.
  • Changes in the working directory are not saved in Git until you stage and commit them.
  • Switching branches updates the working directory to match the other branch.

2.3 Example

echo "SELECT * FROM customers;" > sql/views/vw_customers.sql
git status

Untracked files:
  sql/views/vw_customers.sql

The file exists in the working directory but Git is not tracking it yet.

4.14

What is a Staging Area?

Source S40 · 3. What is a Staging Area?

3.1 Definition

The staging area (also called the index or cache) is an intermediate area where you prepare the exact set of changes that will go into the next commit. It is stored in the file .git/index.

3.2 Why a staging area exists

You may have changed five files, but only three belong to one logical change. The staging area lets you commit those three now and the other two separately, producing clean, reviewable history.

3.3 Example

# You changed a SQL procedure and a Python script for two different tickets
git add sql/procedures/usp_load_customers.sql
git commit -m "fix(sql): exclude test customers"     # only the SQL change

git add python/etl/transform.py
git commit -m "feat(etl): add currency conversion"   # Python change separately

You can even stage part of a file:

git add -p python/etl/transform.py

3.4 Commands related to staging

Command Effect
git add <file> Add changes to the staging area
git restore --staged <file> Remove from staging (keep edits)
git diff --staged Show what is staged
git status Show staged ("Changes to be committed") vs unstaged
4.15

What is a Local Repository?

Source S40 · 4. What is a Local Repository?

4.1 Definition

The local repository is the .git directory on your machine that permanently stores committed snapshots and the project history. When you run git commit, the staged content is saved here.

4.2 Characteristics

  • Contains every commit, branch and tag you have locally.
  • Fully functional offline — you can commit, branch, merge and view history without a network.
  • Private to you until you push.

4.3 Example

git commit -m "Add customer view"
git log --oneline
# 3f2a7d1 Add customer view
4.16

What is a Remote Repository?

Source S40 · 5. What is a Remote Repository?

5.1 Definition

A remote repository is a version of the repository hosted on a server (GitHub, GitLab, Bitbucket, Azure Repos or a company server) that the team uses to share work.

5.2 Characteristics

  • Usually a bare repository (no working files).
  • Named in your local repo, typically origin.
  • You push commits to it and fetch/pull commits from it.
  • Access-controlled (permissions, branch protection).

5.3 Summary of all four areas

Working Directory ──add──► Staging Area ──commit──► Local Repository ──push──► Remote Repository
        ▲                                                  ▲                          │
        └───────── restore/switch ─────────────────────────┘◄──────── fetch/pull ─────┘
Area Stored where Saved by Shared?
Working directory Project folder Editor (Save) No
Staging area .git/index git add No
Local repository .git/objects, .git/refs git commit No
Remote repository Server git push Yes
4.17

Understanding .git Directory

Source S40 · 6. Understanding .git Directory

6.1 Structure

.git/
├── HEAD             # points to the current branch, e.g. "ref: refs/heads/main"
├── config           # repository-level (local) configuration
├── description      # used only by GitWeb
├── index            # the staging area (binary file)
├── hooks/           # sample scripts run on events (pre-commit, commit-msg, pre-push...)
├── info/
│   └── exclude      # local-only ignore patterns (not shared)
├── objects/         # all content: blobs, trees, commits, tags
│   ├── 3f/2a7d1...  # loose objects (first 2 chars = folder)
│   ├── info/
│   └── pack/        # packfiles (compressed objects)
├── refs/
│   ├── heads/       # local branches (one file per branch)
│   ├── remotes/     # remote-tracking branches (origin/main)
│   └── tags/        # tags
├── logs/            # reflog: history of where HEAD and branches pointed
├── ORIG_HEAD        # previous HEAD before reset/merge/rebase (when present)
├── FETCH_HEAD       # what was last fetched (when present)
└── packed-refs      # many refs packed into one file (when present)

6.2 Explore it

ls -la .git
cat .git/HEAD
cat .git/config
ls .git/refs/heads

Warning Do not edit files inside .git manually, and never store a repository inside OneDrive/Dropbox sync folders — sync tools can corrupt .git.

Initializing a Repository

Source S40 · 7. Initializing a Repository

7.1 git init

git init                    # in the current folder
git init my-project         # creates a new folder and initialises it
git init -b main            # specify initial branch name
git init --bare repo.git    # bare repository for server use

Output:

Initialized empty Git repository in C:/Projects/retail-data-platform/.git/

7.2 What git init does

  • Creates the .git directory and its sub-folders.
  • Sets HEAD to point to the default branch (main).
  • Does not track any files yet; no commits exist.

Note Never run git init inside a folder that is already part of a repository (nested repositories cause confusion). Check with git status first.

4.21

Tracking Files in Git

Source S40 · 10. Tracking Files in Git

10.1 Tracked vs untracked

  • Tracked files are files Git knows about (they were in the last commit or are staged).
  • Untracked files are new files Git has not been told to track.
  • Ignored files match .gitignore and are never shown as untracked.

10.2 Commands

git status                     # see untracked / modified / staged
git add sql/views/vw_customers.sql   # start tracking
git ls-files                   # list all tracked files
git ls-files --others --exclude-standard   # list untracked (not ignored)
git rm --cached secret.env     # stop tracking but keep file
git check-ignore -v app.log    # see why a file is ignored

10.3 Lifecycle example

touch sql/views/vw_sales.sql
git status -s        # ?? sql/views/vw_sales.sql   (untracked)
git add sql/views/vw_sales.sql
git status -s        # A  sql/views/vw_sales.sql   (added/staged)
git commit -m "Add vw_sales"
echo "SELECT 1;" > sql/views/vw_sales.sql
git status -s        #  M sql/views/vw_sales.sql   (modified, unstaged)

Command reference

git init
Syntax
git init [<directory>] [-b <branch>] [--bare]
Purpose
Create a new, empty repository (creates .git).
Key parameters
  • -b main / --initial-branch=main — name of the first branch
  • --bare — repository without working tree (server/shared use)
  • <directory> — create the folder if it does not exist
Expected output
Initialized empty Git repository in /home/priya/work/enterprise-retail-data-platform/.git/
Example
git init -b main enterprise-retail-data-platform
cd enterprise-retail-data-platform
Common mistakes
Running git init in your home directory or in a parent folder — every file below becomes part of one huge repository.
Troubleshooting
Find the repository root with git rev-parse --show-toplevel; remove an accidental .git folder only after checking it is not a real repository.
git status
Syntax
git status [-s | --short] [-b] [--ignored]
Purpose
Show the branch, staged changes, unstaged changes and untracked files.
Expected output
On branch main
No commits yet
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        README.md
        sql/
nothing added to commit but untracked files present (use "git add" to track)
Example
git status
git status -sb      # short form:  ?? untracked,  A added,  M modified,  first column = staged, second = unstaged
Common mistakes
Assuming an empty folder will be committed — Git tracks files, not directories. Add a .gitkeep or README to keep a folder.
git init --bare
Syntax
git init --bare <name>.git
Purpose
Create a server-style repository used only as a push/fetch target.
Behaviour
No working tree; the repository files are at the top level of the folder. Hosting services keep bare repositories internally.
Example
git init --bare /srv/git/retail-platform.git
git remote add origin /srv/git/retail-platform.git
Common mistakes
Pushing to the checked-out branch of a non-bare repository — Git refuses (receive.denyCurrentBranch).

cat .git/HEAD                # ref: refs/heads/main

Empty folders without files are not recorded; they will appear when files are added in Stage 2. .gitignore/.gitattributes are added in Chapter 24 (and a first version in Chapter 5).

Chapter 4 Interview Questions

Source S05 · Chapter manual · interview

1. What is a Git repository?

A project managed by Git, containing working files and Git metadata that records commits, references, and configuration.

2. What is the working directory?

The checked-out project files where a developer creates and edits content.

3. What is the staging area?

The index that holds the selected content for the next commit.

4. What is the difference between staging and committing?

Staging selects changes for the next commit; committing records the staged snapshot in local repository history.

5. What is the difference between a local and remote repository?

A local repository is stored on your machine. A remote repository is another repository hosted elsewhere for sharing and collaboration.

6. What is the purpose of the .git directory?

It stores Git's object database, references, index, configuration, logs, and other repository metadata.

7. Does git init track all files automatically?

No. It initializes repository metadata. Files must be added to the index with git add before they can be included in commits.

8. What is the difference between git add . and git add -A?

git add . stages changes under the current directory; git add -A stages additions, modifications, and deletions across the working tree.

9. How can you check whether a file is tracked?

Use git ls-files to list tracked paths, or inspect git status for a specific file's state.

10. What happens if you delete the .git directory?

The directory loses its normal Git repository metadata and local history. The working files may remain, but Git no longer recognizes that folder as the same repository.

11. Can you commit without an internet connection?

Yes. Git commits are created locally. Internet access is generally needed only when communicating with a remote host.

12. What is a bare repository?

A repository without a checked-out working tree, often used as a shared central repository on a server.

13. How do you unstage a file without discarding its changes?

Use git restore --staged filename.

14. Does .gitignore affect files already tracked?

No. Ignore rules normally apply to untracked files. A tracked file remains tracked until it is removed from the index.

15. Which command shows the root folder of the current repository?

git rev-parse --show-toplevel.

Beginner
What does git init create?

A .git directory containing the object database, refs, HEAD, config and other metadata — an empty repository.

What is the staging area?

The index: the list of file versions that will form the next commit.

Intermediate
What is a bare repository and when is it used?

A repository without a working tree, used as a central push/fetch target on servers.

What does git status -s output MM file.sql mean?

The file has staged changes (first M) and further unstaged changes (second M).

Advanced
Why can't Git commit an empty directory?

Trees store entries for files (blobs) and sub-trees that contain files; a directory with no files produces no tree entry. Use a placeholder file.

Scenario
A new team member cloned the repo but git status shows hundreds of modified SQL files without edits. What do you check?

Line-ending normalization (core.autocrlf, .gitattributes), file mode changes (core.fileMode), and whether an editor reformatted files; git diff --stat and git diff -w help confirm.
