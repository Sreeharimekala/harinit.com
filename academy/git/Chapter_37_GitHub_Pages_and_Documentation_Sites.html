Learning objectives

Chapter introduction

What it is. GitHub Pages hosts static websites (HTML, CSS, JavaScript) directly from a GitHub repository — either from a branch/folder or through a GitHub Actions workflow — optionally built with the Jekyll static site generator and served on a custom domain with HTTPS.

Why it matters. Data teams need living documentation: architecture, data dictionaries, runbooks, onboarding guides. Publishing them from the same repository keeps docs versioned and reviewed like code.

Where it is used. Project documentation sites, user/organization profile sites (<user>.github.io), course sites, generated documentation (MkDocs, Sphinx, dbt docs) deployed by Actions.

Why a bonus chapter. This module is not in the 36-chapter syllabus. It comes from the third-party guide in your folder (S38, Chapter 9) and the optional module listed in the earlier consolidated guide (S01, Appendix A). Every platform detail was checked against GitHub Docs in November 2026.

In this course's project. Stage 8 extra: the platform's docs/ folder (architecture, runbooks, data dictionary) is published as an internal documentation site via a Pages workflow.

37.1

What the source guide teaches (S38, Chapter 9) — summarized and updated

Source S38 · What the source guide teaches (S38, Chapter 9) — summarized and updated

S38 walks through four steps: (1) setting up Pages by creating a repository, adding an index.html and enabling Pages in Settings; (2) customizing with Jekyll — install Jekyll, run jekyll new ., preview with bundle exec jekyll serve, then commit and push; (3) using a custom domain — add a CNAME file containing the domain and create DNS A records pointing to GitHub's IP addresses; (4) updating the site by committing and pushing changes. It ends with a cheat sheet of the commands used. The consolidated guide (S01, Appendix A) lists Pages as an optional bonus covering purpose, publishing sources, Jekyll and custom domains.

What changed or needs care today: publishing can also use GitHub Actions (where CNAME files are ignored); the custom domain should be added in Settings → Pages before DNS; www subdomains need a CNAME record, not A records; domains should be verified; and the IPv6 AAAA records are now documented. The sections below teach the current behaviour.

🔎

Added topics, conflicts & verification

Source conflict — Custom domain set-up steps

S38 says to add a CNAME file to the repository and then configure A records. Resolution (verified with GitHub Docs, Nov 2026): add the domain in Settings → Pages first. Branch publishing then commits the CNAME file for you; Actions publishing does not use CNAME files at all. Apex domains use A/AAAA (or ALIAS/ANAME) records and www uses a CNAME record. Verify the domain to prevent takeover.

Command reference

Publish from a branch
Syntax
Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: main → Folder: / (root) or /docs → Save
Purpose
Serve the files of a branch folder as a website.
Expected output
Your site is live at https://<user>.github.io/<repository>/
Example
mkdir -p docs && printf '<!DOCTYPE html>\n<html><head><meta charset="utf-8"><title>Retail Data Platform Docs</title></head>\n<body><h1>Retail Data Platform</h1><p>Architecture, runbooks, data dictionary.</p></body></html>\n' > docs/index.html
git add docs/index.html
git commit -m "docs: add documentation site home page"
git push
Common mistakes
Publishing from a branch with a _config.yml you didn't intend — Jekyll processing ignores files/folders starting with _; add an empty .nojekyll file for plain HTML sites that need underscore folders.
Jekyll locally
Syntax
gem install bundler jekyll
jekyll new <dir>
bundle exec jekyll serve
Purpose
Create and preview a Jekyll site before pushing.
Expected output
Server address: http://127.0.0.1:4000/
  Server running... press ctrl-c to stop.
Example
cd docs
jekyll new --skip-bundle .
bundle install
bundle exec jekyll serve
Common mistakes
Using plugins not supported by GitHub's built-in Jekyll build — use an Actions workflow for custom plugins.
Custom Actions workflow (.github/workflows/pages.yml)
Syntax
permissions pages: write + id-token: write · environment github-pages · actions/configure-pages · actions/upload-pages-artifact · actions/deploy-pages
Purpose
Build documentation with any tool and deploy it to Pages.
Example
name: docs-site
on:
  push:
    branches: [main]
    paths: ["docs/**"]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: false
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/configure-pages@v6
      - uses: actions/setup-python@v7
        with:
          python-version: "3.12"
      - run: pip install mkdocs && mkdocs build --config-file docs/mkdocs.yml --site-dir _site
      - uses: actions/upload-pages-artifact@v5
        with:
          path: _site
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v5
Common mistakes
Forgetting pages: write and id-token: write, or not switching Settings → Pages → Source to "GitHub Actions".

Continuous project — Stage 8: Enterprise governance

Continuous project · Stage 8 (bonus) — Publish the platform documentation

  2. Add .github/workflows/pages.yml (above) through a PR; CODEOWNERS for docs/ = tech writers + leads.

Real-time scenarios

Source S38, S01 · Site shows 404 after enabling Pages

Causes: no index.html/index.md at the published folder root, wrong folder selected (/docs vs /), the first deployment still running (check the Actions tab), or a project site URL missing the repository path (/<repo>/). Fix the source setting or file location and re-run.

Course addition · Custom domain keeps disappearing

With a custom Actions workflow GitHub ignores CNAME files — set the domain in Settings → Pages. With branch publishing, a build that overwrites the branch (e.g. a generator) can delete the CNAME file; keep it in the source folder that is published.

Best practices

Course addition · best practices
  • Keep docs next to code; review docs changes in PRs like code.
  • Prefer the Actions source for generated sites; use paths filters and concurrency.
  • Add the domain in Settings before DNS; verify domains; enforce HTTPS; avoid wildcard DNS.
  • Use private Pages (Enterprise Cloud) for internal documentation; never publish secrets or internal data on public sites.
  • Pin action major versions and let Dependabot update them.

Common errors & troubleshooting

Course addition · error reference
Symptom / message Cause Fix
404 "There isn't a GitHub Pages site here." Wrong source/folder, no index file, deployment not finished Check Settings → Pages and Actions run
Error: Get Pages site failed (configure-pages) Pages not enabled / source not set to GitHub Actions Enable Pages with Actions source
Error: HttpError: Resource not accessible by integration (deploy) Missing pages: write/id-token: write Add permissions
"Domain's DNS record could not be retrieved" / "Improperly configured" DNS not propagated or wrong records Fix A/AAAA/CNAME records; wait for propagation

Chapter 37 Interview Questions

Beginner
What is GitHub Pages?

A static-site hosting service that publishes HTML/CSS/JS from a GitHub repository, optionally built with Jekyll or a custom Actions workflow.

What is the URL of a project site?

https://<user-or-org>.github.io/<repository>/ (user/organization sites use https://<user-or-org>.github.io/).

Intermediate
Branch publishing vs Actions publishing?

Branch publishing serves a branch folder (with automatic Jekyll); Actions publishing builds with any tool and deploys an artifact via deploy-pages, with the domain configured in Settings.

Which DNS records do you need for an apex domain?

A records to 185.199.108.153–111.153 (optionally AAAA 2606:50c0:8000–8003::153) or an ALIAS/ANAME to <user>.github.io; www uses a CNAME to <user>.github.io.

Scenario
The team wants internal docs from the platform repo that only employees can read. How?

GitHub Enterprise Cloud with private Pages visibility, Actions workflow building docs/, CODEOWNERS review for docs, optional verified custom domain with HTTPS.

Summary & completion checklist

Key takeaways
  • Pages publishes static sites from a branch folder or an Actions workflow.
  • Jekyll runs automatically for branch publishing; Actions allows any generator.
  • Custom domains: Settings first, then A/AAAA (apex) or CNAME (subdomain), verify and enforce HTTPS.
  • Treat documentation as code: PRs, CODEOWNERS, automated deployment.
