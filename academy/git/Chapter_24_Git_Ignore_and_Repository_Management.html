Learning objectives

Chapter introduction

What it is. Controlling what enters the repository and how it is stored: .gitignore (patterns, global ignores, untracking), .gitattributes (line endings, diff/merge drivers, binary handling), large files and Git LFS, submodules, repository size management and cleanup.

Why it matters. Data projects are full of things that must not be committed — virtual environments, data extracts, Parquet/CSV samples, PBIX files, credentials — and of files that need special handling (SQL with CRLF, notebooks, binaries).

Where it is used. Every repository, from day one; CI checks for size and forbidden files.

In this course's project. Stage 8: the platform repository gets a complete .gitignore and .gitattributes, LFS for a few required binaries, and a cleanup of an accidentally committed 300 MB CSV.

24.1

What is .gitignore?

Source S25 · Chapter manual · 1. What is .gitignore?

A .gitignore file tells Git which untracked paths to intentionally leave out of normal status and add operations. Ignore rules do not affect files already tracked. Multiple ignore files can apply at different directory levels.

Commands and practical example

# Example .gitignore
.env
*.log
__pycache__/
build/
dist/
24.2

Creating .gitignore

Source S25 · Chapter manual · 2. Creating .gitignore

Create a root .gitignore for shared project rules. Keep generated files, local configuration and editor-specific artifacts out of version control when they are not part of the project deliverable.

Commands and practical example

touch .gitignore
printf "*.log\n.env\n__pycache__/\n" >> .gitignore
git status --short
24.3

Ignore specific files

Source S25 · Chapter manual · 3. Ignore specific files

A literal path can ignore a particular file relative to the .gitignore location. Anchor it with a leading slash when it should match only at that directory level.

Commands and practical example

# Ignore a root-level local config
/local.settings.json
# Ignore a nested file relative to this .gitignore
config/dev-only.json
24.4

Ignore folders

Source S25 · Chapter manual · 4. Ignore folders

A directory pattern such as logs/ ignores matching directories and their contents. Use root anchoring when the rule should apply only to a top-level folder.

Commands and practical example

logs/
/build/
/temp-output/
24.5

Wildcard patterns

Source S25 · Chapter manual · 5. Wildcard patterns

Ignore patterns support *, ?, character ranges and recursive matching with **. A leading ! negates an earlier pattern, but parent directory exclusions can prevent re-inclusion. Test patterns with check-ignore.

Commands and practical example

*.tmp
data/**/*.parquet
!important.tmp
git check-ignore -v path/to/file
24.6

Global Git ignore

Source S25 · Chapter manual · 6. Global Git ignore

A global excludes file is useful for machine-specific files such as editor settings and OS metadata that should not be imposed on every project. Shared build outputs belong in the repository's .gitignore.

Commands and practical example

git config --global core.excludesfile ~/.config/git/ignore
git config --show-origin --get core.excludesfile
24.7

Ignoring already tracked files

Source S25 · Chapter manual · 7. Ignoring already tracked files

Adding a tracked file to .gitignore does not untrack it. Use git rm --cached to remove it from the index while keeping the working copy, then commit the index change. Verify the path carefully.

Commands and practical example

echo "local.settings.json" >> .gitignore
git rm --cached local.settings.json
git add .gitignore
git commit -m "Stop tracking local settings"
24.8

gitattributes

Source S25 · Chapter manual · 8. .gitattributes

A .gitattributes file assigns path-specific attributes. It can control text normalization, diff and merge behavior, export rules and filters. It is commonly used to standardize line endings and identify binary files.

Commands and practical example

# Example .gitattributes
* text=auto
*.sql text eol=lf
*.bat text eol=crlf
*.png binary
*.parquet binary
24.9

Line-ending management

Source S25 · Chapter manual · 9. Line-ending management

Windows commonly uses CRLF while Linux/macOS tools commonly use LF. Configure normalization consistently with .gitattributes and set core.autocrlf according to team policy. Avoid noisy whole-file diffs caused by inconsistent endings.

Commands and practical example

git config --show-origin --get core.autocrlf
git config --global core.autocrlf true
git check-attr text eol -- scripts/deploy.sh
24.10

Binary files

Source S25 · Chapter manual · 10. Binary files

Binary assets such as images, archives, database extracts and model files often do not diff or merge meaningfully. Mark binary paths in attributes and avoid storing generated binaries unless they are intentionally versioned.

Commands and practical example

*.png binary
*.jpg binary
*.parquet binary
*.zip binary
24.11

Large files in Git

Source S25 · Chapter manual · 11. Large files in Git

Large binaries can make Git history grow quickly because old versions remain in history. Avoid committing generated exports, raw data and build artifacts unless intentionally versioned. Store datasets in systems designed for data storage.

Commands and practical example

git count-objects -v
git rev-list --objects --all
24.12

Git LFS

Source S25 · Chapter manual · 12. Git LFS

Git Large File Storage replaces large file content in Git history with small pointer files and stores actual content in an LFS object store. Consider hosting quotas and bandwidth. LFS is not a substitute for a data lake or artifact repository.

Commands and practical example

git lfs install
git lfs track "*.psd"
git lfs track "*.zip"
git add .gitattributes
git add model-artifact.zip
git lfs ls-files
24.13

Repository size management

Source S25 · Chapter manual · 13. Repository size management

Measure before cleaning. Inspect object counts and large blobs; avoid committing datasets; use LFS for suitable versioned binaries; and store analytical datasets in ADLS, OneLake or approved artifact storage. Removing a file from the latest commit does not remove historical copies.

Commands and practical example

git count-objects -v
git rev-list --objects --all
git gc
git maintenance run
24.14

Repository cleanup

Source S25 · Chapter manual · 14. Repository cleanup

Use git clean only after a dry run; it deletes untracked files and directories. Use git rm for tracked files. Rewriting history to remove large files or secrets is disruptive and should follow an approved procedure with backups and coordination.

Commands and practical example

git clean -nd   # preview
git clean -fd   # destructive
git rm -- path/to/tracked-file
git status

What is .gitignore?

Source S40 · 1. What is .gitignore?

1.1 Definition

.gitignore is a text file listing patterns of files and folders Git should not track. Ignored files don't appear as untracked in git status and are skipped by git add ..

1.2 What to ignore

Category Examples
Secrets .env, *.pem, local.settings.json
Dependencies / environments .venv/, node_modules/
Build outputs dist/, build/, bin/, obj/, *.egg-info/
Caches __pycache__/, .pytest_cache/, .ipynb_checkpoints/
Logs and temp *.log, tmp/
Data files data/, *.csv, *.parquet
IDE / OS files .idea/, .DS_Store, Thumbs.db
Tool state .terraform/, *.tfstate, .databricks/

Note .gitignore only affects untracked files. Files already tracked continue to be tracked (see section 7).

24.19

Wildcard Patterns

Source S40 · 5. Wildcard Patterns
Pattern Matches
* Any characters except / (*.csv → a.csv, x/b.csv)
? Exactly one character (file?.sql → file1.sql)
[abc], [0-9] One character from a set/range
**/ Any number of directories (**/logs → logs, a/b/logs)
/** Everything inside (build/**)
a/**/b a/b, a/x/b, a/x/y/b
!pattern Negate — re-include previously ignored files
# Comment
\#, \! Literal # or !
Leading / Anchored to the .gitignore's directory
Trailing / Directory only

Negation rule: you cannot re-include a file if its parent directory is ignored. Use dir/* instead of dir/ when you need exceptions.

24.20

Global Git Ignore

Source S40 · 6. Global Git Ignore

For files specific to your machine/editor (not the project), use a global ignore file instead of every repository's .gitignore.

git config --global core.excludesFile ~/.gitignore_global

# ~/.gitignore_global
.DS_Store
Thumbs.db
*.swp
.idea/

Ignore precedence (highest first):

  1. Command line patterns
  2. .gitignore in the same directory, then parent directories
  3. .git/info/exclude (per-repo, not shared — personal ignores)
  4. core.excludesFile (global)
24.21

Ignoring Already Tracked Files

Source S40 · 7. Ignoring Already Tracked Files

7.1 Stop tracking (remove from the repository, keep locally)

echo "config/local.json" >> .gitignore
git rm --cached config/local.json
git commit -m "Stop tracking local config"

For a folder:

git rm -r --cached logs/

After pushing, the file is deleted for teammates when they pull (warn them to back it up).

7.2 Re-apply .gitignore to everything

git rm -r --cached .
git add .
git commit -m "Apply .gitignore rules"

7.3 Keep tracking but ignore local changes (temporary)

git update-index --skip-worktree config/settings.json      # ignore my local edits
git update-index --no-skip-worktree config/settings.json   # undo
git ls-files -v | grep ^S                                   # list skip-worktree files

(--assume-unchanged is a performance hint, not intended for this purpose.) Better long-term solution: commit a template (settings.example.json) and ignore the real file.

24.22

.gitattributes

Source S40 · 8. .gitattributes

8.1 Definition

.gitattributes assigns attributes to paths to control how Git handles them: line endings, binary detection, diff drivers, merge strategies, LFS, export behaviour, linguist stats.

8.2 Example

# Normalise all text files
* text=auto

# Force line endings
*.sh    text eol=lf
*.py    text eol=lf
*.yml   text eol=lf
*.sql   text eol=crlf
*.ps1   text eol=crlf
*.bat   text eol=crlf

# Binary files: no line-ending conversion, no textual diff/merge
*.png   binary
*.jpg   binary
*.xlsx  binary
*.pbix  binary
*.dacpac binary

# Custom diff
*.ipynb diff=jupyternotebook

# Merge strategy for generated files
CHANGELOG.md merge=union

# Git LFS
*.pbix  filter=lfs diff=lfs merge=lfs -text

# Exclude from 'git archive'
tests/  export-ignore

# Mark generated/vendored files for GitHub stats & diffs
adf/ARMTemplate*.json linguist-generated=true

Commit .gitattributes at the repository root so the whole team shares it.

24.23

Line-Ending Management

Source S40 · 9. Line-Ending Management

9.1 The problem

OS Line ending
Windows CRLF (\r\n)
Linux/macOS LF (\n)

Mixed endings cause every line to appear changed in diffs, noisy conflicts, and shell scripts failing on Linux (/bin/bash^M: bad interpreter).

9.2 Solutions

1. .gitattributes (repository-wide — recommended): * text=auto normalises text files to LF in the repository and converts on checkout according to platform/eol settings.

2. core.autocrlf (per user):

Setting Behaviour Use on
true LF→CRLF on checkout, CRLF→LF on commit Windows
input CRLF→LF on commit, no conversion on checkout Linux/macOS
false No conversion When .gitattributes handles everything 
git config --global core.autocrlf true     # Windows
git config --global core.autocrlf input    # macOS/Linux

9.3 Fix an existing repository

# after adding .gitattributes
git add --renormalize .
git commit -m "Normalize line endings"

Check endings of tracked files:

git ls-files --eol
24.24

Binary Files

Source S40 · 10. Binary Files

10.1 Characteristics

Images, Excel, Power BI (.pbix), compiled files, archives, DACPACs.

  • Git cannot show meaningful diffs or merge them.
  • Every change stores a full new copy (poor delta compression) → repository growth.

10.2 Handling

  • Mark as binary in .gitattributes.
  • Resolve conflicts by choosing a version: git checkout --ours file.pbix / --theirs.
  • Prefer text-based formats when possible: Power BI PBIP/TMDL instead of .pbix, SQL scripts instead of .bacpac, notebooks as .py source.
  • Store large binaries in Git LFS or external storage.
  • Lock files to avoid parallel edits (LFS locking).
24.25

Large Files in Git

Source S40 · 11. Large Files in Git

11.1 Why large files are a problem

  • Every version stays in history forever → slow clones and fetches.
  • GitHub warns at 50 MB and blocks files over 100 MB; recommended repository size is small (ideally < 1 GB).
  • CI pipelines slow down.

11.2 What not to commit

Datasets (CSV/Parquet extracts), database backups, model artifacts, logs, .zip of builds, videos.

11.3 Alternatives

Asset Better home
Data ADLS Gen2, OneLake, S3, Databricks Volumes
ML models MLflow model registry, Azure ML
Build artifacts GitHub Releases/Packages, Azure Artifacts
Reports/binaries that must be versioned Git LFS
Small test fixtures Git (keep them small)

Prevent accidents: check-added-large-files pre-commit hook; GitHub push limits.

24.26

Git LFS

Source S40 · 12. Git LFS

12.1 Definition

Git Large File Storage (LFS) replaces large files in your repository with small text pointer files, storing the actual content on a separate LFS server (GitHub, Azure Repos, GitLab and Bitbucket all support it).

version https://git-lfs.github.com/spec/v1
oid sha256:4d7a214614ab2935c943f9e0ff69d22eadbb8f32b1258daaa5e2ca24d17e2393
size 52428800

12.2 Setup and usage

git lfs install                         # once per machine
git lfs track "*.pbix"                  # adds rule to .gitattributes
git lfs track "models/**/*.pkl"
git add .gitattributes
git add reports/sales.pbix
git commit -m "Add sales report via LFS"
git push

git lfs ls-files                        # files managed by LFS
git lfs status
git lfs pull                            # download LFS content
git lfs fetch --all
GIT_LFS_SKIP_SMUDGE=1 git clone <url>   # clone without downloading LFS content

12.3 Migrate existing files into LFS

git lfs migrate import --include="*.pbix" --everything    # rewrites history!
git push --force-with-lease --all

12.4 File locking

git lfs track "*.pbix" --lockable
git lfs lock reports/sales.pbix
git lfs locks
git lfs unlock reports/sales.pbix

12.5 Considerations

Storage and bandwidth quotas/costs on hosting platforms; all collaborators and CI need LFS installed (actions/checkout with lfs: true).

Repository Size Management

Source S40 · 13. Repository Size Management

13.1 Measure

git count-objects -vH
du -sh .git
git rev-list --objects --all \
  | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' \
  | awk '$1=="blob"' | sort -k3 -n -r | head -20       # largest blobs in history

GitHub also shows size in Settings and warns on large pushes.

13.2 Reduce for users

Technique Command
Shallow clone git clone --depth 1 <url>
Partial clone git clone --filter=blob:none <url>
Sparse checkout git sparse-checkout init --cone && git sparse-checkout set sql python
Single branch git clone --single-branch -b main <url>

13.3 Reduce the repository itself

Remove large files from history (section 14), move binaries to LFS, split monolithic repositories when appropriate.

24.28

Repository Cleanup

Source S40 · 14. Repository Cleanup

14.1 Local housekeeping

git fetch --prune                             # remove stale remote-tracking branches
git branch --merged main | grep -vE "^\*|main|develop" | xargs -r git branch -d   # delete merged branches
git stash list && git stash clear              # (review first)
git worktree prune
git clean -n && git clean -fd                  # untracked files
git gc                                          # pack & prune

14.2 Remote housekeeping

  • Enable Automatically delete head branches.
  • Delete stale branches (git push origin --delete <branch> or GitHub Branches → Stale).
  • Archive repositories no longer used (Settings → Archive).

14.3 Rewriting history to remove large/unwanted files

pip install git-filter-repo
git clone --mirror <url> rdp-cleanup.git
cd rdp-cleanup.git
git filter-repo --strip-blobs-bigger-than 50M
git filter-repo --path data/ --invert-paths            # remove a folder from history
git push --force --mirror

Then coordinate: everyone re-clones; check that branch protection temporarily allows the force push; run git gc on the server side (handled by the host).

Source conflict — Line endings for SQL scripts: LF or CRLF?

S25 sets *.sql text eol=lf; S40 sets *.sql text eol=crlf for SQL edited in SSMS/Visual Studio on Windows. Resolution: both are valid if made explicit. Recommended default: * text=auto with *.sql text eol=lf; use CRLF only for Windows-only script types (.bat, .cmd, .ps1) or if your SQL tooling demonstrably requires CRLF on disk. What matters is one committed rule plus a one-time git add --renormalize ..

Command reference

.gitignore patterns
Syntax
# comment
*.log            # any .log file at any level
/tmp/            # tmp folder at the repo root only
data/**/*.csv    # csv files anywhere under data/
!data/reference/*.csv   # negation: keep these
.venv/           # a directory named .venv anywhere
Purpose
Tell Git which untracked files to ignore.
Behaviour
A trailing / matches directories only; a leading / anchors to the .gitignore's directory; ** matches across directories; later rules override earlier ones; you cannot re-include a file if its parent directory is excluded.
Example
# Enterprise Retail Data Platform .gitignore (excerpt)
.venv/
__pycache__/
*.py[cod]
.pytest_cache/
.env
local.settings.json
*.log
tmp/
data/raw/
*.parquet
*.pbix
.databricks/
bin/
obj/
Common mistakes
Adding a rule for a file that is already tracked and expecting Git to ignore it.
git check-ignore / git rm --cached
Syntax
git check-ignore -v <path>
git rm -r --cached <path>
git ls-files --others --ignored --exclude-standard
Purpose
Debug which rule ignores a path; stop tracking files while keeping them locally.
Expected output
.gitignore:9:*.log	python/ingestion/logs/run.log
Example
git check-ignore -v python/ingestion/logs/run.log
git rm -r --cached data/raw
git commit -m "chore: stop tracking raw data extracts"
Common mistakes
Running git rm --cached on config other developers need — they lose it on next pull; commit a template instead.
.gitattributes
Syntax
<pattern> <attr> [<attr>…]
Purpose
Per-path settings: text/eol normalization, binary, diff/merge drivers, LFS filters, export-ignore.
Example
* text=auto
*.sql   text eol=lf        # recommended default (see conflict box)
*.bat   text eol=crlf
*.ps1   text eol=crlf
*.py    text eol=lf
*.sh    text eol=lf
*.json  text eol=lf
*.ipynb text eol=lf
*.pbix  binary
*.parquet filter=lfs diff=lfs merge=lfs -text
docs/** export-ignore
Common mistakes
Changing eol rules without renormalizing.
Troubleshooting
After changing attributes: git add --renormalize . and commit separately; check with git ls-files --eol.
Git LFS
Syntax
git lfs install
git lfs track "<pattern>"
git lfs ls-files
git lfs migrate import --include="<pattern>" --everything
Purpose
Store large binaries outside the normal object store; Git keeps small pointer files.
Expected output
Tracking "*.parquet"
Example
git lfs install
git lfs track "tests/fixtures/*.parquet"
git add .gitattributes tests/fixtures/orders_sample.parquet
git commit -m "test: add parquet fixture via LFS"
Common mistakes
Using LFS for data that should not be in Git at all (production extracts); forgetting that LFS storage/bandwidth has quotas; platforms like ADF/Fabric Git integration do not resolve LFS pointers.
Submodules (overview)
Syntax
git submodule add <url> <path>
git clone --recurse-submodules <url>
git submodule update --init --recursive
Purpose
Embed another repository at a fixed commit.
Behaviour
The parent stores the submodule URL in .gitmodules and a commit pointer (gitlink). Updating the submodule requires a commit in the parent.
Example
git submodule add git@github.com:retail-data/shared-sql-utils.git sql/shared
Common mistakes
Forgetting --recurse-submodules — the folder stays empty. Note: Fabric Git integration does not support submodules.

Real-time scenarios

Source S25, S40 · `.env` still shows in `git status` after adding it to .gitignore

It is tracked. git rm --cached .env, commit, and rotate the secrets it contained if it was pushed.

Course addition · Every line of a SQL file shows as changed

Line endings changed (CRLF ↔ LF). Add explicit *.sql text eol=…, renormalize once, and ask everyone to pull.

Best practices

Course addition · best practices
  • Commit .gitignore and .gitattributes in the first commit.
  • Use the global ignore file for OS/IDE clutter, not the project file.
  • Never commit data extracts, secrets, virtual environments or build output.
  • Use LFS sparingly for necessary binaries; prefer artifact stores/lakes for data.
  • Add CI guards for file size and forbidden paths; review git count-objects -vH periodically.

Chapter 24 Interview Questions

Source S25 · Chapter manual · interview

1. What does .gitignore do?

It excludes matching untracked paths from normal Git status/add behavior.

2. Does .gitignore affect tracked files?

No. Already tracked files remain tracked until explicitly removed from the index.

3. How do you ignore all log files?

Add *.log to .gitignore.

4. How do you ignore a directory?

Add its directory pattern, such as logs/.

5. What does ! do in an ignore pattern?

It negates a previous pattern, subject to parent-directory traversal rules.

6. How do you debug an ignore rule?

Use git check-ignore -v path.

7. What is a global ignore file for?

Machine-specific exclusions such as editor and operating-system files.

8. How do you stop tracking a file but keep it locally?

Use git rm --cached file and commit the index change.

9. What is .gitattributes?

A file assigning path-specific attributes such as text normalization and binary handling.

10. Why standardize line endings?

To avoid noisy diffs and inconsistent file content across operating systems.

11. What is Git LFS?

An extension that stores large file content separately while Git tracks pointer files.

12. Should large analytical datasets usually be committed to Git?

Usually not; use data or artifact storage designed for those assets.

13. Does deleting a large file from the latest commit shrink old history?

No. Historical versions remain unless history is rewritten.

14. What does git clean -n do?

It previews untracked files/directories that a clean operation would remove.

15. Why use git clean -f carefully?

It deletes untracked files that Git may not be able to recover.

Beginner
What is .gitignore?

A file listing patterns of untracked files Git should ignore.

Why does Git keep tracking a file I added to .gitignore?

Ignore rules affect only untracked files; untrack it with git rm --cached.

Intermediate
What is .gitattributes used for?

Path-specific behaviour: line-ending normalization, marking binaries, custom diff/merge drivers, LFS filters, export rules.

What problem does Git LFS solve?

Large binary files bloating the repository; LFS stores them on a separate server and keeps pointer files in Git.

Advanced
How do you remove a large file from the entire history?

git filter-repo --path <file> --invert-paths (or git lfs migrate import to move it to LFS), then force-push all refs and have everyone re-clone.

What is a submodule and a common pitfall?

A pointer to another repository at a specific commit; pitfalls are empty folders without --recurse-submodules and forgetting to commit updated pointers.

Scenario
A data engineer wants sample Parquet files for unit tests in the repo. What do you recommend?

Small, synthetic fixtures (KB-sized) committed normally, or LFS if larger; never production extracts; generate data in tests where possible.
