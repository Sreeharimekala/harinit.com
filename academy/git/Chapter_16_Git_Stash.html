Learning objectives

Chapter introduction

What it is. git stash saves uncommitted changes (working tree and index) on a local stack and returns you to a clean state, so you can switch context and later re-apply the work.

Why it matters. Urgent interruptions — a production bug, a reviewer's request — happen while you are mid-change. Stash lets you switch safely without half-baked commits.

Where it is used. Locally only; stashes are never pushed. IDEs expose it as "Stash changes".

16.1

What is Git Stash?

Source S17 · Chapter manual · 1. What is Git Stash?

Git stash temporarily saves selected working-tree changes and returns the working tree to a clean state. It is useful when you need to switch branches or handle urgent work before your current task is ready to commit. A stash is stored locally in the repository; it is not automatically pushed to a remote.

Commands and example

git status
git stash
git stash list
16.2

Why do we need Git Stash?

Source S17 · Chapter manual · 2. Why do we need Git Stash?

Imagine you are modifying a SQL stored procedure on a feature branch and a production defect arrives. You may need to switch to a hotfix branch, but Git will prevent or complicate that switch if your changes would be overwritten. Stashing lets you park the unfinished work, switch context, and restore it later.

Commands and example

# Save current tracked changes
git stash push -m "WIP: optimize customer load"

# Switch to urgent work
git switch hotfix/customer-load

# Return later
git switch feature/customer-load
git stash pop
16.3

Stashing modified files

Source S17 · Chapter manual · 3. Stashing modified files

By default, git stash (equivalent to git stash push) saves tracked modifications in the working tree and index. Untracked files are not included by default. Use -u / --include-untracked to include untracked files. Ignored files require -a / --all; use that carefully because build output and secrets may be included.

Commands and example

git stash push -m "WIP: pipeline validation"
git stash push -u -m "WIP: include new test files"
git stash push -a -m "WIP: include ignored files" # use cautiously
16.4

Stashing staged changes

Source S17 · Chapter manual · 4. Stashing staged changes

Stash normally saves both staged and unstaged tracked changes. The index is restored to the state it had before the stash operation (typically clean). If you want to keep the staged/unstaged distinction when applying, use --index with apply or pop. --keep-index is useful when you want to stash unstaged work but leave the staged changes available for a commit.

Commands and example

git add sql/customer_load.sql
git stash push -m "WIP: staged and unstaged changes"

# Apply and attempt to restore the original index state
git stash apply --index stash@{0}

# Alternative: keep staged changes in place while stashing other work
git stash push --keep-index -m "WIP: unstaged only"
16.5

Viewing stash history

Source S17 · Chapter manual · 5. Viewing stash history

Stashes form a stack. The newest entry is stash@{0}, followed by stash@{1}, and so on. These references can change when entries are added or removed, so inspect the list before selecting one. Use show -p to inspect the patch.

Commands and example

git stash list
git stash show stash@{0}
git stash show -p stash@{0}
git stash show --stat stash@{1}
16.6

Applying vs popping

Source S17 · Chapter manual · 6. Applying vs popping

apply reapplies a stash and keeps the stash entry. pop reapplies it and, if the application succeeds, removes that entry. If a pop results in conflicts, Git normally keeps the stash so you can resolve the conflict and retry or recover manually. Prefer apply when the work is important or you want a safety copy.

Commands and example

git stash apply stash@{1}
git status
# After verifying the restored changes:
git stash drop stash@{1}

# Or apply and remove on success:
git stash pop
16.7

Deleting stash entries

Source S17 · Chapter manual · 7. Deleting stash entries

Use drop to remove one entry and clear to remove every stash entry in the repository. Clearing is destructive and there is no ordinary undo command. Confirm the list and, if necessary, save a patch or create a branch before deleting valuable work.

Commands and example

git stash list
git stash drop stash@{2}
git stash clear
16.8

Creating named stashes and managing many

Source S17 · Chapter manual · 8. Creating named stashes and managing many

Use descriptive messages so the stash list communicates the task and context. Keep stashes small and short-lived. The stash reference is positional, so do not assume an entry remains at index zero after another stash is created.

Commands and example

git stash push -m "WIP: add late-arriving order handling"
git stash push -u -m "WIP: add reconciliation test"
git stash list
git stash show -p stash@{1}
16.9

Stash conflicts

Source S17 · Chapter manual · 9. Stash conflicts

A stash can conflict when the target branch has changed the same lines or files. Git reports unmerged paths. Resolve the files as with a merge conflict, inspect the result, and stage resolved paths if appropriate. An apply conflict does not remove the stash. Avoid running git stash pop repeatedly while a conflict is unresolved.

Commands and example

git stash apply stash@{0}
git status
# Edit conflicted files, remove conflict markers, validate
git add path/to/resolved-file
# Keep or remove the stash after verifying the result
git stash list
16.10

Practical use cases

Source S17 · Chapter manual · 10. Practical use cases

Common uses include switching to a production hotfix, pausing work before a pull/rebase, testing a clean working tree, and moving unfinished changes between branches. A stash is not a substitute for a durable commit or backup: it is local, easy to clear, and not part of normal remote collaboration.

Commands and example

# Pause current work
git stash push -u -m "WIP: ADF schedule validator"

# Handle another branch
git switch main
git pull --ff-only

# Resume
git switch feature/schedule-validator
git stash apply stash@{0}
git status
16.11

What is Git Stash?

Source S40 · 1. What is Git Stash?

1.1 Definition

git stash saves your uncommitted changes (staged and unstaged modifications to tracked files) onto a stack, and reverts your working directory to the last commit (clean state). You can re-apply the saved changes later on the same or a different branch.

1.2 How it's stored

Each stash is stored as a special commit referenced by refs/stash; the list is a stack (stash@{0} is the most recent).

stash@{0}  ← newest
stash@{1}
stash@{2}  ← oldest

16.13

Stashing Modified Files

Source S40 · 3. Stashing Modified Files
git stash                 # stash staged + unstaged changes to tracked files
git stash push            # same (explicit)

What is and isn't stashed by default:

File state Stashed by default? Option to include
Modified tracked files (unstaged) Yes —
Staged changes Yes —
Untracked (new) files No -u / --include-untracked
Ignored files No -a / --all 
git stash -u               # also untracked files
git stash -a               # also ignored files
git stash push -- sql/procedures/usp_load_orders.sql   # only specific paths
git stash push -p          # choose hunks interactively
git stash --keep-index     # stash but keep staged changes in the working directory
16.14

Stashing Staged Changes

Source S40 · 4. Stashing Staged Changes

By default, a stash records both the index (staged) and the working tree. When you re-apply:

git stash apply            # restores changes, but staged changes become unstaged
git stash apply --index    # restores the staged/unstaged split exactly
git stash pop --index

Stash only the staged changes (Git 2.35+):

git stash push --staged -m "only the SQL I staged"
16.15

Viewing Stash History

Source S40 · 5. Viewing Stash History
git stash list

stash@{0}: On feature/orders-incremental: WIP: incremental watermark for orders
stash@{1}: WIP on main: 9c8b7a6 Add fact_sales table

Inspect a stash:

git stash show                 # summary of latest stash
git stash show stash@{1}       # summary of a specific stash
git stash show -p stash@{1}    # full diff
git stash show -u stash@{0}    # include untracked files (Git 2.32+)
16.16

Applying Stashed Changes

Source S40 · 6. Applying Stashed Changes

apply re-applies a stash and keeps it in the stash list.

git stash apply                # latest (stash@{0})
git stash apply stash@{2}      # specific stash
git stash apply --index        # restore staged state too

Use apply when you want to apply the same changes to multiple branches, or keep a safety copy.

16.17

Popping Stashed Changes

Source S40 · 7. Popping Stashed Changes

pop re-applies a stash and removes it from the list (if there was no conflict).

git stash pop
git stash pop stash@{1}
apply pop
Applies changes Yes Yes
Removes stash No Yes (only if successful)
Typical use Reuse / keep backup Normal "resume work"
16.18

Deleting Stash Entries

Source S40 · 8. Deleting Stash Entries
git stash drop                 # delete latest
git stash drop stash@{2}       # delete a specific stash
git stash clear                # delete ALL stashes

Warning git stash clear cannot be undone with normal commands. A dropped stash can sometimes be found with git fsck --unreachable | grep commit and restored with git stash apply <sha>.

16.19

Creating Named Stashes

Source S40 · 9. Creating Named Stashes

Always add a descriptive message — "WIP on main" is meaningless after a few days.

git stash push -m "DE-1423: half-done SCD2 logic"
git stash push -u -m "orders: new staging files not yet committed"

stash@{0}: On feature/DE-1423: DE-1423: half-done SCD2 logic

(git stash save "message" is the older, deprecated syntax.)

16.20

Managing Multiple Stashes

Source S40 · 10. Managing Multiple Stashes
git stash list
git stash show -p stash@{3}            # check content before applying
git stash apply stash@{3}
git stash drop stash@{3}
git stash branch feature/from-stash stash@{1}

git stash branch <name> [stash] creates a new branch from the commit where the stash was created, applies the stash there, and drops it if successful — the cleanest way to turn old stashed work into a real branch without conflicts.

Good practices:

  • Keep the stash list short — turn long-lived work into commits on a branch instead.
  • Name every stash.
  • Review git stash list weekly and drop stale entries.
16.21

Stash Conflicts

Source S40 · 11. Stash Conflicts

11.1 When they occur

If the branch changed the same lines since the stash was created, applying it causes a conflict:

Auto-merging sql/procedures/usp_load_orders.sql
CONFLICT (content): Merge conflict in sql/procedures/usp_load_orders.sql
The stash entry is kept in case you need it again.

11.2 Resolution

# edit the file, remove conflict markers
git add sql/procedures/usp_load_orders.sql      # mark resolved (or git restore --staged to keep unstaged)
git stash drop                                   # pop doesn't auto-drop after a conflict

11.3 Avoiding conflicts

  • Apply onto the branch the stash came from.
  • Use git stash branch for old stashes.
  • Don't keep stashes for long.

11.4 Undo a messy apply

git restore .            # discard the applied changes (stash is still in the list)

Added topics, conflicts & verification

Source conflict — `git stash save` and named stash syntax

S41 shows a reference like stash@{manoj} and its embedded cheat-sheet image uses git stash save "msg". Resolution (git-stash docs): git stash save is deprecated in favour of git stash push -m "msg"; stash entries are referenced by index (stash@{0}) or reflog date syntax (stash@{2.hours.ago}), not by name — the message is only a description.

Purpose
Create a branch at the commit where the stash was made, apply the stash there, and drop it if successful.

Real-time scenarios

Source S17, S40 · Recovering a stash dropped by mistake

git stash drop prints the dropped commit ID (Dropped stash@{0} (3a9f…)). Re-apply with git stash apply 3a9f…. If the ID is lost, list unreachable stash commits: git fsck --no-reflogs | grep "dangling commit" and inspect candidates with git show <sha>.

Course addition · Testing only what is staged

Before committing, stash unstaged edits but keep the index: git stash push --keep-index -u, run tests on exactly what will be committed, then git stash pop.

Best practices

Course addition · best practices
  • Always name stashes (-m); keep the stack short.
  • Use -u when you have new files.
  • Prefer a WIP commit on your own feature branch for work that will sit for days; stash is for short interruptions.
  • Use git stash branch for old stashes.
  • Stashes are local — they are not a backup.

Course addition · graded exercises

  1. Modify one tracked file and create one new file; run git stash.

    The new file is still present (not stashed).

  2. Repeat with git stash push -u -m "test".

    Working tree clean; git stash list shows "test".

  3. Create two stashes and apply the older one with git stash apply stash@{1}.

Chapter 16 Interview Questions

Source S17 · Chapter manual · interview

1. What does git stash do?

It saves selected local changes and cleans the working tree so you can change context.

2. Does git stash include untracked files by default?

No. Use git stash push -u to include untracked files.

3. What is the difference between apply and pop?

Apply keeps the stash entry; pop removes it after successful application.

4. How do you inspect a stash patch?

Use git stash show -p stash@{0}.

5. How do you create a named stash?

Use git stash push -m "message".

6. How do you remove one stash?

Use git stash drop stash@{n}.

7. What does git stash clear do?

It deletes all stash entries in the repository.

8. Can a stash cause conflicts?

Yes, if the target branch has overlapping changes.

9. Is a stash shared with teammates?

No. Stashes are local unless you explicitly export their changes another way.

10. How do you include ignored files?

Use git stash push -a, with care.

11. What does --keep-index do?

It leaves staged changes in the index while stashing other changes.

12. How do you preserve staged state on apply?

Use git stash apply --index.

13. Where is the newest stash?

Usually stash@{0}.

14. Should stash replace commits?

No. Commit meaningful, durable work; use stash for temporary context switches.

15. What should you do before stash clear?

Inspect entries and preserve any important changes in a branch, commit or patch.

What does git stash do?

Saves uncommitted changes to a stack and cleans the working tree so you can switch tasks.

Difference between stash apply and stash pop?

Apply re-applies and keeps the entry; pop re-applies and removes it if there were no conflicts.

Intermediate

Advanced
How is a stash stored internally?

As a commit referenced by refs/stash; older entries are in its reflog. The stash commit has HEAD and an index commit as parents (and a third parent for untracked files).

Scenario
You need to apply a 3-week-old stash, but main has changed a lot. What is the safest way?

git stash branch <name> stash@{n} — creates a branch at the original base commit, applies cleanly, then merge/rebase that branch onto the current main.

  • Resolve a conflict when applying a stash and know the entry is kept.
  • Create a branch from a stash (git stash branch) and stash only staged changes (--staged).
  • Recover a dropped stash.
