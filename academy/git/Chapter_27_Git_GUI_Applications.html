Learning objectives

Chapter introduction

What it is. Stand-alone Git GUI clients — GitHub Desktop, GitKraken, Sourcetree, TortoiseGit — and the Git integration in Visual Studio, compared with the command line.

Why it matters. GUIs make history graphs, partial staging and conflict resolution approachable for analysts and occasional contributors; teams must know their limits and the commands underneath.

Where it is used. Mixed-skill data teams, Windows-heavy environments, reviewing complex histories visually.

In this course's project. Neha (Power BI/Fabric) uses GitHub Desktop for PBIP report changes; Meera uses Visual Studio for SSDT database projects; the team documents which GUI operations are allowed (no force-push buttons on shared branches).

27.9

GitHub Desktop

Source S40 · 1. GitHub Desktop

1.1 Overview

Free, open-source desktop app by GitHub for Windows and macOS, focused on simplicity.

1.2 Key features

  • Clone, create and publish repositories (GitHub, GitHub Enterprise, any Git URL).
  • View changes, select lines to commit, write commit messages (co-authors supported).
  • Create, switch, merge, rebase and squash-merge branches; Update from main.
  • Stash changes ("Stashed changes" when switching).
  • Push, pull, fetch; Create Pull Request (opens on GitHub) and preview PRs/checks.
  • Resolve simple conflicts or open in your editor.
  • History view, revert, cherry-pick by drag-and-drop, amend, undo last commit.

1.3 Best for

Beginners, designers/analysts, GitHub-centric teams.

27.10

GitKraken

Source S40 · 2. GitKraken

2.1 Overview

Cross-platform (Windows, macOS, Linux) Git client known for its visual commit graph. Free for public repositories; paid plans for private repos and advanced features.

2.2 Key features

  • Interactive commit graph with drag-and-drop merge/rebase.
  • Built-in merge conflict editor.
  • Integrations: GitHub, GitLab, Bitbucket, Azure DevOps, Jira.
  • Interactive rebase UI, stash, submodules, LFS, Git Flow support.
  • Workspaces for multiple repositories; GitKraken CLI and GitLens (same company).

2.3 Best for

Visual learners, multi-platform teams, complex histories.

27.11

Sourcetree

Source S40 · 3. Sourcetree

3.1 Overview

Free Git client by Atlassian for Windows and macOS.

3.2 Key features

  • Detailed history and branch visualisation.
  • Interactive staging (hunks/lines), stash, tags, submodules, LFS.
  • Git Flow and Hg Flow buttons for structured workflows.
  • Deep Bitbucket integration (also GitHub/GitLab).
  • Interactive rebase, cherry-pick, blame.

3.3 Best for

Atlassian/Bitbucket users and teams using Git Flow.

27.12

TortoiseGit

Source S40 · 4. TortoiseGit

4.1 Overview

Free, open-source Windows shell extension — Git commands in the File Explorer right-click menu, with icon overlays showing file status.

4.2 Key features

  • Commit, push, pull, fetch, branch, merge, rebase, stash from Explorer.
  • Icon overlays (modified, added, conflicted).
  • Log viewer, diff and merge tools (TortoiseGitMerge), blame.
  • Familiar to former TortoiseSVN users.

4.3 Best for

Windows users who prefer Explorer integration, teams migrating from SVN.

27.13

Visual Studio Git Integration

Source S40 · 5. Visual Studio Git Integration

5.1 Overview

Visual Studio (Windows; Community edition free) includes full Git tooling — important for SQL Server Database Projects (SSDT), SSIS, .NET and Azure Functions developers.

5.2 Key features

  • Git Changes window: stage, commit, amend, stash, push, pull, sync.
  • Git Repository window: branch graph, history, compare commits, cherry-pick, revert, reset, rebase.
  • Branch management from the status bar.
  • Merge editor with 3-way view.
  • Create GitHub / Azure DevOps repositories and pull requests from within Visual Studio.
  • Multi-repository support (up to 25 repos in one solution/folder).
  • Line-staging, blame (Annotate), Git Line History.

5.3 Best for

SSDT database projects (DACPAC), SSIS/SSRS, .NET development in the Microsoft ecosystem.

Command Line vs GUI

Source S40 · 7. Command Line vs GUI
Aspect Command line GUI
Feature coverage Complete — every Git feature Common operations; advanced features vary
Learning value Builds deep understanding Easier start, can hide what's happening
Speed Fast for experienced users; scriptable Fast for visual tasks (line staging, browsing history)
Automation / CI/CD Required (pipelines run CLI) Not applicable
Visualising history git log --graph (text) Rich interactive graphs
Conflict resolution Manual or external tool Integrated visual editors
Consistency Same everywhere (servers, containers, Databricks web terminal) Tool-specific UIs
Troubleshooting Full error messages and recovery commands (reflog, fsck) Limited
Interviews Expected knowledge Rarely asked

Recommendation: learn the CLI first — it is what every GUI runs underneath and what CI/CD uses — then use a GUI/IDE for productivity where it genuinely helps (staging hunks, reviewing history, resolving conflicts).

Selecting the Right Git Tool

Source S40 · 8. Selecting the Right Git Tool
If you… Use
Are new to Git and use GitHub GitHub Desktop + CLI practice
Write Python/SQL/YAML daily VS Code (+ GitLens, GitHub PRs)
Build SSDT database projects or SSIS Visual Studio
Want the best visual graph across OSes GitKraken
Work in Atlassian/Bitbucket with Git Flow Sourcetree
Prefer Windows Explorer integration TortoiseGit
Work in Databricks/Fabric/ADF Their built-in Git UIs (Phase 11) + CLI/VS Code for advanced operations

Selection criteria: operating system, hosting platform integration, team standards, licence cost, required features (rebase, LFS, Git Flow), and learning curve.

Command reference

GUI operation → Git command (examples)
Syntax
GitHub Desktop "Fetch origin" → git fetch
"Push origin" → git push
"Undo" (last commit) → git reset --soft HEAD~1
"Discard changes" → git restore
"Stash all changes" → git stash push -u
GitKraken/Sourcetree "Pull (rebase)" → git pull --rebase
Purpose
Map buttons to commands so behaviour is predictable.
Common mistakes
Clicking "Force push" offered after a rebase on a shared branch.

Real-time scenarios

Source S28, S40 · Analyst accidentally discarded changes in a GUI

GUI "Discard" = git restore — uncommitted changes are gone. Recover only from editor/app autosave or OS file history. Team rule: commit early on feature branches; disable discard confirmation bypasses.

Course addition · Choosing a GUI for a mixed team

Windows-only Power BI/SQL users → GitHub Desktop or Visual Studio; cross-platform engineers who like graphs → GitKraken; Bitbucket users → Sourcetree; Explorer-centric users → TortoiseGit. Everyone still follows the same branching/PR standard.

Best practices

Course addition · best practices
  • Standardize on one or two GUIs and document button ↔ command mapping.
  • Keep CLI available for recovery and automation.
  • Disable/avoid force-push on shared branches in GUI settings; rely on server protection.
  • Configure the same identity and credential helper as the CLI.
  • Review the GUI's pre-commit diff before every commit.

Chapter 27 Interview Questions

Source S28 · Chapter manual · interview

1. What is a Git GUI?

A graphical application for Git repository operations.

2. What is GitHub Desktop focused on?

A straightforward desktop workflow integrated with GitHub.

3. What is TortoiseGit?

A Windows Explorer shell integration for Git.

4. Does GUI eliminate Git knowledge?

No; branches, commits, remotes and conflicts still need to be understood.

5. When is CLI preferable?

Automation, scripts and advanced repeatable operations.

Source S40 · 10. Chapter 27 – Interview Questions
No. Question Short answer
1 Name some Git GUI tools. GitHub Desktop, GitKraken, Sourcetree, TortoiseGit, Visual Studio, VS Code
2 Why learn the CLI if GUIs exist? Full feature set, automation/CI, troubleshooting, consistency
3 Which tool for SSDT database projects? Visual Studio
4 Which tool integrates with Windows Explorer? TortoiseGit
5 How do you choose a Git tool? OS, platform integration, features, team standards, cost
Beginner
Name three Git GUI clients.

GitHub Desktop, GitKraken, Sourcetree (also TortoiseGit, Visual Studio, VS Code).

Intermediate
When is the CLI preferable to a GUI?

Automation/CI, servers, advanced or recovery operations (reflog, filter-repo, bisect), and when exact error output is needed.

Do GUIs use a different repository format?

No — they operate on the same .git repository, so you can switch between GUI and CLI freely.

Scenario
A Power BI developer wants version control without learning the CLI. What do you set up?

PBIP/PBIR format in a Git repo, GitHub Desktop (or VS Code), a branch-per-change workflow with PRs, and Fabric Git integration for the workspace (Chapter 35).
