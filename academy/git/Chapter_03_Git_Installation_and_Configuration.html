Where it is used. Every developer workstation, build agents, and containers used by CI/CD.

3.1

Installing Git on Windows

Source S04 · Chapter manual · 1. Installing Git on Windows

Method 1: Official Git for Windows installer

  1. Open the official Git for Windows download page.
  2. Download the installer that matches your Windows architecture.
  3. Run the downloaded installer.
  4. Review the license and proceed through the setup wizard.
  5. Choose the installation location, components, default editor, PATH integration, SSH executable, and line-ending options as appropriate for your environment.
  6. Complete the installation.
  7. Open Git Bash or PowerShell and verify the installation using git --version.

Important installer choices

Installer optionRecommended understanding
PATH environmentThe option that allows Git to be used from Git Bash, PowerShell, Command Prompt, and other applications. The installer wording may vary by release.
SSH executableGit can use its bundled OpenSSH or a system-provided SSH client.
HTTPS transportChoose the supported TLS backend suitable for your organization and environment.
Line endingsUnderstand Windows CRLF and Unix LF handling. The common Windows default is to check out Windows-style endings and commit Unix-style endings.
Terminal emulatorGit Bash commonly uses MinTTY, though Windows console options are also available.

Method 2: Install using Windows Package Manager

If winget is available on your Windows machine, open PowerShell and run:

winget install --id Git.Git -e --source winget

Follow any prompts, then close and reopen the terminal so it refreshes the PATH environment.

Method 3: Verify from PowerShell

git --version
where.exe git

The first command prints the installed Git version. The second shows the executable location resolved by Windows.

Corporate devices: If your laptop is managed by your organization, installation may require administrator approval or an approved software portal. Follow your company's endpoint and security policies.

3.4

Git Bash Introduction

Source S04 · Chapter manual · 4. Git Bash Introduction

What is Git Bash?

Git Bash is a command-line environment installed with Git for Windows. It provides a Bash-like shell and a collection of Unix-style command-line utilities, allowing Windows users to run Git commands and many familiar shell commands.

Why use Git Bash?

  • Run Git commands in a consistent Bash-style environment.
  • Use commands such as ls, pwd, cat, and touch.
  • Run shell scripts written for Bash, subject to the tools and compatibility available.
  • Follow tutorials that use Linux/macOS-style terminal commands.

Common Git Bash commands

CommandPurpose
pwdPrint the current directory.
lsList files and directories.
cd folderChange directory.
mkdir projectCreate a directory.
touch file.txtCreate an empty file or update its timestamp.
cat file.txtDisplay file content.
clearClear the terminal screen.
git statusDisplay repository status.

Open Git Bash

  1. Install Git for Windows.
  2. Open the Start menu.
  3. Search for Git Bash.
  4. Launch it.
  5. Run git --version.

Windows path example

Git Bash commonly represents the C: drive as /c/. For example, C:\Users\YourUser\Projects may be accessed as:

cd /c/Users/YourUser/Projects

The exact path depends on your Windows account and folder layout.

3.7

Configuring Username

Source S04 · Chapter manual · 7. Configuring Username

Git records author and committer names in commit metadata. Set a name so your commits identify you consistently.

Set a global username

git config --global user.name "Your Name"

This setting applies to your user account's repositories unless overridden by a more specific configuration.

Set a repository-specific username

git config --local user.name "Project Contributor"

Run this command from inside the repository. It overrides the global value for that repository.

Verify username

git config user.name
git config --global user.name
The Git user.name value is commit metadata. It is not necessarily your GitHub display name or login username.
3.8

Configuring Email

Source S04 · Chapter manual · 8. Configuring Email

Git also records an email address in commit author and committer metadata.

Set a global email

git config --global user.email "you@example.com"

Set a repository-specific email

git config --local user.email "project-address@example.com"

Verify email

git config user.email
git config --global user.email

Choosing the right email

  • Use an email address approved for your work commits.
  • If your organization requires a corporate address, follow that policy.
  • If you want GitHub to associate commits with your account, use an address verified on GitHub or configure the GitHub-provided noreply address.
  • Be aware that commit email metadata may be visible to people who can access the repository.
Privacy: Do not use a personal email in a public repository if you do not want it exposed. GitHub provides a noreply email option; see its documentation for the current format and settings.
3.9

Git Global Configuration

Source S04 · Chapter manual · 9. Git Global Configuration

What is global configuration?

Global configuration applies to the current operating-system user and is commonly stored in a file named ~/.gitconfig or an XDG configuration file, depending on the setup.

Set common global settings

# Set commit author name
git config --global user.name "Your Name"

# Set commit author email
git config --global user.email "you@example.com"

# Set the default initial branch name
git config --global init.defaultBranch main

# Choose a default editor (example: VS Code)
git config --global core.editor "code --wait"

View global settings

git config --global --list
git config --global --list --show-origin

Remove a global setting

git config --global --unset user.name

Only unset a setting when you intend to remove it. If a setting is required, configure the correct value instead.

3.10

Git Local Configuration

Source S04 · Chapter manual · 10. Git Local Configuration

What is local configuration?

Local configuration applies only to one Git repository. It is stored in that repository's .git/config file.

How to configure local settings

  1. Open a terminal.
  2. Navigate to the repository folder.
  3. Run Git configuration commands with the --local option.
cd path/to/project

git config --local user.name "Project Contributor"
git config --local user.email "project@example.com"

View local settings

git config --local --list
git config --local --list --show-origin

When should you use local configuration?

  • When a work repository must use your corporate identity.
  • When a personal project must use a different commit email.
  • When a project requires a specific editor or other repository-level preference.
Example: You can use your personal email globally but set a corporate email locally inside your organization's repository.
3.11

Git System Configuration

Source S04 · Chapter manual · 11. Git System Configuration

What is system configuration?

System configuration applies to all users on a machine. It is generally stored in a Git configuration file under the Git installation's system configuration location.

Set a system-level value

git config --system core.autocrlf true

This is only an example. Line-ending behavior should be selected to suit the operating systems and conventions used by the project. Changing system configuration typically requires administrator or elevated permissions.

View system configuration

git config --system --list
git config --system --list --show-origin

When is system configuration useful?

  • On shared or managed computers.
  • When administrators need to establish machine-wide defaults.
  • When an organization centrally manages Git behavior on developer workstations.
Be careful: Avoid changing system-level settings unless you administer the machine or have clear instructions from your IT team. A system setting can affect every user on that computer.
3.12

Git Configuration Levels

Source S04 · Chapter manual · 12. Git Configuration Levels

Git supports configuration at multiple scopes. More specific settings can override less specific settings.

ScopeCommand optionTypical locationApplies to
System--systemSystem Git configuration fileAll users on the machine
Global--global~/.gitconfig or XDG config locationCurrent user
Local--local.git/configCurrent repository
Worktree--worktreeWorktree-specific config, when enabledCurrent linked working tree

Configuration precedence

For ordinary single-valued settings, Git generally reads lower-priority configuration first and allows higher-priority, more specific values to take precedence. Command-line options and environment variables can also influence behavior.

Lower priority System ↓ Global ↓ Local ↓ Worktree (when configured) ↓ Command-line options / environment overrides Higher priority

Some configuration keys are multi-valued and combine rather than simply replace earlier values. Conditional includes and other configuration mechanisms can also affect the final result.

Example: different names at different levels

# Global identity
git config --global user.name "Sreehari"
git config --global user.email "personal@example.com"

# Run inside a specific repository
git config --local user.email "sreehari@company.example"

# Check the effective value
git config user.email

# See all values and their source files
git config --list --show-origin

Inside that repository, the local email is used instead of the global email. Outside that repository, the global email remains the default.

Useful configuration inspection commands

git config --list
git config --list --show-origin
git config --show-origin user.name
git config --show-origin user.email
git config --show-scope --list
3.13

Setting the Default Branch Name

Source S04 · Chapter manual · 13. Setting the Default Branch Name

What is the default branch?

When Git initializes a new repository, it creates an initial branch. The branch name can be configured. Many teams use main as the default branch name.

Set the default initial branch to main

git config --global init.defaultBranch main

Verify the setting

git config --global init.defaultBranch

Test it in a new repository

mkdir branch-test
cd branch-test
git init
git branch --show-current

Before the first commit, git branch --show-current should show the current initial branch name in modern Git versions.

Rename the current branch in an existing repository

git branch -m main

This renames the currently checked-out branch. If the branch has already been pushed, coordinating the remote branch rename and updating collaborators may also be necessary.

The init.defaultBranch setting affects newly initialized repositories. It does not automatically rename branches in repositories that already exist.
3.14

Configuring Default Editor

Source S04 · Chapter manual · 14. Configuring Default Editor

What is the default Git editor?

Git sometimes opens a text editor when you create a commit without supplying a message, edit a merge message, or perform other operations that require text input.

You can configure which editor Git launches.

Visual Studio Code

git config --global core.editor "code --wait"

The --wait option tells Git to wait until you close the editor window before continuing. The code command must be available in your terminal PATH.

Notepad on Windows

git config --global core.editor notepad

Vim

git config --global core.editor "vim"

Nano

git config --global core.editor "nano"

Verify editor configuration

git config --global core.editor

How to test it

Inside a repository, run:

git commit

If there are staged changes, Git should open the configured editor for the commit message. Save and close the editor to complete the commit, or exit without saving to cancel the message.

Common issue: If Git reports that it cannot find code, configure the VS Code command-line launcher in PATH or select an editor that is already installed.
3.15

Understanding .gitconfig

Source S04 · Chapter manual · 15. Understanding .gitconfig

What is .gitconfig?

.gitconfig is a configuration file used by Git to store settings such as user identity, editor preferences, aliases, and other Git options.

Common configuration locations

ConfigurationTypical location
GlobalWindows: C:\Users\YourUser\.gitconfig; Linux/macOS: ~/.gitconfig (unless XDG configuration is used)
Local<repository>/.git/config
SystemGit installation or operating-system-specific system configuration location

Example .gitconfig content

[user]
    name = Sreehari
    email = sreehari@example.com

[init]
    defaultBranch = main

[core]
    editor = code --wait

[alias]
    st = status
    co = checkout
    br = branch
    ci = commit

What do these sections mean?

SectionPurpose
[user]Default author and committer identity values.
[init]Repository initialization defaults.
[core]Core Git behavior, including editor settings.
[alias]Shortcuts for Git commands.

Creating Git aliases

Aliases help shorten frequently used commands.

git config --global alias.st status
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit

Then you can run:

git st
git br
git ci -m "Add initial files"

Read configuration using Git

# Show all effective configuration values
git config --list

# Show each value's source
git config --list --show-origin

# Read one setting
git config user.name

# Read a setting and its source
git config --show-origin user.email
Do not confuse the files: the global .gitconfig is different from a repository's .git/config. Use git config commands to inspect and change settings safely.

Git Bash is an application installed with Git for Windows that provides a Bash shell emulation on Windows. It lets you use Git along with common Linux/Unix commands.

Git Global Configuration

Source S40 · 9. Git Global Configuration

9.1 Definition

Global configuration applies to all repositories of the current operating-system user. It is stored in:

OS File
Windows C:\Users\<username>\.gitconfig
Linux / macOS ~/.gitconfig (or ~/.config/git/config)

9.2 Commands

git config --global user.name "Ravi Kumar"

git config --global init.defaultBranch main

git config --global color.ui auto
git config --global alias.st "status -sb"

3.25

Git Local Configuration

Source S40 · 10. Git Local Configuration

10.1 Definition

Local configuration applies only to one repository. It is stored in .git/config inside that repository. --local is the default when you are inside a repository.

10.2 Example — different email for one project

cd retail-data-platform
git config --local user.email "ravi.personal@gmail.com"
git config --local --list
cat .git/config

[core]
    repositoryformatversion = 0
    filemode = false
    bare = false
    logallrefupdates = true
[user]
    email = ravi.personal@gmail.com
[remote "origin"]
    url = https://github.com/ravi/retail-data-platform.git
    fetch = +refs/heads/*:refs/remotes/origin/*
[branch "main"]
    remote = origin
    merge = refs/heads/main

10.3 Conditional includes (advanced)

Use one identity for every repository under a work folder automatically:

# ~/.gitconfig
[includeIf "gitdir:C:/Work/"]
    path = ~/.gitconfig-work

# ~/.gitconfig-work
[user]
    email = ravi.kumar@company.com

Git Configuration Levels

Source S40 · 12. Git Configuration Levels

12.1 Summary

Level Flag Location Applies to Priority
System --system Git installation's etc/gitconfig All users, all repos Lowest
Global --global User home .gitconfig One user, all repos Medium
Local --local .git/config One repository High

3.28

Setting Default Branch Name

Source S40 · 13. Setting Default Branch Name

When you run git init, Git creates an initial branch. Older Git versions named it master; GitHub, GitLab and Azure Repos now default to main.

git config --global init.defaultBranch main     # Git 2.28+
git init                                         # new repos start on main
git init -b main                                 # set for a single repo
git branch -m master main                        # rename an existing master branch

Note Keeping your local default aligned with the remote (main) avoids errors such as src refspec main does not match any when pushing.

3.29

Configuring Default Editor

Source S40 · 14. Configuring Default Editor

Git opens an editor for commit messages without -m, interactive rebase, merge messages and git config --edit.

Editor Command
VS Code git config --global core.editor "code --wait"

Understanding .gitconfig

Source S40 · 15. Understanding .gitconfig

15.1 Format

.gitconfig is an INI-style text file with sections in square brackets and key = value pairs. Subsections use quotes: [remote "origin"].

15.2 Example global .gitconfig

[user]
    name = Ravi Kumar
    email = ravi.kumar@company.com
[init]
    defaultBranch = main
[core]
    editor = code --wait
    autocrlf = true            # Windows; use 'input' on macOS/Linux
    longpaths = true
[pull]
    rebase = false
[fetch]
    prune = true
[push]
    autoSetupRemote = true
[merge]
    conflictstyle = zdiff3
[rerere]
    enabled = true
[credential]
    helper = manager
[alias]
    st = status -sb
    lg = log --oneline --graph --decorate --all
    co = checkout
    sw = switch
    last = log -1 HEAD --stat
    unstage = restore --staged

15.3 Important sections explained

Section.key Meaning
user.name, user.email Identity stored in each commit
init.defaultBranch Initial branch name for git init
core.editor Editor Git opens
core.autocrlf Line-ending conversion (true on Windows, input on Mac/Linux)
core.longpaths Allow long paths on Windows
pull.rebase Whether git pull merges or rebases
fetch.prune Remove remote-tracking branches deleted on the server
push.autoSetupRemote Automatically set upstream on first push
credential.helper Where credentials are stored securely
alias.* Your own shortcut commands (git lg)

Command reference

git config
Syntax
git config [--system | --global | --local] <key> <value>
git config [--show-origin] --list
git config --get <key>
git config --unset <key>
Purpose
Read and write Git configuration at a given level.
Key parameters
  • --global — your user (most personal settings)
  • --local — current repository (default when inside a repo)
  • --system — all users (needs admin rights)
  • --show-origin — print the file each value comes from
  • --edit / -e — open the config file in your editor
Behaviour
Writes INI-style entries into the chosen file. When the same key exists at several levels, the most specific one wins (local over global over system).
Expected output
file:/home/asha/.gitconfig       user.name=Asha Rao
file:/home/asha/.gitconfig       user.email=asha.rao@retail-example.com
file:.git/config                 core.repositoryformatversion=0
Example
git config --global user.name "Asha Rao"
git config --global user.email "asha.rao@retail-example.com"
git config --global init.defaultBranch main
git config --global core.editor "code --wait"
git config --global pull.rebase false     # or: git config --global pull.ff only
git config --list --show-origin
Common mistakes
Using a personal e-mail in a work repository (commits then do not link to your company account); quoting errors in PowerShell; forgetting --wait for VS Code so Git aborts the commit immediately.
Troubleshooting
Correct the setting, then fix the last commit's author with git commit --amend --reset-author --no-edit (only if not yet pushed).
core.autocrlf / .gitattributes
Syntax
git config --global core.autocrlf true     # Windows
git config --global core.autocrlf input    # macOS / Linux
Purpose
Normalize line endings so files are stored with LF in the repository.
Behaviour
true converts LF→CRLF on checkout and CRLF→LF on commit; input converts CRLF→LF on commit only. A committed .gitattributes (Chapter 24) overrides personal settings and is the team-wide recommendation.
Example
# .gitattributes at repository root
* text=auto
*.sh  text eol=lf
*.ps1 text eol=crlf
Common mistakes
Relying only on personal core.autocrlf — different settings across the team produce whole-file diffs.
includeIf (conditional configuration)
Syntax
[includeIf "gitdir:~/work/"]
    path = ~/.gitconfig-work
Purpose
Load extra settings (for example a work e-mail) only for repositories under a path.
Example
# ~/.gitconfig
[user]
    name = Asha Rao
    email = asha.personal@example.com
[includeIf "gitdir:~/work/"]
    path = ~/.gitconfig-work

# ~/.gitconfig-work
[user]
    email = asha.rao@retail-example.com
Common mistakes
Missing trailing slash in gitdir:~/work/ — without it only that exact directory matches. On Windows use forward slashes or gitdir/i: for case-insensitive matching.

Best practices

Course addition · best practices
  • Set init.defaultBranch main — it matches GitHub, Azure Repos and the Git 3.0 default.
  • Commit a .gitattributes for line endings instead of relying on individual settings.
  • Choose a pull strategy explicitly (pull.rebase or pull.ff) — Git asks you to when branches diverge.
  • Keep secrets out of .gitconfig; use a credential manager (Chapter 23).
  • Review git config --list --show-origin when behaviour is surprising.

Beginner
Which two settings must you configure before your first commit?

user.name and user.email.

How do you check the installed Git version?

git --version.

Intermediate
Explain the precedence of Git configuration levels.

System < global < local (< worktree < command-line -c). The most specific value wins.

How do you find which file a setting comes from?

git config --show-origin --get <key> or git config --list --show-origin.

Advanced
How would you use different identities for work and personal repositories automatically?

Use [includeIf "gitdir:~/work/"] in the global config pointing to a file that overrides user.email (and signing key).

What is the difference between core.autocrlf true and input?

true converts on commit and on checkout (Windows); input only converts CRLF to LF on commit (macOS/Linux). A .gitattributes file overrides both for the repository.

Scenario
A teammate's commit diff shows every line of a SQL file changed although only one line was edited. What happened and how do you prevent it?

Line endings were converted (CRLF vs LF). Add .gitattributes with * text=auto (and explicit rules), run git add --renormalize . once, and commit the normalization separately.
