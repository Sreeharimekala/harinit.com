1.1

What is Microsoft Fabric?

Before jumping into details, let's understand the big picture. Microsoft Fabric is a single platform where all your data work happens — from collecting raw data all the way to publishing a business dashboard. Think of it as a one-stop shop for everything data-related in your organisation.

Definition

Microsoft Fabric is Microsoft's end-to-end, cloud-based, Software-as-a-Service (SaaS) analytics platform. It unifies the following capabilities under one roof:

🔗
Data Factory
Ingest data from any source, build pipelines, and orchestrate workflows.
⚙️
Data Engineering
Process large datasets with Apache Spark, Python notebooks, and SQL.
🏛️
Data Warehouse
Run SQL analytics on a fully managed enterprise data warehouse.
🧪
Data Science
Build and train machine learning models using notebooks and MLflow.
⚡
Real-Time Intelligence
Process streaming and event data in real time for instant insights.
📊
Power BI
Build interactive reports, dashboards, and self-service analytics.
🗄️
OneLake
A single, unified data lake that stores all your organisation's data.

In Simple Terms

Microsoft Fabric = One platform where you can collect data → store data → transform data → analyse data → build reports and insights.

How Fabric Fits Together

All workloads run on top of a shared storage foundation called OneLake. This means every team — data engineers, SQL analysts, data scientists, and BI developers — works with the same data without copying it.

1.2

Why Was Fabric Created?

To appreciate Fabric, you need to understand the pain of working without it. Before Fabric, organisations had to stitch together many separate Azure tools — each with its own configuration, storage, security, and billing. Fabric was designed to remove that complexity.

The Problem Before Fabric

A typical modern data platform used to look like this:

❌ Traditional Approach

  • Azure Data Factory (ingest)
  • ADLS Gen2 (store)
  • Azure Databricks / Synapse Spark (process)
  • Synapse SQL (warehouse)
  • Power BI (report)
  • + Separate security, monitoring, connections for each

Result: more administration, more data copies, more cost, more complexity.

✅ With Microsoft Fabric

  • One platform
  • One data lake (OneLake)
  • Integrated workloads
  • Shared governance
  • Shared capacity billing
  • + Built-in Power BI

Result: simpler operations, no unnecessary data movement, faster delivery.

The Data Duplication Problem

Consider a company with 1 TB of sales data. In a traditional setup, every team kept its own copy:

Original Data      →  1 TB
Data Engineering   →  1 TB copy
Data Warehouse     →  1 TB copy
Power BI Import    →  Additional cached data
─────────────────────────────────
Total storage      →  3+ TB for the same data

With OneLake, all workloads read from one single copy — drastically cutting storage costs and removing synchronisation problems.

Key Reasons to Use Fabric

  • One platform — data engineers, SQL developers, BI analysts all collaborate in one place
  • OneLake — one data lake for the whole organisation, no duplication
  • Reduced data movement — workloads share data in place rather than copying it
  • SaaS simplicity — no infrastructure to manage; Microsoft handles scaling, patching, and updates
  • Integrated Power BI — reports connect to data directly, using Direct Lake for fast queries without import
  • Centralised governance — one place for security, permissions, and compliance
  • Shared capacity — a single compute pool (CU) is shared across all workloads in a workspace
Microsoft Fabric simplifies modern data analytics by bringing data integration, engineering, warehousing, data science, real-time intelligence, and Power BI into one SaaS platform. It uses OneLake as a unified data foundation, reducing data movement and duplication while improving collaboration, governance, and end-to-end analytics.
1.3

Fabric Architecture

Architecture means "how the parts fit together". Fabric is not just a collection of independent tools — its layers are designed to work together through shared storage, shared security, and shared capacity. Understanding the layers will help you know where each piece of work happens.

The Six Layers of Fabric Architecture

1
Data Source Layer
Where data originates — on-premises databases, cloud services, files, APIs, streaming events.
2
Data Integration Layer (Data Factory)
Pipelines, Copy Activities, and Dataflow Gen2 bring data from sources into OneLake.
3
Storage Layer (OneLake)
The single, unified data lake for the organisation. All Fabric items store data here in Delta/Parquet format.
4
Processing & Analytics Layer
Data Engineering (Spark), Data Warehouse (SQL), Data Science (ML), and Real-Time Intelligence all operate here.
5
Semantic / BI Layer
Semantic Models define business logic (measures, KPIs, relationships). Power BI reads from these models for reports.
6
Security & Governance
Microsoft Entra ID, workspace roles, and data-access controls span all layers.

Medallion Architecture (Bronze → Silver → Gold)

Inside Fabric, data is typically organised in three quality layers called the Medallion Architecture. This is a best-practice pattern for structuring data in a Lakehouse.

🥉 BRONZE
Raw data, exactly as received. Nothing is changed. Acts as your historical archive.
🥈 SILVER
Cleaned and validated data. Duplicates removed, formats standardised, nulls handled.
🥇 GOLD
Business-ready data. Aggregated, modelled, and optimised for reporting and analytics.
Always keep Bronze data untouched. If something goes wrong in Silver or Gold, you can reprocess from Bronze.

Lakehouse vs Data Warehouse

Fabric offers two main storage items for structured data. Here is when to use each:

LakehouseData Warehouse
Best forLarge-scale data engineering, mixed file typesSQL analytics, enterprise BI reporting
Query languageSpark (PySpark, Spark SQL)T-SQL
Data formatDelta Lake + Parquet filesRelational tables (Delta under the hood)
Primary usersData engineersSQL developers, analysts

Key Architecture Concepts

Direct Lake

Direct Lake is a Power BI query mode unique to Fabric. Instead of importing data into Power BI (which creates a copy), Direct Lake reads Delta tables in OneLake directly — giving you near-import speed with no data duplication.

OneLake → Delta Tables → Direct Lake → Semantic Model → Power BI

Real-Time Intelligence

For streaming data (IoT sensors, clickstreams, financial ticks), Fabric provides an Eventstream to capture events and an Eventhouse for real-time querying.

Events / Streams → Eventstream → Eventhouse → Real-Time Dashboards / Alerts

Workspace

A Workspace is a container for all Fabric items in a project. It is shared by a team and linked to a Capacity.

Fabric Capacity
├── Workspace A  (Sales project)
│   ├── Lakehouse
│   ├── Pipeline
│   ├── Notebook
│   └── Power BI Report
└── Workspace B  (Finance project)
    ├── Warehouse
    └── Semantic Model
Fabric architecture follows a layered SaaS model: data flows from sources through Data Factory into OneLake, is processed by engineering/warehouse/data-science workloads, and surfaces to business users through semantic models and Power BI. Security and governance span every layer.
1.4

OneLake

OneLake is the most important concept in Microsoft Fabric. Everything else in Fabric depends on it. If you understand OneLake well, the rest of Fabric becomes much easier to grasp.

What is OneLake?

"OneDrive for organisational data."

Just as OneDrive gives every Microsoft 365 user one place to store files, OneLake gives every Fabric tenant one place to store all organisational data — regardless of which workload created it.

  • One per Fabric tenant (created automatically)
  • Built on Azure Data Lake Storage Gen2 (ADLS Gen2) under the hood
  • All Fabric workloads read and write here — no siloed storage
  • Stores data in Delta Lake / Parquet open format

OneLake Hierarchy

OneLake (one per tenant)
└── Workspace A
    ├── Lakehouse 1
    │   ├── Files/     ← raw files (CSV, JSON, Parquet)
    │   └── Tables/    ← Delta tables
    └── Warehouse 1
        └── Tables/    ← Delta tables (SQL access)

OneLake Shortcuts

A Shortcut lets you reference data stored in an external location (ADLS Gen2, Amazon S3, Google Cloud Storage) without copying it. The data stays in place; Fabric just points to it.

Use Shortcuts when you have existing data in ADLS or S3 and don't want to migrate it. You can still query it in Fabric notebooks and warehouses as if it were local.

OneLake vs Traditional Storage

OneLakeADLS Gen2 (traditional)
SetupAutomatic — created with your Fabric tenantMust be manually created and configured
Access controlFabric workspace roles + item-level securityAzure RBAC + ACLs
Multi-workloadShared natively by all Fabric itemsEach service configures its own access
FormatDelta Lake / ParquetAny file format
Direct LakeSupported (fast Power BI)Not supported
OneLake is Fabric's built-in, single data lake for the entire organisation. It is automatically provisioned with the tenant, stores data in Delta/Parquet format, and is shared by all Fabric workloads — eliminating the need for separate storage accounts per service.
1.5

SaaS vs PaaS

You will often hear "Fabric is SaaS". But what does that mean, and how is it different from the Azure services you may have used before? This lesson explains the key difference.

Service Model Comparison

PaaS (e.g. Azure Synapse, ADF)SaaS (Microsoft Fabric)
Who manages infrastructure?Microsoft manages hardware; you manage the serviceMicrosoft manages everything
SetupYou provision resources, choose SKUs, configure networkingYou sign up and start working immediately
UpdatesYou apply updates on your scheduleAutomatic — always on the latest version
BillingPer resource (each service billed separately)Per capacity unit (CU) — one pool for all workloads
IntegrationYou wire services together with connectors and credentialsWorkloads are natively integrated
SaaS means less administration for your team. The trade-off is less low-level control — but for most analytics workloads, that is a worthwhile exchange.

Capacity & Licensing

Capacity is how Fabric measures and allocates compute power. Understanding it helps you know why performance varies and how costs work. Think of capacity as a shared engine — all your workloads run on the same engine, and they share its power.

Capacity Units (CUs)

Fabric compute is measured in Capacity Units (CUs). You purchase a capacity SKU (e.g. F64 = 64 CUs) and all workloads in workspaces assigned to that capacity share those CUs.

1.7

Workspaces

A Workspace is your project folder inside Fabric. Everything you build — Lakehouses, notebooks, pipelines, reports — lives inside a workspace. Teams share workspaces and control who can access what through roles.

What Lives in a Workspace?

  • Lakehouse — store and process data with Spark
  • Warehouse — SQL analytics on structured data
  • Pipeline — orchestrate data movement
  • Notebook — write PySpark / SQL / R code
  • Semantic Model — define business metrics and relationships
  • Power BI Report / Dashboard — visualise data
  • Eventstream / Eventhouse — real-time data

Workspace Roles

RoleCan Do
AdminManage workspace settings, add/remove members, delete items
MemberCreate, edit, and delete items; share reports
ContributorCreate and edit items; cannot delete or manage access
ViewerRead-only access to items and reports
1.8

Roles & Permissions

Security in Fabric works at multiple levels. You need to understand both workspace-level roles (who can access the workspace) and item-level permissions (who can access specific data within a Lakehouse or Warehouse).

Security Layers

  • Microsoft Entra ID — users and groups are managed here (the identity provider)
  • Workspace roles — control who can create/edit items in a workspace
  • Item-level permissions — share individual Lakehouses, Warehouses, or reports with specific users
  • Row-level security (RLS) — restrict which rows of data a user sees in a report
  • Column-level security (CLS) — restrict which columns a user can query in a Warehouse
  • OneLake data access roles — control access to specific folders within a Lakehouse
Always apply the principle of least privilege — give users the minimum access they need. Use Viewer for most report consumers; only give Contributor or higher to developers.

Hands-On: Create a Fabric Trial & Explore the UI

The best way to learn Fabric is to use it. In this lesson you will activate a free 60-day trial, create your first workspace, and explore the interface so you know where everything is.

Steps to Get Started

  1. Go to app.fabric.microsoft.com and sign in with your Microsoft account.
  2. Click your account icon (top right) → Start trial.
  3. Accept and activate the F64-equivalent free trial (60 days).
  4. Click + New workspace → name it Retail Sales – Data Engineering [DEV] → click Apply. (Course naming standard: <Project> – <Area> [<ENV>] for workspaces and <type>_<project>_<layer/purpose> for items, with project code sales.)
  5. Explore the left navigation:
    • Home — recent items and announcements
    • OneLake data hub — browse all data items across workspaces
    • Workspaces — your project containers
    • Create — create Lakehouses, Notebooks, Pipelines, Reports, and more
  6. Try creating your first Lakehouse — click + New item → Lakehouse → name it lh_sales_bronze and click Create.
The trial gives you full access to all Fabric features. Use it to follow along with the hands-on exercises in every lesson of this academy.
