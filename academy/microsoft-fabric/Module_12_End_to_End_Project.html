Source Systems: SQL Server, Blob, REST API

The project has three very different sources — a transactional database, files dropped by stores, and a web API — which is typical of real platforms. For each one, this lesson describes the data, how Fabric connects to it, and how you'll detect what's new.

Source 1 — SQL Server RetailOps (on-premises)

TableRowsKeyChange detectionLoad type

Sales.OrderLines~120 M (+180 k/day)OrderID, LineNumberModifiedDateIncremental

  • Connect through an on-premises data gateway (Module 3) with a connection owned by a service account
  • Ask the DBA for a read-only login, and an index on ModifiedDate for the large tables
  • Watch out: does ModifiedDate change on every update? Are deletes physical (rows disappear) or soft (IsDeleted flag)? Physical deletes need a periodic full key comparison or CDC.

Source 2 — Azure Blob Storage store-uploads

The project ingests from three typical source types. The on-premises SQL Server is reached through a data gateway with a read-only service connection; large tables are loaded incrementally by a ModifiedDate watermark and small ones in full, with attention to hard deletes. Store files in Azure Blob Storage are read through a connection or OneLake shortcut, and new files are tracked with a processed-files log to catch late or duplicate uploads. The REST exchange-rate API is called with a Key Vault-stored token, handling pagination and rate limits, and requested by date, recording both requested and returned dates for holidays.

Step 3 — Store Files: nb_sales_bronze_ingest_inventory

A shortcut Files/store_uploads in lh_sales_bronze points at the Blob container. The notebook processes only files not yet logged:

from pyspark.sql import functions as F
from datetime import datetime, timezone

# Parameters cell — the pipeline passes @pipeline().RunId
batch_id = "manual"

root = "Files/store_uploads/inventory"

# 1. List candidate files for the last 3 days (catches late uploads)
def list_csvs(path):
    try:
        return [f.path for f in notebookutils.fs.ls(path) if f.name.endswith(".csv")]
    except Exception:
        return []                              # folder doesn't exist yet

days = spark.sql("SELECT explode(sequence(date_sub(current_date(), 2), current_date())) d").collect()
candidates = [p for r in days for p in list_csvs(f"{root}/{r.d:%Y/%m/%d}")]

# 2. Remove files already processed
done = {r.file_path for r in spark.table("ops.processed_files").select("file_path").collect()}
new_files = [p for p in candidates if p not in done]
print(f"{len(new_files)} new files")

if new_files:
    df = (spark.read.option("header", True).csv(new_files)
            .withColumn("_source_file", F.input_file_name())
            .withColumn("_batch_id", F.lit(batch_id))
            .withColumn("_loaded_at", F.current_timestamp()))
    df.write.mode("append").option("mergeSchema", "true").saveAsTable("bronze_inventory")

    # 3. Log each file with its row count
    counts = df.groupBy("_source_file").count().collect()
    by_name = {r["_source_file"].split("/")[-1]: r["count"] for r in counts}
    now = datetime.now(timezone.utc)
    log = [(p, now, by_name.get(p.split("/")[-1], 0), batch_id) for p in new_files]
    spark.createDataFrame(log, "file_path string, processed_at timestamp, row_count long, batch_id string") \
         .write.mode("append").saveAsTable("ops.processed_files")
Files with zero rows are logged with row_count = 0 — a quick query on ops.processed_files then shows which stores sent empty files or no file at all (compare with DimStore).

Step 4 — FX Rates API: nb_sales_bronze_ingest_fx_api

import json, time, requests
from pyspark.sql import functions as F
from datetime import date, timedelta

# Parameters cell
run_date = ""                               # blank = yesterday

vl       = notebookutils.variableLibrary.getLibrary("vl_sales")
base_url = vl.fx_api_url                          # e.g. https://api.example-fx.com/v1/rates
token    = notebookutils.credentials.getSecret(vl.key_vault_url, "fx-api-token")
req_date = run_date or (date.today() - timedelta(days=1)).isoformat()

def get_with_retry(url, params, attempts=5):
    for i in range(attempts):
        r = requests.get(url, params=params, timeout=30,
                         headers={"Authorization": f"Bearer {token}"})
        if r.status_code == 429 or r.status_code >= 500:          # throttled / server error → back off
            wait = int(r.headers.get("Retry-After", 2 ** i))
            time.sleep(wait); continue
        r.raise_for_status()                                         # 4xx = our mistake → fail now
        return r.json()
    raise RuntimeError(f"API still failing after {attempts} attempts")

pages, page = [], 1
while page:
    body = get_with_retry(base_url, {"base": "INR", "date": req_date, "page": page})
    pages.append(body)
    page = body.get("next_page")

# Keep the raw response (audit, replay), then a flat Bronze table
notebookutils.fs.put(f"Files/raw/fx/{req_date}.json", json.dumps(pages), True)

rows = [(req_date, p["date"], p["base"], r["currency"], float(r["rate"]))
        for p in pages for r in p["rates"]]
if not rows:
    raise ValueError(f"No FX rates returned for {req_date}")

(spark.createDataFrame(rows, "requested_date string, rate_date string, base string, currency string, rate double")
      .withColumn("_loaded_at", F.current_timestamp())
      .write.mode("append").saveAsTable("bronze_fx_rates"))

notebookutils.notebook.exit(json.dumps({"rows": len(rows), "date": req_date}))

Check Your Bronze Layer

  • Five SQL tables loaded; ops.watermark updated for the incremental ones
  • bronze_inventory rows match the sum of ops.processed_files.row_count; re-running loads 0 new files
  • Raw FX JSON in Files/raw/fx/; bronze_fx_rates has a row per currency
  • Every Bronze row has _batch_id / _loaded_at
The Bronze layer is driven by control tables for pipeline configuration, watermarks, processed files and a run log. SQL Server tables are landed by the metadata-driven child pipeline with watermark-filtered Copy queries and appended with batch metadata. Store files are read through a OneLake shortcut by a notebook that lists recent date folders, skips files already in the processed-files log, appends the rest with source-file and batch columns and logs each file's row count. FX rates come from a notebook that reads configuration from a variable library and the token from Key Vault, calls the API with retries and back-off for throttling and server errors, follows pagination, stores the raw JSON and appends a flat Bronze table.

Incremental Loading & Silver

Bronze now receives only new and changed rows each night. Silver must turn those increments into clean, de-duplicated, current tables — without ever reprocessing history. This lesson builds one reusable merge function for all SQL tables, plus source-specific handling for inventory files, FX rates and deleted rows.

How the Increments Flow

→
Bronzeappend, _batch_id = run
→ this batch only →
Clean + dedupe

Step 1 — Table-Specific Cleaning

# nb_sales_util_silver_rules — cleaning rules per table (Module 5.2)
from pyspark.sql import functions as F

def clean_customers(df):
    return (df.select(
                F.col("CustomerID").cast("bigint").alias("customer_id"),
                F.initcap(F.trim("CustomerName")).alias("customer_name"),
                F.lower(F.trim("Email")).alias("email"),
                F.initcap(F.trim("City")).alias("city"),
                F.upper(F.trim("Region")).alias("region"),
                F.coalesce(F.trim("Segment"), F.lit("Unassigned")).alias("segment"),
                F.col("ModifiedDate").cast("timestamp").alias("modified_at"))
              .filter(F.col("customer_id").isNotNull()))

def clean_order_lines(df):
    return (df.select(
                F.col("OrderID").cast("bigint").alias("order_id"),
                F.col("LineNumber").cast("int").alias("line_number"),
                F.col("ProductID").cast("bigint").alias("product_id"),
                F.col("Quantity").cast("int").alias("quantity"),
                F.col("UnitPrice").cast("decimal(18,2)").alias("unit_price"),
                F.col("UnitCost").cast("decimal(18,2)").alias("unit_cost"),
                F.col("ModifiedDate").cast("timestamp").alias("modified_at"))
              .filter("quantity > 0"))

CLEANERS = {"customers": clean_customers, "order_lines": clean_order_lines}   # … one per table

Step 2 — One Generic Incremental Merge

from pyspark.sql.window import Window
from delta.tables import DeltaTable

def merge_to_silver(name, keys, batch_id, order_col="modified_at"):
    """Clean this batch's Bronze rows, keep the latest per key, upsert into Silver."""
    src = CLEANERS[name](spark.table(f"lh_sales_bronze.bronze_{name}")
                               .filter(F.col("_batch_id") == batch_id))
    w = Window.partitionBy(*keys).orderBy(F.col(order_col).desc())
    src = src.withColumn("_rn", F.row_number().over(w)).filter("_rn = 1").drop("_rn")

    target = f"lh_sales_silver.{name}"
    if not spark.catalog.tableExists(target):
        src.write.saveAsTable(target)
        return src.count()

    cond = " AND ".join(f"t.{k} = s.{k}" for k in keys)
    (DeltaTable.forName(spark, target).alias("t")
        .merge(src.alias("s"), cond)
        .whenMatchedUpdateAll(condition=f"s.{order_col} >= t.{order_col}")   # never overwrite with older data
        .whenNotMatchedInsertAll()
        .execute())
    return src.count()

# nb_sales_silver_transform_sql — called by pl_sales_master_daily with batch_id = @pipeline().RunId
rows = {
    "customers":   merge_to_silver("customers",   ["customer_id"], batch_id),
    "orders":      merge_to_silver("orders",      ["order_id"], batch_id),
    "order_lines": merge_to_silver("order_lines", ["order_id", "line_number"], batch_id),
}
The s.modified_at >= t.modified_at condition makes re-runs and out-of-order batches safe: an older version can never overwrite a newer one. Products and stores (full loads) use the same function — every row is in the batch, and unchanged rows simply update to the same values.

Step 3 — Inventory and FX

# Inventory: one count per store, product and day; latest upload wins
inv = (spark.table("lh_sales_bronze.bronze_inventory").filter(F.col("_batch_id") == batch_id)
         .select(F.col("store_id").cast("int"), F.trim("product_code").alias("product_code"),
                 F.col("on_hand_qty").cast("int"),
                 F.to_date("counted_at").alias("count_date"), "_loaded_at")
         .filter("on_hand_qty >= 0"))
w = Window.partitionBy("store_id", "product_code", "count_date").orderBy(F.desc("_loaded_at"))
inv = inv.withColumn("_rn", F.row_number().over(w)).filter("_rn = 1").drop("_rn", "_loaded_at")
# … MERGE on (store_id, product_code, count_date) as above

# FX: one rate per calendar day; weekends/holidays carry the last business day forward
fx = (spark.table("lh_sales_bronze.bronze_fx_rates")
        .select(F.to_date("requested_date").alias("rate_date"), "currency", "rate", "_loaded_at"))
w = Window.partitionBy("rate_date", "currency").orderBy(F.desc("_loaded_at"))
fx = fx.withColumn("_rn", F.row_number().over(w)).filter("_rn = 1").drop("_rn", "_loaded_at")
fx.write.mode("overwrite").saveAsTable("lh_sales_silver.fx_rates")        # small table: rebuild

Keying FX on the requested date means every calendar day has a rate (the API already returns the last business day's rate on holidays), so sales on a Sunday still convert.

Step 4 — Deleted Rows

Watermarks never see rows that were physically deleted in the source. Once a week, copy just the keys of the source table and compare:

src_keys = spark.table("lh_sales_bronze.keys_customers")          # weekly Copy: SELECT CustomerID FROM Sales.Customers
deleted  = (spark.table("lh_sales_silver.customers").select("customer_id")
              .join(src_keys.select(F.col("CustomerID").alias("customer_id")), "customer_id", "left_anti"))

(DeltaTable.forName(spark, "lh_sales_silver.customers").alias("t")
    .merge(deleted.alias("d"), "t.customer_id = d.customer_id")
    .whenMatchedUpdate(set={"is_deleted": "true"})            # soft delete — history stays intact
    .execute())

(Add an is_deleted boolean column, default false, to Silver tables that need this.)

Incremental loading in the project works end to end: source rows newer than a watermark are appended to Bronze with the run's batch ID, and Silver processes only that batch. A generic merge function applies table-specific cleaning, keeps the latest row per key with a window function, and MERGEs into Silver only when the incoming version is at least as new, making re-runs safe. Inventory files are de-duplicated per store, product and day keeping the latest upload; FX rates are keyed on the requested date so every calendar day has a rate. Hard deletes are detected weekly by an anti-join against the source's current keys and recorded as soft deletes. Checks confirm one row per key, idempotent re-runs and complete FX coverage.
12.5

Gold: SCD Type 1 & Type 2, Facts

Gold is the star schema the business uses. You'll build the date and store dimensions, the product dimension as SCD Type 1, the customer dimension as SCD Type 2 (reusing the tested pattern from Module 5.6), and the sales fact — looking up the customer version valid on each order date and converting amounts to USD.

The Gold Model

⭐
FactSales — one row per order line
OrderID, LineNumber, DateKey, CustomerKey, ProductKey, StoreKey, Quantity, SalesAmount, CostAmount, MarginAmount, SalesAmountUSD
👤
DimCustomer — SCD Type 2
CustomerKey, CustomerID, CustomerName, City, Region, Segment, HashValue, StartDate, EndDate, IsCurrent (Email kept out of Gold)
📦
DimProduct — SCD Type 1
ProductKey, ProductID, ProductCode, ProductName, Category, Subcategory, Brand
🏬

Every dimension gets an Unknown member with key -1 (Module 5.7), so fact rows with missing references are kept and visible instead of dropped.

lines  = spark.table("lh_sales_silver.order_lines").filter(F.col("modified_at") > F.lit(last_fact_watermark))
orders = spark.table("lh_sales_silver.orders").select("order_id", "order_date", "customer_id", "store_id")
src    = lines.join(orders, "order_id", "left")

cust = spark.table("lh_sales_gold.DimCustomer").select("CustomerKey", "CustomerID", "StartDate", "EndDate")
prod = spark.table("lh_sales_gold.DimProduct").select("ProductKey", "ProductID")
store = spark.table("lh_sales_gold.DimStore").select("StoreKey", "StoreID")
usd  = (spark.table("lh_sales_silver.fx_rates").filter("currency = 'USD'")
          .select(F.col("rate_date"), F.col("rate").alias("usd_rate")))

fact = (src
    # customer version valid ON the order date (StartDate/EndDate are inclusive)
    .join(cust, (src.customer_id == cust.CustomerID) &
                (src.order_date >= cust.StartDate) & (src.order_date <= cust.EndDate), "left")
    .join(F.broadcast(prod),  src.product_id == prod.ProductID, "left")
    .join(F.broadcast(store), src.store_id == store.StoreID, "left")
    .join(F.broadcast(usd),   src.order_date == usd.rate_date, "left")
    .select(
        F.col("order_id").alias("OrderID"), F.col("line_number").alias("LineNumber"),
        F.date_format("order_date", "yyyyMMdd").cast("int").alias("DateKey"),
        F.col("order_date").alias("OrderDate"),
        F.coalesce("CustomerKey", F.lit(-1)).alias("CustomerKey"),
        F.coalesce("ProductKey",  F.lit(-1)).alias("ProductKey"),
        F.coalesce("StoreKey",    F.lit(-1)).alias("StoreKey"),
        F.col("quantity").alias("Quantity"),
        (F.col("quantity") * F.col("unit_price")).cast("decimal(18,2)").alias("SalesAmount"),
        (F.col("quantity") * F.col("unit_cost")).cast("decimal(18,2)").alias("CostAmount"),
        (F.col("quantity") * (F.col("unit_price") - F.col("unit_cost"))).cast("decimal(18,2)").alias("MarginAmount"),
        (F.col("quantity") * F.col("unit_price") * F.col("usd_rate")).cast("decimal(18,2)").alias("SalesAmountUSD")))

One Logging Helper for Every Notebook

# nb_sales_util_logging — %run it at the top of each notebook
import time, json
from datetime import datetime, timezone

class StepLog:
    def __init__(self, run_id, pipeline, step):
        self.run_id, self.pipeline, self.step = run_id, pipeline, step
        self.start = datetime.now(timezone.utc)

    def _write(self, status, rows_in, rows_out, message):
        spark.createDataFrame(
            [(self.run_id, self.pipeline, self.step, status, rows_in, rows_out,
              self.start, datetime.now(timezone.utc), message[:4000])],
            "run_id string, pipeline string, step string, status string, rows_in long, "
            "rows_out long, started_at timestamp, ended_at timestamp, message string"
        ).write.mode("append").saveAsTable("lh_sales_bronze.ops.run_log")

    def success(self, rows_in=None, rows_out=None, message=""):
        self._write("SUCCESS", rows_in, rows_out, message)
        return json.dumps({"rows_in": rows_in, "rows_out": rows_out})

    def failure(self, err):
        self._write("FAILED", None, None, repr(err))
        raise err

# In each notebook:
log = StepLog(batch_id, "pl_sales_master_daily", "nb_sales_gold_build_facts")
try:
    # … the work …
    summary = log.success(rows_in=src.count(), rows_out=fact.count())
except Exception as e:
    log.failure(e)

notebookutils.notebook.exit(summary)        # last line, outside the try block
Call notebookutils.notebook.exit() as the very last line and outside the try block: it stops the notebook, and inside a try an except Exception could catch the stop and log a false failure.

12.8

Power BI Reporting

The final layer is what stakeholders actually see. You'll build a Direct Lake semantic model on the Gold tables, add the measures the sales director asked for, secure it so regional managers see only their region, and design a report that answers the brief in three business pages plus a data-health page.

Step 1 — Semantic Model

  1. In lh_sales_gold: New semantic model → select FactSales, DimCustomer, DimProduct, DimStore, DimDate, plus a small sec_UserRegion table. Name it sm_sales_performance.
  2. Relationships (many-to-one, single direction): FactSales[DateKey] → DimDate[DateKey]; [CustomerKey] → DimCustomer; [ProductKey] → DimProduct; [StoreKey] → DimStore.
  3. Mark DimDate as the date table. Hide all key columns and the HashValue/IsCurrent technical columns.
  4. Sort MonthName by Month; set data categories (City, Region) and formats (₹, $, %).
Leave OrderID/LineNumber out of the model unless a drill-through page needs them — high-cardinality columns are the biggest cost in Direct Lake memory (Module 10.5).

Step 2 — Measures

Sales           = SUM ( FactSales[SalesAmount] )
Sales USD       = SUM ( FactSales[SalesAmountUSD] )
Cost            = SUM ( FactSales[CostAmount] )
Margin          = SUM ( FactSales[MarginAmount] )
Margin %        = DIVIDE ( [Margin], [Sales] )
Orders          = DISTINCTCOUNT ( FactSales[OrderID] )
Avg Order Value = DIVIDE ( [Sales], [Orders] )

Sales LY        = CALCULATE ( [Sales], SAMEPERIODLASTYEAR ( DimDate[Date] ) )
Sales YoY %     = DIVIDE ( [Sales] - [Sales LY], [Sales LY] )
Sales YTD       = TOTALYTD ( [Sales], DimDate[Date], "3/31" )      -- fiscal year ends 31 March

Customers       = CALCULATE ( DISTINCTCOUNT ( DimCustomer[CustomerID] ), FactSales )
                  -- buying customers: CustomerID, not CustomerKey (SCD2 has several keys per customer);
                  -- the FactSales filter counts only customers with sales in the current context

Keep measures in a dedicated, hidden-columns "Measures" table, with descriptions — they show as tooltips for report builders.

Step 3 — Row-Level Security

    CALCULATETABLE (
        VALUES ( sec_UserRegion[Region] ),

  • Test with View as for two managers and the director (Module 9.4)

The reporting layer is a Direct Lake semantic model on the Gold Lakehouse with single-direction many-to-one relationships from the fact to date, customer, product and store dimensions, hidden keys and technical columns, and a marked date table.
