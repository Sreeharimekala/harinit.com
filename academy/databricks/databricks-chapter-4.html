SQL Fundamentals

4.1.1What is SQL?

SQL (Structured Query Language) is used to retrieve, insert, update, delete, and analyze data stored in relational tables. Consider this employee table:

employee_idemployee_namedepartmentsalarycity
101RahulIT80000Hyderabad
102PriyaFinance65000Chennai
103ArjunIT90000Bengaluru
104SnehaHR55000Hyderabad
105KiranFinance70000Chennai

SQL can answer questions such as: Which employees work in IT? Who earns more than ₹70,000? What is the average salary per department? Which department spends most on salaries? Which employees have duplicate records?

4.1.2SELECT — Retrieve data

SQL
-- Syntax
SELECT column1, column2
FROM table_name;

-- Three specific columns
SELECT employee_id, employee_name, salary
FROM employees;

-- All columns
SELECT *
FROM employees;
Best practice

Avoid SELECT * in production pipelines when you know which columns you need. Unnecessary columns increase data processing and transfer. Prefer, for example, SELECT employee_id, employee_name, department FROM employees; when downstream only needs those three.

Important distinction

SELECT describes which columns appear in the result. The optimizer decides how to execute the query; the physical execution order is not necessarily the written order.

4.1.3DISTINCT — Remove duplicate values

DISTINCT returns unique combinations of the selected columns.

SQL
SELECT DISTINCT department
FROM employees;
-- IT, Finance, HR

-- Unique department + city combinations
SELECT DISTINCT department, city
FROM employees;

The second query removes duplicate combinations of department and city, not duplicates from each column independently. If a table holds 100,000 employees in five departments, SELECT DISTINCT department returns those five.

Important

DISTINCT removes duplicate result rows. It does not decide which record is the correct business record when multiple records exist for the same employee.

4.1.4WHERE — Filter records

SQL
SELECT *
FROM employees
WHERE department = 'IT';

SELECT employee_name, salary
FROM employees
WHERE salary > 70000;

SQL
-- Employees in IT or Finance
SELECT * FROM employees
WHERE department IN ('IT', 'Finance');

-- Employees earning between 60000 and 90000
SELECT * FROM employees
WHERE salary BETWEEN 60000 AND 90000;

-- Names beginning with R
SELECT * FROM employees
WHERE employee_name LIKE 'R%';

-- Names containing "ar"
SELECT * FROM employees
WHERE employee_name LIKE '%ar%';

Combine conditions

SQL
SELECT * FROM employees
WHERE department = 'IT'
  AND salary > 80000;

SELECT * FROM employees
WHERE department = 'IT'
   OR department = 'Finance';

-- Use parentheses when mixing AND and OR
SELECT * FROM employees
WHERE department = 'IT'
  AND (city = 'Hyderabad' OR city = 'Bengaluru');

4.1.5ORDER BY — Sort records

SQL
-- Ascending (the default)
SELECT employee_name, salary
FROM employees
ORDER BY salary ASC;

-- Descending
SELECT employee_name, salary
FROM employees
ORDER BY salary DESC;

-- Departments alphabetically, then highest salary first
SELECT employee_name, department, salary
FROM employees
ORDER BY department ASC, salary DESC;
Important

Without ORDER BY, SQL does not guarantee the order of returned rows.

4.1.6GROUP BY — Aggregate records

GROUP BY groups rows with the same values in the specified columns, usually with aggregate functions.

SQL
SELECT department, COUNT(*) AS employee_count
FROM employees
GROUP BY department;
departmentemployee_count

Finance2
HR1
SQL
-- Average salary by department
SELECT department, AVG(salary) AS average_salary
FROM employees
GROUP BY department;

-- Total salary expenditure
SELECT department, SUM(salary) AS total_salary
FROM employees
GROUP BY department;
FunctionPurpose
COUNT(*)Counts rows
COUNT(column)Counts non-NULL values in a column
COUNT(DISTINCT column)Counts distinct non-NULL values

SQL
SELECT
    department,
    COUNT(*) AS total_rows,
    COUNT(salary) AS employees_with_salary,
    COUNT(DISTINCT city) AS distinct_cities,
    MIN(salary) AS minimum_salary,
    MAX(salary) AS maximum_salary
FROM employees
GROUP BY department;

COUNT(*) and COUNT(salary) differ when salary contains NULLs.

4.1.7HAVING — Filter aggregated results

WHERE filters rows before aggregation; HAVING filters groups after aggregation.

SQL
-- Departments with more than five employees
SELECT department, COUNT(*) AS employee_count
FROM employees
GROUP BY department
HAVING COUNT(*) > 5;

-- Departments with average salary above 70,000
SELECT department, AVG(salary) AS average_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > 70000;

-- Both WHERE and HAVING
SELECT department, AVG(salary) AS average_salary
FROM employees
WHERE city = 'Hyderabad'
GROUP BY department
HAVING AVG(salary) > 60000;

The last query filters to Hyderabad employees, groups them by department, calculates each department's average salary, and returns only departments averaging above ₹60,000.

4.1.8LIMIT — Restrict the result size

SQL
SELECT *
FROM employees
LIMIT 10;

-- Five highest-paid employees
SELECT employee_name, salary
FROM employees
ORDER BY salary DESC
LIMIT 5;
Important

Use an appropriate ORDER BY for a meaningful top-N result. Without ordering, LIMIT 5 does not guarantee the five highest-paid employees.

4.1.9Aliases — Rename columns and tables

SQL
-- Column aliases
SELECT
    employee_name AS name,
    salary AS monthly_salary
FROM employees;

-- Table alias
SELECT e.employee_name, e.salary
FROM employees AS e;

-- Aliases in a join
SELECT e.employee_name, d.department_name
FROM employees AS e
INNER JOIN departments AS d
    ON e.department_id = d.department_id;

-- Alias for a calculated value
SELECT employee_name, salary * 12 AS annual_salary
FROM employees;

4.1.10NULL handling

NULL represents missing, unknown, or unavailable data. It is not zero and not an empty string.

employee_idemployee_namesalarymanager_id
101Rahul80000NULL
102Priya65000101
103ArjunNULL101
✓ Correct
SELECT *
FROM employees
WHERE salary IS NULL;
✗ Incorrect
SELECT *
FROM employees
WHERE salary = NULL;

Comparisons involving NULL generally produce an unknown result rather than TRUE or FALSE.

SQL
-- Non-NULL values
SELECT * FROM employees
WHERE salary IS NOT NULL;

-- Replace NULL with a default
SELECT employee_name, COALESCE(salary, 0) AS salary
FROM employees;
Business decision

Replacing NULL with zero can wrongly imply the employee earns nothing, rather than that salary information is missing.

NULL and aggregate functions

With salaries A = 50000, B = 60000, C = NULL:

SQL
SELECT
    COUNT(*) AS total_rows,        -- 3
    COUNT(salary) AS salary_count, -- 2
    AVG(salary) AS average_salary  -- 55000
FROM employees;
Remember

AVG ignores NULL values. It does not treat them as zero.

Section 4.1 summary

SELECT retrieves columns · DISTINCT removes duplicate result rows · WHERE filters rows · GROUP BY groups for aggregation · HAVING filters groups · ORDER BY sorts · LIMIT restricts row count · IS NULL and COALESCE handle missing values.

SQL Functions

Functions transform, calculate, and analyze values without writing a full program. Databricks SQL has a broad library; these are the ones most useful in data engineering.

4.2.1String functions

employee_nameemaildepartment
Rahul SharmaRahul@Example.comIT
Priya ReddyPriya@Example.comFinance
Arjun KumarArjun@Example.comIT
SQL
-- UPPER / LOWER: normalize text
SELECT
    UPPER(employee_name) AS uppercase_name,
    LOWER(email) AS lowercase_email
FROM employees;

-- TRIM: ' Rahul Sharma ' becomes 'Rahul Sharma'
SELECT TRIM(employee_name) AS cleaned_name
FROM employees;

-- LENGTH
SELECT employee_name, LENGTH(employee_name) AS name_length
FROM employees;

-- SUBSTRING: extraction starts at position 1
SELECT SUBSTRING(employee_name, 1, 5) AS first_five_characters
FROM employees;

-- CONCAT
SELECT CONCAT(employee_name, ' - ', department) AS employee_details
FROM employees;

-- REPLACE
SELECT REPLACE(email, 'Example.com', 'Company.com') AS updated_email
FROM employees;

-- SPLIT: string to array by delimiter
SELECT email, SPLIT(email, '@') AS email_parts
FROM employees;

-- REGEXP_REPLACE: keep digits only
SELECT REGEXP_REPLACE(phone_number, '[^0-9]', '') AS cleaned_phone
FROM employees;
Data engineering example

A source system sends phone numbers as +91-98765 43210 but the destination expects digits only. String functions standardize the format during ingestion or transformation.

4.2.2Numeric functions

SQL
SELECT ROUND(1234.567, 2) AS rounded_value;   -- 1234.57

SELECT
    CEIL(10.2) AS ceiling_value,   -- 11
    FLOOR(10.8) AS floor_value;    -- 10

SELECT ABS(-150) AS absolute_value;   -- 150

SELECT MOD(17, 5) AS remainder;       -- 2

-- Annual salary
SELECT
    employee_name,
    salary AS monthly_salary,
    salary * 12 AS annual_salary
FROM employees;

4.2.3Date and time functions

Date functions are essential for ETL pipelines, incremental loads, reporting, and historical analysis. Databricks SQL supports CURRENT_DATE(), CURRENT_TIMESTAMP(), YEAR(), MONTH(), DAY(), DATE_ADD(), DATE_SUB(), DATEDIFF(), ADD_MONTHS(), DATE_TRUNC(), TO_DATE(), TO_TIMESTAMP(), and DATE_FORMAT(), among others.

SQL
SELECT CURRENT_DATE() AS today;
SELECT CURRENT_TIMESTAMP() AS current_timestamp;

-- Extract year and month
SELECT
    employee_name,
    YEAR(joining_date) AS joining_year,
    MONTH(joining_date) AS joining_month
FROM employees;

-- Days since joining (argument order: end_date, start_date)
SELECT
    employee_name,
    joining_date,
    DATEDIFF(CURRENT_DATE(), joining_date) AS days_since_joining
FROM employees;

-- Add or subtract days
SELECT DATE_ADD(CURRENT_DATE(), 7) AS date_after_seven_days;
SELECT DATE_SUB(CURRENT_DATE(), 30) AS date_thirty_days_ago;

-- Add months
SELECT ADD_MONTHS(CURRENT_DATE(), 3) AS date_after_three_months;

-- Start of the month (useful for monthly reporting)
SELECT DATE_TRUNC('MONTH', CURRENT_TIMESTAMP()) AS month_start;

-- Text to date
SELECT TO_DATE('2026-10-25', 'yyyy-MM-dd') AS parsed_date;

-- Format a date, e.g. 2026-10
SELECT DATE_FORMAT(CURRENT_DATE(), 'yyyy-MM') AS year_month;

Practical ETL example: incremental loading

SQL
SELECT *
FROM source_employees
WHERE last_modified_date >= DATE_SUB(CURRENT_DATE(), 1);

This retrieves records modified since the previous calendar day.

Not a complete strategy

In production, a timestamp watermark or source change tracking is more reliable than filtering on the current date. Also consider time zones, late-arriving changes, and the last successful pipeline run.

4.2.4Aggregate functions

SQL
SELECT
    department,
    COUNT(*) AS employee_count,
    SUM(salary) AS total_salary,
    AVG(salary) AS average_salary,
    MIN(salary) AS minimum_salary,
    MAX(salary) AS maximum_salary
FROM employees
GROUP BY department;

Conditional aggregation

Count employees per department earning more than ₹70,000:

SQL
SELECT
    department,
    SUM(CASE WHEN salary > 70000 THEN 1 ELSE 0 END)
        AS high_salary_employees
FROM employees
GROUP BY department;

The same technique powers reporting tables, such as a daily pipeline-monitoring summary of total, successful, and failed runs:

SQL
SELECT
    CAST(start_time AS DATE) AS run_date,
    COUNT(*) AS total_runs,
    SUM(CASE WHEN status = 'Succeeded' THEN 1 ELSE 0 END)
        AS successful_runs,
    SUM(CASE WHEN status = 'Failed' THEN 1 ELSE 0 END)
        AS failed_runs
FROM pipeline_runs
GROUP BY CAST(start_time AS DATE);

This pattern is the basis for a data engineering monitoring dashboard (Chapter 20).

4.2.5Conditional functions and CASE

SQL
SELECT
    employee_name,
    salary,
    CASE
        WHEN salary >= 100000 THEN 'High'
        WHEN salary >= 70000 THEN 'Medium'
        WHEN salary IS NULL THEN 'Unknown'
        ELSE 'Low'
    END AS salary_category
FROM employees;

Order matters: SQL returns the result of the first matching condition.

SQL · tenure
SELECT
    employee_name,
    joining_date,
    CASE
        WHEN joining_date IS NULL THEN 'Unknown'
        WHEN DATEDIFF(CURRENT_DATE(), joining_date) >= 3650
            THEN '10+ years'
        WHEN DATEDIFF(CURRENT_DATE(), joining_date) >= 1825
            THEN '5-10 years'
        ELSE 'Less than 5 years'
    END AS tenure_category
FROM employees;

Simplified; production tenure rules should specify calendar years or exact day counts.

4.2.6COALESCE

COALESCE returns the first non-NULL expression.

SQL
SELECT
    employee_name,
    COALESCE(email, alternate_email, 'No email') AS contact_email
FROM employees;

If email isn't NULL, return it; otherwise alternate_email if not NULL; otherwise 'No email'. Especially useful when combining data from multiple source systems.

4.2.7NULLIF

NULLIF(a, b) returns NULL if a = b; otherwise it returns a. SELECT NULLIF(100, 100) returns NULL.

SQL
SELECT
    revenue / NULLIF(units_sold, 0) AS revenue_per_unit
FROM sales;

When units_sold = 0, the divisor becomes NULL, preventing division by zero and producing NULL instead of a misleading number.

4.2.8CAST and TRY_CAST

SQL
SELECT CAST('123' AS INT) AS employee_number;          -- 123
SELECT CAST('2026-10-25' AS DATE) AS converted_date;

-- TRY_CAST returns NULL instead of raising an error
SELECT
    TRY_CAST('123' AS INT) AS valid_number,    -- 123
    TRY_CAST('ABC' AS INT) AS invalid_number;  -- NULL

Real-world example: salary stored as text

employee_idsalary_text
10180000
10265000
103UNKNOWN
104NULL
SQL
SELECT
    employee_id,
    salary_text,
    TRY_CAST(salary_text AS DECIMAL(12, 2)) AS salary
FROM source_employee_data;
Don't fail silently

In production, monitor how many rows fail conversion and decide whether to quarantine, reject, or apply a documented correction:

SQL
SELECT COUNT(*) AS invalid_salary_records
FROM source_employee_data
WHERE salary_text IS NOT NULL
  AND TRY_CAST(salary_text AS DECIMAL(12, 2)) IS NULL;
Section 4.2 summary

You can now clean strings, do numeric calculations, compute date differences, aggregate data, implement rules with CASE, replace missing values with COALESCE, prevent division by zero with NULLIF, and convert types with CAST and TRY_CAST.

4.3.2INNER JOIN

Returns rows that match in both tables.

SQL
SELECT
    e.employee_id,
    e.employee_name,
    d.department_name
FROM employees AS e
INNER JOIN departments AS d
    ON e.department_id = d.department_id;
employee_idemployee_namedepartment_name
101RahulIT
102PriyaFinance
103ArjunIT

Sneha is excluded because department 30 doesn't exist in Departments; Kiran because his department is NULL. Use an inner join when you need only matching records, for example transactions with a valid customer.

4.3.3LEFT JOIN

Returns every row from the left table plus matching rows from the right; unmatched right-side columns are NULL.

SQL
SELECT
    e.employee_id,
    e.employee_name,
    d.department_name
FROM employees AS e
LEFT JOIN departments AS d
    ON e.department_id = d.department_id;
employee_idemployee_namedepartment_name
101RahulIT
102PriyaFinance
103ArjunIT
104SnehaNULL
105KiranNULL

Practical use: find missing reference data

SQL
SELECT
    e.employee_id,
    e.employee_name,
    e.department_id
FROM employees AS e
LEFT JOIN departments AS d
    ON e.department_id = d.department_id
WHERE d.department_id IS NULL;

This returns Sneha and Kiran, but they are different data-quality problems: Kiran's department is NULL in the source, while Sneha's department ID doesn't match any department.

4.3.4RIGHT JOIN

Returns every row from the right table plus matching rows from the left. This includes Marketing even though no employee belongs to it.

SQL
SELECT
    e.employee_name,
    d.department_id,
    d.department_name
FROM employees AS e
RIGHT JOIN departments AS d
    ON e.department_id = d.department_id;

Many developers rewrite a RIGHT JOIN as a LEFT JOIN by swapping table order, since the intent is often easier to read.

4.3.5FULL OUTER JOIN

Returns matching rows plus unmatched rows from both sides.

SQL
SELECT
    e.employee_name,
    e.department_id AS employee_department_id,
    d.department_id AS reference_department_id,
    d.department_name
FROM employees AS e
FULL OUTER JOIN departments AS d
    ON e.department_id = d.department_id;

Full outer joins are useful for reconciliation between systems:

SQL
SELECT
    COALESCE(s.employee_id, t.employee_id) AS employee_id,
    s.employee_name AS source_name,
    t.employee_name AS target_name
FROM source_employees AS s
FULL OUTER JOIN target_employees AS t
    ON s.employee_id = t.employee_id;

This identifies records only in the source, only in the target, or in both. For accurate reconciliation, also compare column values and handle NULLs explicitly.

4.3.6CROSS JOIN

Returns every combination of rows: 5 rows × 3 rows = 15 rows.

SQL
SELECT
    e.employee_name,
    d.department_name
FROM employees AS e
CROSS JOIN departments AS d;

Useful for generating combinations of dates and product IDs, departments and reporting months, or products and price scenarios.

Be careful

A cross join can produce a very large result.

4.3.7SELF JOIN

Joins a table to itself, which is useful for employee–manager relationships.

SQL
SELECT
    e.employee_name AS employee_name,
    m.employee_name AS manager_name
FROM employees AS e
LEFT JOIN employees AS m
    ON e.manager_id = m.employee_id;
employee_namemanager_name

PriyaRahul
ArjunRahul

The aliases e and m are two logical roles played by the same table.

4.3.8LEFT SEMI JOIN

Returns left-table rows that have a match in the right table, with only left-side columns. Think of it as an existence test.

SQL
SELECT e.*
FROM employees AS e
LEFT SEMI JOIN departments AS d
    ON e.department_id = d.department_id;
Equivalent
SELECT e.*
FROM employees AS e
WHERE EXISTS (
    SELECT 1
    FROM departments AS d
    WHERE d.department_id = e.department_id
);

A semi join does not multiply employee rows when multiple right-side rows match.

4.3.9LEFT ANTI JOIN

Returns left-table rows with no matching row in the right table.

SQL
SELECT e.*
FROM employees AS e
LEFT ANTI JOIN departments AS d
    ON e.department_id = d.department_id;
Equivalent
SELECT e.*
FROM employees AS e
WHERE NOT EXISTS (
    SELECT 1
    FROM departments AS d
    WHERE d.department_id = e.department_id
);

4.3.10Handling duplicate records after joins

A critical topic.

employees
employee_idemployee_name
101Rahul
102Priya
employee_addresses
employee_idaddress
101Hyderabad
101Bengaluru
102Chennai
SQL
SELECT
    e.employee_id,
    e.employee_name,
    a.address
FROM employees AS e
LEFT JOIN employee_addresses AS a
    ON e.employee_id = a.employee_id;

Rahul appears twice because two address records match employee 101. The join isn't wrong: it reflects the one-to-many relationship. The right fix depends on the business requirement.

Solution 1: Select the latest address

SQL
WITH ranked_addresses AS (
    SELECT
        employee_id,
        address,
        updated_at,
        ROW_NUMBER() OVER (
            PARTITION BY employee_id
            ORDER BY updated_at DESC
        ) AS rn
    FROM employee_addresses
)
SELECT
    e.employee_id,
    e.employee_name,
    a.address
FROM employees AS e
LEFT JOIN ranked_addresses AS a
    ON e.employee_id = a.employee_id
   AND a.rn = 1;

If two addresses share the same updated_at, add a stable tie-breaker such as a unique address record ID.

Solution 2: Use EXISTS

If you only need employees who have an address:

SQL
SELECT e.*
FROM employees AS e
WHERE EXISTS (
    SELECT 1
    FROM employee_addresses AS a
    WHERE a.employee_id = e.employee_id
);

Solution 3: Aggregate the child table

SQL
SELECT
    employee_id,
    COUNT(*) AS address_count
FROM employee_addresses
GROUP BY employee_id;
-- then join this aggregated result to employees

Solution 4: Investigate the data quality

SQL
SELECT
    employee_id,
    COUNT(*) AS record_count
FROM employee_addresses
GROUP BY employee_id
HAVING COUNT(*) > 1;

If multiple records are legitimate, don't delete them just to force a one-to-one join.

Production rule

Before joining two tables, understand their grain: the meaning and uniqueness of one row in each table.

Chapter 4 · Lesson 4.4

Advanced SQL

Multi-step transformations, historical analysis, ranking, and deduplication, all in SQL.

4.4.1Common Table Expressions (CTEs)

A CTE is a named query defined with WITH, which breaks complex SQL into readable steps.

SQL
WITH department_salary AS (
    SELECT
        department,
        AVG(salary) AS average_salary
    FROM employees
    GROUP BY department
)
SELECT department, average_salary
FROM department_salary
WHERE average_salary > 70000;

Multiple CTEs

SQL
WITH employee_data AS (
    SELECT employee_id, employee_name, department, salary
    FROM employees
    WHERE salary IS NOT NULL
),
department_summary AS (
    SELECT
        department,
        COUNT(*) AS employee_count,
        AVG(salary) AS average_salary
    FROM employee_data
    GROUP BY department
)
SELECT *
FROM department_summary
ORDER BY average_salary DESC;
Important

A CTE improves organization but is not automatically a physically materialized table. The optimizer may inline or transform it.

4.4.2Subqueries

SQL
-- Employees earning above the overall average
SELECT employee_id, employee_name, salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
);

-- IN subquery: departments with budget above 1,000,000
SELECT *
FROM employees
WHERE department_id IN (
    SELECT department_id
    FROM departments
    WHERE budget > 1000000
);

Correlated subquery

Employees earning more than their own department's average; the inner query refers to the outer row's department:

SQL
SELECT e.employee_id, e.employee_name, e.department_id, e.salary
FROM employees AS e
WHERE e.salary > (
    SELECT AVG(e2.salary)
    FROM employees AS e2
    WHERE e2.department_id = e.department_id
);

A window function often expresses this more clearly:

SQL
WITH employee_salary AS (
    SELECT
        employee_id,
        employee_name,
        department_id,
        salary,
        AVG(salary) OVER (
            PARTITION BY department_id
        ) AS department_average
    FROM employees
)
SELECT *
FROM employee_salary
WHERE salary > department_average;

4.4.3Recursive-query alternatives

Recursive CTE support differs across SQL engines and versions; check the runtime and documentation available in your workspace. Many hierarchy problems have alternatives.

SQL · one level
SELECT
    e.employee_name,
    m.employee_name AS manager_name
FROM employees AS e
LEFT JOIN employees AS m
    ON e.manager_id = m.employee_id;
SQL · fixed depth
SELECT
    e.employee_name AS employee,
    m.employee_name AS manager,
    gm.employee_name AS grand_manager
FROM employees AS e
LEFT JOIN employees AS m
    ON e.manager_id = m.employee_id
LEFT JOIN employees AS gm
    ON m.manager_id = gm.employee_id;

This handles two management levels. For arbitrary-depth hierarchies, consider iterative processing in PySpark, a precomputed hierarchy (closure) table, or a supported recursive-query feature where available.

4.4.4Window functions

Window functions calculate across related rows without collapsing them into one row per group.

GROUP BY: one row per department
SQL
SELECT
    department_id,
    AVG(salary) AS average_salary
FROM employees
GROUP BY department_id;
Window: keeps every employee row
SQL
SELECT
    employee_id, employee_name,
    department_id, salary,
    AVG(salary) OVER (
        PARTITION BY department_id
    ) AS department_average_salary
FROM employees;
ConceptMeaning
PARTITION BYDefines groups within which the function operates
ORDER BYDefines row ordering within each partition
Window frameDefines which rows are included relative to the current row

4.4.5ROW_NUMBER

Assigns a sequential number to rows within each partition.

SQL
SELECT
    employee_id,
    employee_name,
    department_id,
    salary,
    ROW_NUMBER() OVER (
        PARTITION BY department_id
        ORDER BY salary DESC, employee_id
    ) AS row_num
FROM employees;

The highest-paid employee per department gets 1. Adding employee_id breaks salary ties deterministically.

SQL · highest-paid per department
WITH ranked_employees AS (
    SELECT
        employee_id, employee_name, department_id, salary,
        ROW_NUMBER() OVER (
            PARTITION BY department_id
            ORDER BY salary DESC, employee_id
        ) AS rn
    FROM employees
)
SELECT *
FROM ranked_employees
WHERE rn = 1;
SQL · keep latest version
WITH ranked_employees AS (
    SELECT
        *,
        ROW_NUMBER() OVER (
            PARTITION BY employee_id
            ORDER BY updated_at DESC, source_record_id DESC
        ) AS rn
    FROM source_employees
)
SELECT *
FROM ranked_employees

4.4.12MERGE INTO

MERGE INTO combines insert and update logic in one operation and is widely used with Delta tables for upserts: update when the key matches, insert when it doesn't.

SQL
MERGE INTO main.default.employee_target AS target
USING main.default.employee_staging AS source
ON target.employee_id = source.employee_id

WHEN MATCHED THEN
    UPDATE SET
        target.employee_name = source.employee_name,
        target.salary = source.salary,
        target.updated_at = source.updated_at

WHEN NOT MATCHED THEN
    INSERT (
        employee_id,
        employee_name,
        salary,
        updated_at
    )
    VALUES (
        source.employee_id,
        source.employee_name,
        source.salary,
        source.updated_at
    );
  1. Databricks compares source and target on employee_id.
  2. If a target record exists, it is updated.
  3. If no target record exists, a new one is inserted.
Common production issue

If staging has several rows for the same employee_id, multiple source rows matching one target row can cause a MERGE failure or ambiguous results. Deduplicate the source to at most one row per key first:

SQL
WITH ranked_source AS (
    SELECT
        *,
        ROW_NUMBER() OVER (
            PARTITION BY employee_id
            ORDER BY updated_at DESC, source_record_id DESC
        ) AS rn
    FROM main.default.employee_staging
)
SELECT *
FROM ranked_source
WHERE rn = 1;

MERGE is useful for incremental loads, updating customer or employee dimensions, maintaining current-state tables, applying change data from upstream systems, and synchronizing source and target. It isn't a replacement for every INSERT or UPDATE.

4.5.9Query history

Query history can show query text, start time and duration, status, user or principal, warehouse, errors, and execution details.

How to investigate a slow query

  1. Open Query History in your workspace.
  2. Find the query by time, user, warehouse, or status.
  3. Inspect the query text.
  4. Check its duration and execution details.
  5. Review the execution plan or query profile.
  6. Decide whether the cause is scanning too much data, a large join, a shuffle, poor filtering, or insufficient compute.

        AVG(salary) OVER (
            PARTITION BY department_id
        ) AS department_average
    FROM main.employee_sql_lab.employees
)
SELECT *
FROM employee_salary
WHERE salary > department_average;
29. Count attendance records for each employee, including employees with none.
SQL
SELECT
    e.employee_id,
    e.employee_name,
    COUNT(a.attendance_id) AS attendance_records
FROM main.employee_sql_lab.employees AS e
LEFT JOIN main.employee_sql_lab.attendance AS a
    ON e.employee_id = a.employee_id
GROUP BY e.employee_id, e.employee_name;

Use COUNT(a.attendance_id), not COUNT(*): COUNT(*) would count the NULL-extended row the left join produces for an employee with no attendance.

30. Find employees who have no attendance records.
SQL
SELECT e.*
FROM main.employee_sql_lab.employees AS e
LEFT ANTI JOIN main.employee_sql_lab.attendance AS a
    ON e.employee_id = a.employee_id;

48. Pivot attendance statuses into columns: Present and Absent counts per employee.
SQL

Check the generated column names in your workspace. Conditional aggregation is often easier to customize:

SQL
SELECT
    employee_id,

FROM main.employee_sql_lab.attendance
GROUP BY employee_id;
49. Write a MERGE INTO that updates existing employees and inserts new ones.

First create and fill a staging table:

SQL
CREATE OR REPLACE TABLE main.employee_sql_lab.employee_staging (
    employee_id INT,
    employee_name STRING,
    email STRING,
    department_id INT,
    manager_id INT,
    salary DECIMAL(12, 2),
    joining_date DATE,
    city STRING,
    employment_status STRING
)
USING DELTA;

INSERT INTO main.employee_sql_lab.employee_staging
VALUES
    (101, 'Rahul Sharma', 'rahul@example.com', 10, NULL, 125000, DATE '2020-01-15', 'Hyderabad', 'Active'),
    (116, 'Akhil Rao', 'akhil@example.com', 20, 101, 82000, DATE '2026-10-01', 'Chennai', 'Active');

Then merge:

SQL
MERGE INTO main.employee_sql_lab.employees AS target
USING main.employee_sql_lab.employee_staging AS source
ON target.employee_id = source.employee_id

WHEN MATCHED THEN
    UPDATE SET
        target.employee_name = source.employee_name,
        target.email = source.email,
        target.department_id = source.department_id,
        target.manager_id = source.manager_id,
        target.salary = source.salary,
        target.joining_date = source.joining_date,
        target.city = source.city,
        target.employment_status = source.employment_status

WHEN NOT MATCHED THEN
    INSERT (
        employee_id, employee_name, email, department_id,
        manager_id, salary, joining_date, city, employment_status
    )
    VALUES (
        source.employee_id, source.employee_name, source.email,
        source.department_id, source.manager_id, source.salary,
        source.joining_date, source.city, source.employment_status
    );

-- Verify
SELECT *
FROM main.employee_sql_lab.employees
WHERE employee_id IN (101, 116);

Expected: employee 101 is updated to ₹125,000 and employee 116 is inserted. This assumes each ID appears at most once in staging; otherwise deduplicate and validate first.

50. Write a deduplication query that keeps the latest record per employee, using updated_at and a deterministic tie-breaker.

Assume an incoming table source_employees with employee_id, employee_name, salary, updated_at, and source_record_id:

SQL
WITH ranked_source AS (
    SELECT
        *,
        ROW_NUMBER() OVER (
            PARTITION BY employee_id
            ORDER BY updated_at DESC, source_record_id DESC
        ) AS rn
    FROM source_employees
)
SELECT
    employee_id,
    employee_name,
    salary,
    updated_at,
    source_record_id
FROM ranked_source
WHERE rn = 1;

The tie-breaker must have meaningful, stable ordering. An arbitrary ID makes the result deterministic but not necessarily the correct business record.
